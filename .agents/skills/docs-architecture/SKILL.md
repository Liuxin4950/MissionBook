# 架构文档维护

维护 `Docs/架构/` 下的模块化架构文档。功能改完需要把架构变更落进文档时使用，方便用户查看和理解学习系统架构。

## 何时用 / 何时不用

**用**：功能改完要把架构变更同步到文档；新增功能域需要建档；重构导致文件地图 / 数据流变化。

**不用**：纯实现细节调整（架构未变，commit message 承担）；写用户向文档；记录临时开发笔记。

## 文档体系

```
Docs/架构/
├── README.md              索引：按领域分组的模块导航表 + 文档约定
├── 设计/                  设计规范类文档（待建）
├── 前端/
│   ├── 看板娘/
│   │   ├── 总览.md        模块入口（固定文件名）
│   │   ├── 状态与消息流.md 细分文档，按子领域命名
│   │   ├── TTS与表情.md
│   │   ├── Live2d渲染.md
│   │   ├── Markdown与会话.md
│   │   └── SSE流式与心跳机制.md
│   └── Banner/
│       └── 总览.md
├── 后端/                  后端服务模块（待建：认证授权、后端 API、AI 服务、图片管理等）
└── 运维/
    └── 部署运维/
        └── 总览.md
```

**规则**：
- 一个模块 = 一个可独立理解的功能域，按业务领域划分，不按技术分层。候选模块：看板娘、Banner、部署运维、认证授权、后端 API、AI 服务、Admin、图片管理、跨服务约定。
- 目录分两级：**领域目录**（设计 / 前端 / 后端 / 运维）+ **模块目录**（领域下的具体功能域，目录名 = 模块中文名）。
- 入口固定叫「总览.md」；细分文档用子领域名，不加序号前缀。
- 单一文档不超过 500 行；超了按子领域拆细分文档。
- 横切关注点（跨服务调用约定、统一日志规范等）单独成模块，不散落到各模块。
- **移动模块目录时**：同步更新 README 导航表、AGENTS.md 等外部引用，并修正模块文档内相对引用的深度（如 `../../../Web` → `../../../../Web`）。

## 编写规范

### 风格
- 中文；务实、基于事实；不写"为什么这么设计"的主观推测，只写"是什么 / 怎么工作"。
- 同一事实只在一处定义，他处用相对路径链接引用，不复制。
- 不大段复制代码原文；用 `file:line` 引用 + 一句摘要。
- 跨服务硬约束（`JWT_SECRET`、`LIUTECH_INTERNAL_TOKEN`、`BLOG_API_URL`、JDBC `allowPublicKeyRetrieval` 等）不在此重复，引用 `AGENTS.md` 与 `Docs/架构/跨服务规范.md`。

### 引用路径
- 代码引用用相对路径，从当前文档到目标文件。例如 `Docs/架构/前端/看板娘/总览.md` 引用 Web 代码写 `../../../../Web/src/stores/chat.ts`。
- 写成可点击的 markdown 链接：`[\`Web/src/stores/chat.ts\`](../../../Web/src/stores/chat.ts)`。

### 数据流图
- 用文字流程图（ASCII 缩进树 / 箭头），不依赖外部图片。
- 字段名、方法名、事件名必须与代码逐字一致。

### 总览.md 骨架

```
# <模块名>架构总览
> 一句话职责 + 导读（读完能定位到细分文档）

## 模块职责
（一段话，说清边界与涉及的前后端位置）

## 文件地图
（按子领域分组的表格，列：文件 | 职责，file:line 可点击）

## 数据流概览
（文字流程图，主链路）

## 细分文档
（表格：文档 | 内容）

## 陷阱与约束
（列表，已踩过的坑 / 必须遵守的硬约束）
```

### 细分文档骨架

```
# <子领域>
> 职责 + 本文档内容范围

## <主题1>
（小标题分节，表格 + 文字流程图）

## <主题2>
...

## 陷阱与约束
（列表）
```

## 工作流

### 0. 前置
先读 `Docs/README.md`、`Docs/AGENTS.md`，再读 `Docs/架构/README.md`（模块导航）和 `Docs/架构/总览.md`（全局架构），建立全局认知，避免把跨模块的横切内容写进单一模块文档。

### 1. 判断：更新还是新增
- 改动的功能域已有模块目录 → 走「更新」
- 新功能域，现有目录都不覆盖 → 走「新增」
- 架构未变（只改实现）→ 不动文档，commit 承担

### 2. 更新现有文档
1. 读模块的「总览.md」和相关细分文档，建立现状认知
2. `git diff` 或读改动文件，确认变更范围
3. 对照定位需要改的段落：文件地图增删行、数据流改链路、陷阱加新坑
4. 改文档，保持与现有文档风格一致
5. **验证引用**：被重命名 / 删除的文件，更新或移除其 `file:line` 引用；新增的引用用 Grep / Read 抽验存在
6. 模块边界变化（新增 / 移除细分文档）→ 同步更新总览的「细分文档」表和 README 索引

### 3. 新增模块
1. 确认是新功能域（现有模块都不覆盖），并确定所属领域目录（设计 / 前端 / 后端 / 运维）
2. `Docs/架构/<领域>/<模块名>/` 建目录
3. 写「总览.md」（按骨架）
4. 按子领域拆细分文档（每个不超 500 行）
5. 在 `Docs/架构/README.md` 对应领域分组下加一行：`| <模块名> | [<领域>/<模块名>/总览.md](领域>/<模块名>/总览.md) | <一句话说明> |`

## 准确性硬规则
- **写之前先读代码**：用 Read / Grep / Glob 读相关文件，不凭记忆写文档
- **引用必须真实**：`file:line` 写完抽验存在；字段 / 方法 / 事件 / 配置键与代码逐字一致
- **不确定不写**：宁可不写，不写猜测
- **不重复跨服务约束**：引用 AGENTS.md 与 `Docs/架构/总览.md`

## 自检清单
- [ ] 文档所述与当前代码一致（已读代码验证，非凭记忆）
- [ ] 所有 `file:line` 引用真实存在
- [ ] 字段 / 方法 / 事件名与代码逐字一致
- [ ] 单一文档未超 500 行
- [ ] 总览含：文件地图 / 数据流 / 细分索引 / 陷阱约束
- [ ] 新增模块已在 `README.md` 模块导航表登记
- [ ] 同一事实未在多处重复（用链接引用）
- [ ] 无过时信息（被改掉的字段 / 方法 / 文件已更新或移除）
- [ ] 跨服务约束未重复（引用 AGENTS.md / 架构总览 / 跨服务规范）
- [ ] 核验现行文档链接、章节锚点、索引及路径大小写，路径大小写、章节锚点、模块索引和文档入口检查通过
