# 三步交互原则

2026-10-18，用户新增硬约束：**任何功能不能超过三步页面跳转。** 今天v8获准作为暂定视觉参考；后续逐页遵守共同风格和这条约束。此文约束设计，应用代码尚未按新导航改造。

## 如何检查

从用户实际所在的任一顶层页出发，核对到功能完成并显示必要反馈的整个必经路径。切换顶层、独立工作页、保存后自动去结果/列表、系统选择器及必需返回均计数。表单输入、滚动和在原任务上下文内展开/筛选不是页面跳转。

不能将一整页表单或独立确认塞进弹窗后说“零跳转”。真正就地处理需要保留对象、上下文和清楚反馈。正常路径、强制材料分支、导入/附件/备份的系统选择器分别审查；不能只审最短阅读路径。

## 目标页的确定入口

| 功能 | 从其他顶层开始的主路径 | 跳数 |
| --- | --- | --- |
| 查看目标覆盖/切状态 | 目标，原位切状态 | 1 |
| 查看目标与节点树 | 目标→目标卡进入节点树 | 2 |
| 从节点创建任务 | 目标→节点树→节点行“建任务”表单；表单内显示创建成功 | 3 |
| 手动新建目标 | 目标→新建表单→创建后的目标详情；方式选择不另设页面 | 3 |
| 添加节点 | 目标→目标树，树内新增节点并原位显示结果 | 2 |
| 进入当前执行 | 当前任务快捷栏直接开始/继续/返回执行，按阶段显示动作 | 1 |

目标详情树v2补充：节点的“已安排”可原位展开已有任务摘要，直接进入对应工作页；从其他顶层→目标（1）→树（2）→执行/记录工作页（3），不强制先开节点任务列表。节点名称仍可进入完整列表浏览，展开树、查看摘要和创建新任务是不同动作。正式《界面与交互》§5.1已修订为创建成功原位反馈；这只更新设计约定，尚未证明应用实现符合。

建任务保留有效归属重验、必填字段和原子保存；成功后关闭重复提交入口，查看今天作为可选动作，不再强制第4跳。目标非ACTIVE或节点归档时不能创建任务，不为少跳自动恢复状态。点击节点浏览任务与“建任务”是分开的动作；节点任务列表不是创建的强制中转。

## 后续页面必须解决的链路

- 独立“执行→结束确认→材料→结果”会超限。后续设计应在执行上下文处理明确的报告确认，保留先暂停、确认才END、强制材料和截止等规则；不得只换成全屏弹窗来躲计数。
- 保存、材料修正、再次尝试等第3跳工作区，应就地显示真实成功反馈；不能又强制返回另一个结果页。结果仍可被查看，入口无需强制中转。
- 文件材料的系统选择器与返回也占跳数；单靠“当前任务直达执行”不能证明该分支已达标。必须在材料页设计时连同执行/记录上下文重新核对。
- 待补材料需要可发现的直达工作区；历史记录操作不能强制经过结果详情再进入编辑。
- 备份说明/进度留在我的上下文；系统保存和返回后原位反馈，不另设说明页、进度页和成功页。

完整静态审查见[三步可达审查](../../output/ui-prototypes/三步可达审查.md)。其中未解决路径不是原则的例外，必须在相应页面继续设计及实际验收；本轮只完成目标页候选，不能宣称应用的所有功能已满足三步。
