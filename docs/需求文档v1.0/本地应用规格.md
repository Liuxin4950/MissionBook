# Mission Book — 本地应用规格

本文档约束本次交付范围和验收。领域规则以[领域模型](领域模型.md)为准，持久化事实以[数据模型](数据模型.md)为准。规格完成不代表代码完成。

2026-10-25 路径补正：保留本地双端范围和执行操作重试。运行或暂停任务在今天、目标节点、全部任务列表及底部快捷栏统一进入独立执行页；顶层列表不内嵌执行工作区。早期关于“原位执行”的表述以本条和[界面与交互](界面与交互.md)当前规则为准。

## 1. 本次交付

做出一个可连续自用的 Local First 应用。Windows 和 Android 都需完成最终验收；两端数据库独立，不提供跨设备接力。开发时先在一个平台跑通切片，再同步到另一平台，不降低最终双端要求。

```text
手动创建 Mission（可关联 Goal / GoalNode）
→ Start / Pause / Resume / Extend / End
→ 自报结束，或稍后提交材料
→ 查看执行记录、材料与可选失败原因
→ 关闭并重开，记录和计时口径保持正确
```

当前没有内置 AI，结果页显示执行事实及“智能评价暂未接入”，不显示模拟评分、评语、建议或通过验证标记，也不为等待评价保持任务未结束。

## 2. 必须包含

| 能力 | 当前范围 |
| --- | --- |
| Goal | 手动创建、编辑、变更状态，查看和恢复已放弃目标 |
| GoalNode | 树形展示、新增、改名、说明、同级调序、归档和恢复 |
| 外部大纲 | JSON 文件或粘贴 → 校验 → 预览 → 用户确认 → 新 Goal 和节点树 |
| Mission | 独立、关联 Goal 或关联节点；创建、开始前编辑和改期、开始前取消 |
| 再次尝试 | 由终态任务打开预填表单，保存后产生 RETRY 新任务 |
| 执行 | 五种执行事件、合法性、单个 RUNNING 限制、重启恢复 |
| 材料 | 三种策略、草稿、五种材料类型、首次正式提交、已有正式材料修正 |
| 截止与失败 | 强制材料截止补算；未完成或材料超时必须有记录，用户原因可空 |
| 页面 | 今天、目标、历史、我的；任务详情、独立执行页和执行记录按职责分开。运行或暂停任务通过列表及底部快捷栏进入同一执行页，列表不内嵌执行区 |
| 统计 | 最近 7 天计划数与完成数、近 30 天完成格子、节点完成记录覆盖率 |
| 通知 | FIXED 到点提醒及延后，执行/暂停通知、动作与数据库事实对账 |
| 本地数据 | Drift / SQLite、私有附件、升级保留数据、当前数据备份导出 |
| 交付 | 中文功能文案、窄屏可用、Windows 与 Android release 候选和实机验收 |

这些能力是最终范围，不要求第一天建立全部表或页面。[学习开发教纲](../教学/教纲.md)按可验收切片推进。

## 3. 当前不包含

内置 AI Planner / Evaluation、AI 实时陪伴、Plan 编辑器、ContextState / ProgressState、反思和智能记忆、掌握度、云端/账号/同步、自动执行 START、自动延期、PREFERRED 时间窗口、批量从大纲生成任务、导入 Merge / Replace、额外血缘类型、外部 Evidence Provider、正式数据恢复导入、金币/等级/排行榜。

只有当前数据的备份导出，不承诺把备份重新导入或进行跨设备合并。原始大纲 JSON 审计快照和未来完整成长上下文导出均不属于本次交付。未来能力不得提前建立空表、空接口或占位字段，见[未来方向](未来方向.md)。

## 4. 验收口径

### 4.1 Goal、节点和导入

- 创建与编辑 Goal 的标题、说明和 Why，标题 Trim 后非空。
- Goal 状态由用户决定，不由覆盖率自动修改；放弃和暂停不修改已有任务。
- 只有 ACTIVE Goal 和未归档节点能被用于新任务；当前任务的继续执行和补交不受 Goal 后续状态影响。
- 节点父子关系、顺序、归档和恢复重启后保持；归档不破坏已有 Mission 关联。
- 导入协议、字节上限、深度、节点数和错误处理遵守[数据落地与平台](数据落地与平台.md#5-goal-outline-导入)。非法输入、取消预览或事务失败均不写入半个 Goal。
- Goals 只有一个页面级“新建目标”入口，点击后选择手动创建或导入。新增根节点位于节点树区块。

### 4.2 Mission 创建和编辑

- 临时自报任务只填标题、日期和计划时长即可保存；Why、步骤和验收方向不被强迫填写。
- 从节点创建时预填标题、说明与 Goal Why；objective 默认使用标题，用户可修改，不编造步骤和验收标准。
- 新建默认可选材料，验收方向选填，用户可以只交文本、只交图片、混合或不交；强制材料必须有验收方向和合法截止时间。
- 保存时 Mission、方案和首条排期全部存在或全部不存在。
- 待开始可以改期、改方案、改验证策略；需要时追加完整排期快照。开始后锁定；取消后不再编辑。
- 开始前可取消，取消不产生 END 或失败记录；开始后放弃通过未完成报告结束。
- 再次尝试创建新任务；来源归属已经不可用时要求用户重新选择或改为独立任务，绝不自动重新激活 Goal 或节点。

### 4.3 执行与恢复

- 五类执行事件持久化；顺序、条件字段和允许的操作符合[领域模型](领域模型.md#42-事件与合法性)。
- 关闭处于 RUNNING 的应用再打开，未暂停区间继续累计；PAUSED 的关闭期间不增加 Focus。
- 未开始不生成执行时长；PAUSED 可直接 END；END 后不能再暂停、恢复或延长。
- 同一设备最多一个 RUNNING，多个 PAUSED 均能恢复查看，不因切换页面静默暂停或结束。
- 延长保存额外额度，不覆盖原计划；达到当前额度仅提示，绝不自动完成。
- 自报完成/未完成只从 END 读取，历史与页面使用同一查询口径。

### 4.4 END、材料和截止时间

END 分流以[领域矩阵](领域模型.md#52-end-的分流矩阵)为准，必须覆盖三种策略与完成/未完成的全部组合。特别验收：

- 自报完成、可选材料选择不交、任意策略报告未完成，均直接 CLOSED。
- 可选材料选择稍后交、强制材料尚未到期，均进入 EVIDENCE_PENDING。
- 可选材料之后可以明确放弃提交并结束，不因跨日超时；强制材料不可跳过。
- 首次提交至少一条有效材料，整批原子保存后直接 CLOSED，结果页无需再次确认结束。
- 无 END、仍在执行、已取消、报告未完成、材料已经提交的任务，不被材料截止操作结束或改写。
- 强制材料到期未交，保持 COMPLETED 报告，只记录材料超时；关闭期间错过截止时，重启补记一次。
- 跨午夜或截止后才 END 报告完成，同一事务保存报告和材料超时；不出现负时间或先于 END 的关闭时间。
- 截止前通过事务内校验的提交有效；截止时刻起提交失败并执行超时处理，不能同时留下首批材料和超时记录。
- 重复点击、重复通知、重复补算均不重复写事件、材料或 FailureRecord。
- 未完成记录必须存在，用户原因可为空；不强迫用户写说明，不填原因也能结束。

### 4.5 材料、草稿和文件

- 文字、代码、手动记录保存文本；图片、文件复制进私有目录并预览/显示可读名称。Android 支持拍照；Windows 通过文件选择添加图片。
- 单附件最多 20 MiB（20 × 1024 × 1024 字节），校验实际字节大小。
- 草稿可增删改，离开需确认是否丢弃；进程退出不保证草稿恢复，已保存 Mission 仍待补材料。
- 正式提交前无 Formal Evidence；复制或落库失败保留当前草稿；正式材料重启后仍可读取。
- 正式材料只能追加修正，原条目和附件保留；不向已经结束但没有材料的任务补交首批材料。
- 不读取来源路径作为长期附件；不删除仍有正式引用的文件；启动时只清理已确认无引用的草稿遗留。

### 4.6 页面、进度和日期

- 页面操作与全部六种 MissionPhase 对齐。今天页不设底部取消折叠区；最终通过“全部任务”或历史取消筛选查看取消记录并再次尝试。当前相关查询入口尚未实现，不能把保留数据描述为已经有可用入口。
- Today 提供所选日期的固定日程窗口、自选任务和安排概览；“查看全部”只打开所选日期的完整固定日程，不等于跨日期的“全部任务”筛选。最终另有跨日执行、待补材料和过去未开始任务的处理入口，不让任务因日期变化失联。
- 完成数只统计 END 报告 COMPLETED；未完成 END、取消、重复材料和材料修正不增加完成数。
- 完成日期按 END 在当前设备时区对应的日历日期；计划数按当前排期的 scheduledDate。二者分别展示，不强行限制完成数小于计划数。
- 设备时区改变可以重新分组实际完成日期，原始 UTC 事件、排期日期和截止时刻不变。跨日任务只在实际 END 日期计一次完成。
- 节点标签和覆盖率遵循[领域模型 §2.3](领域模型.md#23-节点记录与覆盖率)，报告完成即可计入，待补材料不阻塞记录覆盖。
- History 默认展示已有 END 的 Mission，包括待补材料、完成、未完成和材料超时；取消记录通过筛选查看，不混入执行完成数。
- 主办理路径及系统选择器、必要返回遵守[三步交互原则](../ui设计手册/三步交互原则.md)；完整详情和结果阅读页可选，不作为执行、报告、材料提交的强制中转。正常、取消、错误和权限分支分别审查。
- 中文按钮、标签、错误提示和日期选择器；品牌名和用户内容不强制翻译。窄屏无溢出，键盘弹出后仍能滚动到操作按钮。

### 4.7 通知与数据安全

- FLEXIBLE 无开始提醒；FIXED 到点仅提醒，不自动 START；“延后 15 分钟”只改变提醒安排，不改业务排期。
- 通知“停止”在 RUNNING 时先 PAUSE，再进入 END 确认；用户返回保持 PAUSED，明确确认完成/未完成后才写 END。
- 通知“继续”仍遵守单个 RUNNING 限制；陈旧动作重新校验，不执行非法转换。
- 通知权限、精确提醒能力或调度失败不回滚已保存业务事实；显示降级说明和重试入口。
- Android 重启恢复提醒，强行停止后不承诺继续提醒；Windows 通知行为以实际分发形态验收，不先声称已验证。
- 不自动加载示例数据、不提供正式“一键清空”、不以删库重建代替迁移。
- 未知枚举、损坏关系、不支持的存储版本明确报错；事务失败不留下半条链。
- 备份导出包含一致的数据库快照、全部正式附件和格式说明；导出失败不修改源数据，不包含未提交草稿。恢复导入另行设计。

### 4.8 U08 与执行操作专项验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| v1 旧库升级 | 先保留 v1 Schema 快照；v2 增量建立事件表，既有任务、排期、方案及关联不变；新建库也能得到完整 v2 结构 |
| 首条事件与序号 | 首条只能 START、sequence=1；之后连续递增；相同毫秒按 sequence 排序，倒退时刻被拒绝 |
| 条件字段 | START 绑定同任务最新排期；EXTEND 仅正整数分钟；END 及可选材料选择按数据模型校验，其他动作不得携带不适用字段 |
| 重试与新操作 | 同一事件编号及相同业务输入重试只返回原记录；相同编号不同输入拒绝；新一次延长用新编号，额度才能再次增加 |
| 迟到与并发 | 旧 expectedSequence 被拒绝；两个任务竞争开始时最多一个成功；编辑/取消与 START 在写事务中互斥 |
| 阶段推导 | 无事件为待开始；START→执行中；PAUSE→暂停；暂停时 EXTEND 仍暂停；RESUME→执行中；取消无事件 |
| 结束与失败原子性 | U10 接入 END 写入口时联验 END 与必要 FailureRecord 同时保存；U08 不提前暴露不完整的 END 生产入口 |
| 结束报告中途返回 | 打开报告前已保存的 PAUSE 保留；取消报告无 END，明确继续才产生 RESUME；PAUSE 失败不打开报告 |
| 历史与损坏数据 | 事件不能直接覆盖/删除；未知类型、缺序号、错误引用不猜成正常阶段，明确报错 |

U08 完成定义为事件模型、合法性/阶段计算、Schema 快照、增量迁移和真实存储验证。U09 负责可用执行动作与全局竞争联验，U10 负责 END/失败原子链，U12/U13 负责材料阶段全部分支；不能用当前单元通过宣称六阶段全部落地。执行规则的权威来源见[事件与合法性](领域模型.md#42-事件与合法性)和[执行操作身份](领域模型.md#91-执行操作身份与重试)。

## 5. 完成定义

在 Windows 与 Android 分别用真实数据完成：

```text
独立创建 Mission → Start → Pause 或保持 Running
→ 关闭并重开 → 恢复 → End → 自报结束或提交材料
→ 结果页 → 再次重启后查看完整历史和附件
```

再覆盖 Goal/大纲、取消与重试、可选材料跳过、强制材料超时及跨日、通知权限失败、备份导出、损坏数据提示和升级保留数据。构建成功和页面截图均不能代替行为验收。

当前实现、验证与学习进度分别记录在[学习进度](../教学/学习进度.md)，本规格不声称上述全部能力已经实现。
