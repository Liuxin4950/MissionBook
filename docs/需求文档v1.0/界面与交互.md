# Mission Book — 界面与交互

视觉布局参考[UI 设计稿](../ui设计手册/README.md)，业务行为遵循[领域模型](领域模型.md)。设计稿中的历史功能示意不扩大当前范围。本文件定义当前版实际显示和操作，不保留模拟评价界面。

## 1. 视觉与文案

Mission Book 的主标语是“让每一个行动，通向更好的自己。”，英文品牌语为 Turn direction into action. / A better you, one mission at a time.。Plan / Act / Grow 表达看清方向、专注执行、持续成长，不表示当前已有 Plan 编辑器。

界面统一引用[颜色与布局规范](../ui设计手册/颜色与布局规范.md)和[唯一颜色定义](../ui设计手册/assets/正稿v1.1/design-tokens.json)：暖白#F7F8F2、森林绿#244D3D、柑橘#D7F57B，全部使用平台无衬线字体。通过位置、留白、圆形动作、胶囊控件和细分隔表达层级；新增入口为页面标题区的圆形按钮，主要提交为胶囊按钮。任务名18/24，页面标题28/36，控制16/24，辅助14/20；执行主Focus单独48/56，冻结摘要28/36，不按内容随意改同级字号。

页面标题、导航、按钮、输入标签、帮助、错误和日期选择器使用中文。Today / Goals / History / Me、In Mission、Result 是文档中的页面代号，实际显示“今天 / 目标 / 历史 / 我的”“执行任务”“执行记录”。Why / What / How / Verify 可作为次级装饰英文，必须同时有中文标签。品牌名与用户内容不强制翻译。

语气陈述事实，不评判用户；不使用金币、等级、签到、排行榜。已提交材料不显示“Verified / 已通过验证”，覆盖率不显示“已掌握”。

## 2. 信息架构与导航

```text
今天 Today：当前执行、所选日期任务、待处理入口、活动概览
目标 Goals：目标列表 → 目标详情与节点树 → 节点任务
历史 History：执行记录 → 结果页 / 待补材料
我的 Me：设置、本地备份导出、关于
```

任务工作区包含详情、执行、结束报告及按策略展开的材料/结果状态，原型分屏不等于必须逐页跳转。结果是只读业务结果入口，另提供修正材料和再次尝试，不包含“确认后才结束”的动作。

四个顶层页保持各自导航与滚动状态；任务子页使用正常返回栈，不重复堆叠底部导航。系统返回、页面返回与关闭编辑页使用相同的未保存内容提示。

正常办理优先在顶层对象上下文原位展开：今天的任务行、目标卡中的节点/任务区、历史的记录行。保留对象标题、状态、必要摘要、同列表的相邻项及导航，不全屏替换为另一项独立工作。目标卡箭头展开路径，节点标签展开任务；完整目标详情、节点任务、任务详情与记录页另作可选专注阅读入口，不是办理的强制中转。12张图用于表达页面或工作状态，不要求12条串行路由。主路径与系统往返的计数见[三步交互原则](../ui设计手册/三步交互原则.md)。

任何顶层有RUNNING或PAUSED任务时，导航上方提供条件式当前任务快捷栏：优先RUNNING，再最近PAUSED；可原位切其他暂停任务。它直接进入该任务工作区，不绕今天。无执行任务时不显示空壳。今天页已有同一当前任务行时不重复堆一张卡。进入工作区后报告、材料、结果均保持任务身份和执行摘要；正常附件路径仅此一次工作区跳转，加系统选择进入与必要返回，共三次。

## 3. 启动与错误

启动页短暂展示品牌与旅程插画，不用虚构进度条掩盖未知加载。数据库初始化、迁移及截止补算完成前显示可解释的加载状态；失败显示原因、重试和错误详情入口，不永远停在品牌页。

开始展示业务数据后，不注入示例任务或假评分。通知对账失败可单独提示，不阻塞已经可用的任务记录。

## 4. Today

### 4.1 布局与当前任务

上方显示页面标题和所选日期，主体为紧凑计划顺序；当前任务行突出标题、计划投入与主操作，Goal路径（独立任务显示“临时任务”）、Why和方案按需原位展开，不在首屏叠加长说明。待开始显示最新排期的“计划时长”；已有 START 才显示原计划、当前额度与 Focus。活动统计位于任务列表后方，不挤占日程主视觉。

当前强调只展示一条：优先全局 RUNNING，其次最近暂停的 PAUSED，最后所选日期中已有“可以开始”标签的 NOT_STARTED。同一任务在日程内已经突出时不另建重复当前卡；跨日任务用持续可见的简洁快捷栏。多个暂停任务通过“其他暂停任务”原位查看。日期不影响正在执行任务的可见性；没有合适任务显示明确空状态和创建入口。

下面展示所选日期的任务列表，默认今天。FIXED 按固定时间排序，FLEXIBLE 随后按创建时间排序，同值以 id 稳定排序；取消项默认折叠。完成报告有独立完成标记，“待补材料”“材料超时”“未完成”“已取消”用文字区分，不能都画成完成圆点。

自选时间区域默认折叠，只显示前 3 项；超过 3 项时显示展开入口，展开后可收起。折叠只限制显示数量，保持原排序与完整查询结果，点击展开或收起不重新查询。2026-10-21 本轮确认：计划日程右侧补“全部任务”入口；用户暂缓确定其列表范围和实现，当前入口禁用，待功能确定后再接通，不能绑定空回调。

### 4.2 待处理与活动

- 待补材料入口查询全部日期的 EVIDENCE_PENDING，强制材料按截止时间优先，可选材料显示“无强制截止”。
- 过去日期的 NOT_STARTED 有“以前未开始”入口，可改期或取消；不自动延期或消失。
- “全部任务”提供日期、阶段和 Goal 筛选，包含取消任务。
- 下方展示最近 7 天计划数和完成数、近 30 天完成格子。两组数字分别标注，不把完成/计划强行解释为成功率。
- 日期与统计口径见[本地应用规格](本地应用规格.md#46-页面进度和日期)，没有记录显示明确空状态。

## 5. 创建、编辑与详情

### 5.1 创建表单

默认 SELF_REPORT + FLEXIBLE + 今天，主区只要求标题、日期和计划时长；可展开填写 Why、具体目标、步骤与验收方向。objective 默认采用标题，用户修改过后不再跟随标题覆盖。

开启固定时间才展示时间选择；切换到可选/强制材料时展示验收方向，强制材料额外展示截止时间。修改日期/时区后重置默认截止并让用户在保存前看到最终值；若所选过去日期使默认值已经过期，标出错误，要求用户显式选择合法截止，不自动推到未来。不能在没有有效值时静默保存条件字段。

从 GoalNode 进入预填节点标题、说明与 Goal Why，归属可见。保存时重新校验 Goal 为 ACTIVE、节点有效，若已经归档或放弃，提示重新选择或改成独立任务。

保存只触发一次原子创建；失败保留用户输入，成功后在原工作上下文显示已创建并阻止重复提交，“查看今天/对应日期列表”作为可选动作，不再强制自动跳转，以满足三步交互约束。取消有内容的表单需确认丢弃。编辑、改期仅在待开始时出现，修改排期原因可选。

“再次尝试”预填来源标题、Why、方案与策略，保留 RETRY 来源；日期重置为今天、时间策略默认 FLEXIBLE，强制材料截止重算。用户必须确认保存才创建新任务，不复制事件、报告、材料或失败记录。

### 5.2 详情主操作

详情依次展示为什么现在做、具体目标、步骤、验收方向；缺少可选内容时不显示空标题。底部根据同一 Phase 查询显示操作：

| Phase | 主操作 | 次级操作 |
| --- | --- | --- |
| NOT_STARTED | 开始任务 | 编辑、改期、取消任务 |
| RUNNING | 返回执行 | 暂停、结束 |
| PAUSED | 继续执行 | 结束 |
| EVIDENCE_PENDING | 整理材料 | 可选材料可放弃提交并结束 |
| CLOSED | 查看执行记录 | 再次尝试；有材料时可修正 |
| CANCELLED | 查看取消记录 | 再次尝试 |

取消任务需要确认，开始后不显示取消入口。提前开始显示原计划时间，点击开始本身就是用户确认；如已有另一个 RUNNING，提示先暂停或结束，不静默处理它。

## 6. 执行任务

圆环和主计时显示 Focus；同时显示原计划、已增加额度和 Current Budget。圆环以 Current Budget 为分母，超出时保持满环并显示实际超时，不覆盖原计划。

- RUNNING 显示“暂停 / 结束”，PAUSED 显示“继续 / 结束”。
- 暂停停止增加 Focus，Elapsed 继续增加；暂停按钮旁可展开可选说明，未展开时直接保存无原因的 PAUSE，不强制弹表单。
- “延长时间”要求正整数分钟；在 PAUSED 下延长仍保持暂停。
- 达到当前额度显示“结束 / 继续”，继续选择新额度后记录 EXTEND；不自动 END，不每次刷新重复弹窗。
- 当前目标可以展开查看完整方案，开始后为只读。
- 计时器只刷新展示，时间计算遵循[领域模型](领域模型.md#6-时间口径)。

执行、结束报告及后续材料操作共享任务工作上下文，持续保留任务身份与必要的计划/执行摘要。“结束”先暂停后在该上下文展开报告区域，不强制导航到独立结束页；不能把整页独立工作视图改叫弹窗来规避跳数。材料和结果原型可表现相应工作状态或直达入口，不要求按图片数量逐页路由。

从今天任务行或目标卡内任务摘要开始时，执行控制在原任务区展开；报告选择、确认后材料编辑与提交回执仍在该区域，任务标题、冻结摘要和相邻列表保留。含文件的完整执行链不得强制先进入独立目标详情/节点列表再进入另一执行页；这些阅读视图可以打开，但不是正常办理入口。另一个RUNNING冲突在原任务区并列显示冲突任务及明确暂停/结束操作，不增加冲突详情中转页，也不静默暂停。

## 7. 结束确认

本节的结束确认指任务工作区内的报告状态，不要求独立路由。保留任务身份、暂停状态和冻结Focus摘要，在原执行区域展开完成情况；初次不代选，选择本身不写事实，明确确认后才保存报告与END。

从页面点击“结束”和通知点击“停止”使用同一交互：若仍 RUNNING，先保存 PAUSE，再打开完成/未完成选择；已经 PAUSED 则不重复暂停。返回或取消确认保持 PAUSED，需要明确点击继续才恢复。

结束报告区域展示“已完成 / 未完成”，用户确认后才写 END。选择未完成时可填原因，也可留空；按钮不得因为未填写原因而禁用。

完成时按真实策略显示：

- 自报：确认后直接结束。
- 可选材料：用户选择“直接结束 / 稍后提交材料”。
- 强制材料：显示确切截止日期和时间；如果已经过期，明确说明“仍会保存完成报告，同时记录材料未按时提交”。

确认成功后按[END 分流矩阵](领域模型.md#52-end-的分流矩阵)显示相应结果或材料工作状态，不以额外独立路由强制增加办理跳数；任务身份和执行摘要保持可见。材料编辑时间不计入 Focus。保存失败保留选择和原因，不产生部分 END 或失败记录。

## 8. 材料编辑

材料编辑在任务工作上下文中展开，保留任务身份、待补材料状态和冻结的Focus摘要；明确标注“草稿，尚未进入正式记录”，支持文字、代码、手动记录、文件与图片；Android 另提供拍照。选择文件后复制到私有目录，图片直接预览，文件显示原名和大小。

- 列表可添加、删除、修改，主按钮为“提交材料”。至少一条有效材料才能提交；END及完成报告已经保存，首次材料提交仅关闭材料阶段，不重复写END或重算Focus。
- 提示“提交后保存为正式记录；原材料保留，后续只能追加修正”。
- 可选材料显示“放弃提交并结束”，有草稿时先确认丢弃。
- 强制材料展示准确截止时间，包含日期，不硬编码“今天 24:00”。
- 离开有内容的草稿页时确认丢弃；确认后仅丢弃草稿，任务仍待补。进程退出不承诺恢复草稿。
- 提交成功在原任务上下文显示提交回执与正式材料，完整执行记录可选展开，不强制追加结果路由；失败保留当前草稿。发现超时则说明完成报告已保留、任务因材料超时结束，并让用户确认丢弃未提交草稿。
- 文件复制失败、超限、读取失败有具体提示；不静默跳过选中的附件。

修正材料从结果页的单条材料菜单进入同类编辑器，按钮为“保存修正”，一次提交一条替代记录，不重新开启任务或重算截止。

文件、图片的普通选择由当前草稿区直接调用系统选择器，必要返回后继续同一草稿区，不再开附件确认页。Android拍照采用当前草稿区内嵌取景/预览，保留任务摘要；首次所需相机权限请求及必要返回计两次，授权后拍摄、重拍、确认在原区完成，不强制外部相机和多次页面返回。拒绝时保留草稿并允许改选文件。Windows不显示拍照。平台实现若采用额外独立拍摄/权限向导，必须重新审查，不能沿用三跳结论。

## 9. 结果页

显示标题与路径、用户完成报告、实际开始/结束时间、Focus、原计划、额外额度、暂停次数和失败原因（如有）。正式材料默认仅显示当前有效项，修正历史通过单独入口展开完整链。报告完成而材料超时要同时展示两个事实。

结果可作为任务工作区内只读状态，也可从历史直达。执行摘要与材料列表保持可见；材料正文、事件明细、修正链和单条材料修正按需原位展开。时间线明确区分START、END与材料提交，不将材料提交视作第二次执行结束。“再次尝试”在保留来源记录的上下文展开新任务草稿，字段与校验沿用创建规则；明确保存才创建新Mission，成功原位反馈，原记录保持不变，不强制再走详情和结果页。

评价区域仅显示“智能评价暂未接入”。不展示 Verified、评分条、AI 评语和下一步建议占位。返回今天不改变任何业务数据。

已取消任务显示取消时间、取消前最新排期和“没有执行记录”，不展示虚构执行时长或未完成原因。没有 END 的执行任务不冒充结果，详情主操作引导回执行页。

## 10. Goals 与节点树

Goals 默认提供“进行中 / 已搁置 / 已达成”三个筛选，“已放弃的目标”在菜单内可访问与恢复。卡片显示标题、说明、有效节点完成记录覆盖率；没有节点显示“暂无节点”。主入口只有“新建目标”，点击选择手动创建或从 JSON 导入。

Goal 详情显示 Why、状态和节点树。新增根节点位于“目标路径”区块；添加子节点、改名、说明、调序、归档在节点菜单。归档需确认并说明包含子树、历史不会删除；“已归档节点”入口可查看和恢复。

节点标签严格引用[领域口径](领域模型.md#23-节点记录与覆盖率)，不根据“未关闭任务”笼统判断正在学习。子树计数包含当前节点；有完成记录但仍待补材料时两者并列展示。

点击节点进入直接关联任务列表，行内创建入口必须写“建任务”。Goal 非 ACTIVE 或节点归档时隐藏新任务入口并说明如何恢复；已有任务仍可进入。

为满足三步交互约束，节点行及节点操作菜单可直接进入建任务表单，不强制经过节点任务列表。“已安排”等记录标签可原位展开该节点的任务摘要，按真实阶段直达开始/继续/查看记录；节点完整任务列表仍可浏览，不作为上述主操作的强制中转。树的展开、子树计数和摘要不改变节点或Mission状态。

目标列表卡内可直接展开路径及节点任务摘要，保留目标标题/覆盖与相邻目标条目。节点维护、新任务、执行及材料操作可在该区办理；这样从其他顶层切目标只需一次跳转，文件选择及必要返回各占一次，整段执行到首次材料提交仍不超过三次。专注详情图的完整树和节点列表可用于阅读，不能取代此普通操作入口后再把系统选择排除计数。

2026-10-20根据新建目标原型反馈修订：目标页的新建菜单先选择手动创建或JSON导入。手动创建进入独立表单，只展示当前未保存目标的名称、选填说明与Why，不放既有目标、节点统计或顶层导航；选填原位展开。保存成功返回来源目标列表并显示新卡与回执，返回栈不残留可重复提交的旧表单；从其他顶层起算为切目标1、进入表单2、保存返回3。返回有内容草稿时确认丢弃，保存失败保留输入。

JSON粘贴、校验和预览在目标页导入区展开；JSON文件动作从目标页直接打开系统选择器，返回目标页导入区展示读取、校验、树预览和明确确认，不先经过手动表单。用户确认前不写业务数据，成功原位显示新目标，不再强制独立预览页或结果页。保留完整输入限制、错误路径和原子保存，不以减少跳数省掉校验或确认。两种路径中的新目标都仅在成功创建后才显示“暂无节点”及添加节点入口。

已进入可选节点任务列表时，常用创建和详情操作在节点上下文内展开，保留节点归属及列表，不再强制新增独立工作页。紧凑创建仍包含标题、日期、计划时长及必要条件字段；原位保存反馈与归属校验不变。三步审查采用上段目标卡原位办理的正常路径，不把用户先浏览多个可选详情的绕路当作必须中转，也不把独立阅读页改名为原位展开。

## 11. History 与 Me

History 默认按 END 时间倒序列出真实执行记录，显示标题、完成报告、Focus、材料标签。待补材料可以直接继续整理；取消记录单独筛选。无 END 的暂停/运行任务从 Today 或全部任务进入。

历史的月份和待补材料筛选原位更新列表，计数随当前日期范围重算；默认范围应能切换到全部日期，不能让较早待补记录失联。更多菜单提供“已取消”入口。为满足包含系统选择器的三步路径，待补行的“整理”直接在该行展开材料草稿区，保留任务、Focus、相邻记录与列表位置，提交原位反馈；不强制先打开结果详情。已提交记录也可原位展开材料摘要及单条修正，完整执行记录为可选阅读入口。文件选择进入和必要返回分别计数，不能以弹窗名称免计。

Me 提供提醒能力与权限说明、备份导出、关于。当前无账号、登录、同步、AI 配置、清空全部数据或恢复导入入口。备份导出展示进度及成功/失败，保存前说明包含数据库和正式附件，不包含未提交草稿。

通知授权与准时提醒能力分别查询、展示，不能因其中一项已授权就声称整体可用。平台不支持的能力说明限制，不展示无效开关；从对应行直接进入适用系统授权/设置，返回后在原行刷新。备份在原数据区说明范围并发起，系统保存选择返回后原位展示阶段、真实进度或未知总量状态，成功显示实际保存位置，失败保留原因和重试。关于内容原位展开。这些操作不额外导航到说明页、进度页或成功页。

## 12. 通用交互与验收

- 2026-10-18新增设计硬约束：任何功能的正常完整办理路径不超过三步页面跳转，包含必经返回、自动结果跳转和系统选择器。按[三步交互原则](../ui设计手册/三步交互原则.md)审查，不将独立工作页改名弹窗来规避；早期原型分屏不等于必须拆成独立路由。相关导航仍待逐页改造和行为验收，不代表当前应用已达标。

- 中文功能文案；输入框有可见边界，聚焦、错误和禁用可辨识。
- 提交中禁用重复提交，按钮尺寸不跳变；失败保留当前表单内容。
- 页面可滚动，窄屏、键盘弹出、较长文件名和深层节点不溢出。
- 空状态提供一句说明和一个可执行的下一步；错误提供原因与重试。
- 数据库读取是唯一业务输入，导入 JSON 与设计稿示例不能直接当运行数据。
- 页面、系统返回和通知动作都复用领域 Workflow 和查询，不能各自维护状态。
- Windows 和 Android 的最终行为验收以[本地应用规格](本地应用规格.md)为准，当前布局图不能替代实际测试。
