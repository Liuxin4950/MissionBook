# 基础配图生成记录

对应图片及课程说明见[配图说明](../配图说明.md)。

## 生成方式与核验

- 使用内置 `image_gen`，每张图片一次独立生成调用；两次调用并行完成。
- 没有使用 CLI/API 密钥方式，没有使用 SVG 或程序绘图代替生成图片。
- 最终图片已从内置工具默认输出位置复制到本项目 `docs/教学/assets/`，保留工具原始输出。
- 已分别通过 `view_image` 打开本项目中的最终文件，人工视觉核对中文、英文标识、卡片状态和箭头方向。
- 架构图核验结果：已有部分与待接通部分区分明确；`MissionRepository`、`AppDatabase`、`DriftMissionRepository`、SQLite 标识可读；六个目标节点按正确方向连接；没有混入代码依赖箭头。
- 流程图核验结果：六个步骤顺序完整；卡点分支回到解释与练习；代码、验证、掌握分别列出；更新教纲与规格位于实施与验证之前。
- 生成图片是位图，无法像源代码一样精确修改每个字和箭头。新版本仍需视觉复核；图中文字与详细教纲发生冲突时，应依据已核验的代码、规格和文字记录修正图片。
- 本次复核未发现影响教学语义的文字或箭头错误。图片做了轻量图标和底色处理，不影响状态含义；小屏幕阅读建议放大查看。

## 最终原始 Prompt：架构图

```text
Use case: infographic-diagram
Asset type: MissionBook 中文软件开发教学教纲的可审阅解释图片。
Primary request: 生成一张高质量中文教育信息图，横向 16:10 构图，浅暖白背景，清晰深色中文无衬线字体、宽松留白，青绿色表示代码已存在，琥珀色表示待实现或待接通。字体足够大，读者是能读懂部分 Dart / Flutter 代码但需要逐步解释的新手。不要花哨装饰，不要渐变，不要人物，不要水印。

Title (verbatim): "MissionBook：已有骨架与待接通链路"
Subtitle (verbatim): "代码存在，不等于功能已经跑通"

上半部分标题 "当前已有"，三个并排青绿色细边卡片，无连接箭头：
左卡标题 "界面层"，正文两行 "Flutter 导航"、"今天页静态骨架"；
中卡标题 "业务层 domain"，正文两行 "三个业务对象"、"MissionRepository 接口"；
右卡标题 "数据层 data"，正文三行 "三张 Drift 表"、"AppDatabase"、"数据库生成代码"。
三个卡片下是一条浅灰说明带，精确文字："边界：业务对象不依赖 Drift 表；仓储实现负责转换。"
这里是代码清单与边界，不要画任何箭头，避免混淆代码依赖与运行数据流。

下半部分标题 "下一条目标链路"，副标题 "整条业务链路尚未接通"。
下方用六个琥珀色虚线边框的编号节点，清楚顺序连接，整条链从左到右：
"1 创建页面" → "2 创建规则" → "3 Drift 仓储" → "4 事务保存" → "5 SQLite" → "6 读回刷新"
第三个节点下允许一条清晰注释 "DriftMissionRepository"。所有箭头为同一琥珀色细实线单箭头，明确表示目标运行顺序，不是代码依赖。不得出现反向箭头、交叉线或额外连接。
六个节点下写："先让一次创建能保存、读回、显示，再扩展功能。"
底部小型但清楚的图例，精确文字："青绿色：已有代码"、"琥珀色虚框：待接通链路"、"箭头：目标运行顺序"。
Constraints: 必须准确呈现以上中文与英文标识，少量大字，文字可读；当前界面是静态骨架，不能显示“已实现创建”或“已完成持久化”；目标链路整体是计划，不能误画为已经实现。不得把箭头画成代码依赖图。
```

## 最终原始 Prompt：教学流程图

```text
Use case: infographic-diagram
Asset type: MissionBook 中文软件开发教学教纲的教学推进与变更控制解释图片。
Primary request: 生成一张高质量中文教育信息图，横向 16:10，浅暖白背景、深色清晰无衬线中文字体、充分留白，柔和蓝绿主色、琥珀色回退与变更分支。信息准确比装饰重要。不要人物、不要水印、不要渐变、不要小字。

Title (verbatim): "每一步都有理由、有验证、有记录"
Subtitle (verbatim): "适合：能读懂部分代码，需要逐步解释"

左侧约 65% 宽度为主流程，标题 "一次只完成一个功能单元"。六个大型卡片从上到下垂直排列，清楚向下单箭头：
"1 明确目标与验收"
"2 阅读当前代码"
"3 解释设计与参数来源"
"4 用户动手完成一个单元"
"5 运行验证＋口述／独立小改"
"6 分别记录：代码｜验证｜掌握"
第 5 卡片旁加一个简单琥珀色分支："遇到卡点"，旁边一条回转箭头向上返回第 3 卡片，清晰标注 "回到卡点解释与练习"。回转箭头不能指向下一阶段，不得增加“自动通过”。

右侧约 35% 宽度为独立浅琥珀色区域，标题 "设计或流程发生变化"，四个节点从上到下，用单向箭头：
"发现需要调整"
"说明原因与影响"
"更新教纲与规格"
"再实施与验证"
右侧区域底部一张强调卡片，文字两行：
"代码完成 ≠ 学会"
"三项状态分别记录"

底部精确文字："通过当前单元的验收与掌握检查，再推进下一步。"
Constraints: 图内所有文字使用所列原文；保持主流程和变更流程独立，不画无意义交叉箭头；以教学循环而非自动化流水线表达；卡住时回到该点，不盲目推进；必须清晰显示修改教纲与规格先于实施。大字少量，不添加复杂术语。
```
