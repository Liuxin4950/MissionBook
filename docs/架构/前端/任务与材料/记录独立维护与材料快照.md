# 记录独立维护与材料快照

> 2026-11-01：记录用于独立留下内容，任务按需将内容提交为材料。本文描述 v16 实现；设备验收单独记录。

## 产品边界

记录与任务是并列业务对象，都可以独立存在，也可以关联目标、节点。记录不要求排期、行动方案、执行事件或任务结果。任务材料是任务的一次提交事实，不接管来源记录。

一条记录支持文字，或一个图片/文件附件及说明。多附件编辑和多任务复用不在本轮范围；同一条记录仍最多关联一个任务，但它自己的内容、归属和删除不再因此锁定。

## 数据与职责

| 对象 | 事实和职责 |
| --- | --- |
| Records | 当前内容、来源、发生/保存时间，以及自己的 goalId / goalNodeId |
| EvidenceRecords | 提交时的完整内容快照、提交时间、任务身份和修正链 |
| record_id | 材料来源的稳定编号；可保留已删除来源的编号，不再是强制外键 |
| ContentDraft | 记录与材料实际共用的内容字段，不含归属、任务和修正身份 |
| RecordDraft | 独立记录保存意图，不包含 supersedesEvidenceId |
| AttachmentCoordinator | 记录和任务共享的附件准备、引用校验、草稿清理与提交互斥 |
| EvidenceDraft / Evidence | 材料草稿、提交快照及追加修正身份 |
| SavedRecord / RecordPage | 页面使用的类型化只读投影；SQL 列名和工具 JSON 留在边界 |

记录修改后，任务材料仍展示当时的快照。记录删除后，材料来源提示已删除，但正文、附件和任务详情继续可读。更新任务材料走已有修正命令，追加历史，不自动跟随原记录。

附件文件不复制；记录与材料快照可以引用同一存储键。清理与备份继续使用两表引用并集，材料仍引用的文件不能被清理。

## 已有调用链

```text
记录编辑器 / 助手保存记录
  → RecordService → AttachmentCoordinator（准备、读取、清理）
  → RecordService.save → 同一附件提交互斥 → 记录仓储事务
    → Records
    → 可选委托统一材料命令 → EvidenceRecords 内容快照

设置记录归属
  → RecordService.setOwnership → RecordRepository.updateOwnership
    → 只更新 Records 的目标、节点

用作任务材料
  → 选择任务 → 预览并确认
  → RecordService.useAsMaterial → MissionService.useRecordAsMaterial
    → 材料事务取得写锁 → 确认已有提交 / 重读并校验预览内容
    → 原子保存材料快照 → 通知重读

执行报告 / 实际时间更正
  → 任务模块 ExecutionReportButton → MissionService.reportExecution
    → 既有执行报告和事件事务
```

记录编辑器只使用 RecordDraft 和 RecordService；记录与任务通过同一个 AttachmentCoordinator 协调共享文件。RecordService 与 MissionService 协作提交任务材料并通知事实刷新；执行报告由任务服务处理。

助手使用 setRecordOwnership 设置记录归属，使用 useRecordAsMaterial 提交任务材料；两者分别由业务服务处理，并在事务内保存操作回执供结果恢复。

## 读取与总结

- 记录列表、详情、当日条带和助手共用 SavedRecord / RecordPage；仓储提供类型化摘要和分页，助手入口将其转成有界 JSON。
- 正文展示保留分页；进入文字编辑前单独读取完整正文，保存时进行乐观冲突检查，避免截断长正文。
- 任务详情和助手材料读取均直接读取材料快照，不回退到当前记录内容。
- 任务评价使用有效材料快照，不再引用原记录的最新总结；图片按快照附件逐项观察后汇总，原记录修改或删除不改写任务评价依据。
- 目标、节点直接记录汇总按记录自身归属收集；已作为任务材料也不失去直接记录身份。记录和任务可能描述同一成果，汇总不把数量当作独立成果数量。
- 来源存续状态只用于导航与提示，不作为读取材料内容的前提。

## 当前开发结构

数据库只维护当前 v16 结构，通过 onCreate 创建表、索引和触发器；不保留旧版转换、回填或拒绝特定旧版本的自定义分支。表定义与生成代码是结构来源，测试直接验证当前建库结构与实际约束，不额外保存 JSON 结构副本。

材料 CHECK 要求完整快照，不能用非空 record_id 绕过内容完整性校验。材料附件键允许复用，以便多个修正版本共享文件；来源编号仍唯一，维持本轮单任务引用范围。
