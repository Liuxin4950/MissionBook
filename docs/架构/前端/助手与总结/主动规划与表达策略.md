# 主动规划与表达策略

> 用户决定方向，助手负责把方向组织成有依据的近期行动。本文描述 2026-11-26 已接入的提示词、计划工具控制与表达设置；真实模型表现见[本轮审查](../../../审查/2026-11-26-主动规划与回复风格.md)。

## 决策与表达职责

| 层次 | 已接入的职责 |
| --- | --- |
| 统一行为 | 主动理解愿望，利用已知事实，自主拆解与估时；只询问会改变目标范围、关键期限、归属或执行方式的问题 |
| 角色定位 | 调整关注重点。计划顾问侧重阶段、近期行动、总负担和冲突；其他角色同样适用主动规划原则 |
| 回答风格 | 调整语气、篇幅、解释结构。提问引导围绕价值取舍，不将名称、步骤、估时或灵活排期交还用户逐项填写 |
| 工具与宿主 | 固定提案、校验执行引文来源、按意图和现有权限决定是否等待确认；角色和风格不能修改宿主权限 |

`AssistantRole` 与 `AssistantReplyStyle` 保留原枚举身份。六种风格的文字分别侧重简洁重点、解释依据、可承受步骤、行动清单、关键取舍与少量方案比较。已保存的自定义正文继续生效，不自动重写；设置编辑页说明职责，并同步更新用于生成自定义正文的可复制提示。

## 愿望、规划与执行

EXPLORE、PLAN、EXECUTE 是行为约定，不是新增的数据库阶段或三个 Agent。EXPLORE 对应理解与讨论，模型不应调用业务写入；PLAN 可以提出有日期、估时的可编辑安排；EXECUTE 对应当前用户已委托的实际操作。

当前生产路径：

```text
用户正文 + 已有引用、记忆与摘要
  → 主提示：识别讨论 / 规划 / 执行，按需读取已有目标、任务及日期
  → 模型请求 planMissions（单项也可用）
      ├ intent 缺省或 PLAN
      │   → prepare 固定条目、原任务快照及冲突预览
      │   → 所有权限模式都等待计划卡确认
      │   → 用户可编辑、移除、取消；编辑后重查冲突
      └ intent EXECUTE + executionBasis
          → 宿主校验引文逐字来自当前用户正文
          → prepare 固定条目、原任务快照及冲突预览
          → 询问 / 自动模式等待确认；完全模式自动执行
          → 悬浮 confirmWrites=true 仍等待确认
  → 原 MissionService.applyPlan 与仓储事务复查并保存
  ← 实际回执 / 阻塞 / 结果未知核对
```

`executionBasis` 只接受最后一条用户消息中的非附件正文，不接受旧消息、角色风格、网页或“MissionBook 文本附件”。PLAN 不携带该字段。确认卡编辑不得更换 `intent` 或 `executionBasis`，也不得借编辑更换任务身份和归属；点击“确认保存”本身是针对最终提案的明确操作。

来源校验不等于理解语义：当前没有独立的宿主自然语言意图识别器。模型仍可能把当前正文里的愿望、引用或否定句误当执行依据；本轮真实模型场景检查这类行为的部分情况，不能证明任意文本均能正确识别。其他写工具仍沿用现有权限，单项任务规划走 `planMissions` 的要求由统一提示约定，尚未把全部写工具重构为同一个意图协议。不能据此宣称所有写入入口都已获得独立语义授权证明。

## 排期与信息边界

- CREATE 必须有 `scheduledDate` 和 `plannedMinutes`；未指定固定时段时默认 FLEXIBLE，不追问开始结束时刻。
- RESCHEDULE 必须有 `scheduledDate`，分钟可省略。准备阶段会补入原分钟供卡片统计和编辑使用，原固定/自选方式及固定开始时刻默认沿用。
- 日期未知仍可推进核对通知、报名要求或项目方向等独立步骤。真正依赖截止日期的日程保持待定，不伪造期限。
- 日程是已记录任务，固定时段检查是重叠检查；二者都不等于完整现实空闲时间或每日容量证明。FLEXIBLE 无重叠不代表能全部做完。
- 阶段、步骤、投入与初步日期可以提出估算，条目的 `notes` / `why` 说明依据。比赛要求、截止、用户承诺和效果没有来源时不能编造，一般经验也要标明假设。
- 长期目标先描述阶段轮廓，只细化近期行动；读取优先摘要与相关范围，不无目的遍历完整历史或一次展开全部远期任务。

## 现有基础与后续规划

已复用五层记忆、渐进读取、Agent Loop、可编辑计划卡、固定回执和事务冲突检查，没有新增 Planner Agent。自动总结仍负责执行事实到任务、节点、目标总结；“总结后自动判断后续安排并局部重规划”的检查点和跨会话持续推进尚未在本轮接通。工具返回预算和完整错误分类评估也不以本轮提示调整宣称完成。

## 验证入口

- [计划工具回归](../../../../test/application/assistant/assistant_plan_test.dart)：提案在完全权限下仍等待、明确执行自动保存、悬浮额外确认、编辑不能升级意图、旧消息和附件不能提供执行引文、原固定策略与分钟保留。
- [计划卡交互](../../../../test/presentation/assistant/assistant_plan_card_test.dart)：手机大字、平板、编辑移除、重新检查与确认。
- [真实模型场景](../../../../test/manual/assistant_planning_live_test.dart)：环境变量 `DEEPSEEK_API_KEY`；隔离内存库、固定业务日期与六种风格。`PLANNING_EVAL_REPORT` 可指定合成场景记录位置；没有凭据明确跳过。

真实模型报告中的 `passed` 表示该用例的结构和数据库断言通过，不代表对回答的全部事实、篇幅、规划质量、风格稳定性或全平台体验作出验收。token 用量记录请求总输入、输出和供应商缓存命中，不将输入总量直接视作未缓存费用。
