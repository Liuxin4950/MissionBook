## 数据流

```text
新会话 / 对象入口 → 未持久化草稿（独立 draftKey）
首次有效发送 → 页面输入区 → Controller → 创建会话与关联对象 → 会话协作者 → agent_core
  → 公开工具 schema → prepare / 校验 / 快照
  → 需要确认的写操作 → 用户确认 → 业务服务 → 仓储事务 → 保存回执
  ← 成功结果 → AssistantToolResultFormatter → 会话消息与引用
  ← 拒绝或可恢复错误 → 会话消息与引用

事实变化 → 持久总结队列 → AnalysisService.claim
  → 按 AnalysisScope 读取上下文 → 模型 → 版本匹配才发布
```

具体任务投影移到 application/missions/mission_projection.dart，domain 不输出助手展示 Map。模型及 JSON 协议字段仍在边界转换；内部用枚举消除魔法 scope 字符串。

## 会话创建与提示词

点击新会话或首次进入某个对象的助手，只切换到空白草稿，不写 assistant_sessions；首条有效文字或附件发送时才创建持久会话。重复点击新会话不新增历史。全局和各对象的草稿按 draftKey 隔离；创建后页面切换到会话编号，语音气泡显式接续本轮消息的身份。

首条输入在预检或上下文准备阶段失败且未保存用户消息时，清理本次新建空壳。用户消息已经保存后即使模型失败，保留真实历史供重试和恢复。既有历史不批量删除。

主提示词独立由 assistant_prompt.dart 组合：讨论和假设先回答，明确操作且参数齐全时走工具，关键歧义才询问；已给出的信息与授权不反复索取，实际工具权限仍由宿主执行。事实、用户声明、材料、模型评价与掌握分别处理。恢复历史时沿用当前提示词及用户角色设置，不改写历史消息。

## 偏好与失败恢复

自动总结范围为 record、mission、node、goal；memory 为独立的后台提取范围。偏好读取失败时保留最近成功快照或初始默认快照，显示错误和重试入口；实际自动取任务暂停，避免在不知道用户设置时发送数据。

显式手动请求表达本次意图，可在偏好读取失败时处理。领取任务时自动范围为空仍允许 manual 任务，不能把读设置失败写成用户关闭所有开关。设置重读成功后恢复正常范围；主会话占用模型时后台队列暂停取下一项。

## 模型请求的生命周期

后台分析、主会话工具内的按需分析、连接检查分别登记取消令牌。主会话开始立即抢占后台分析，停止主会话取消其按需分析，关闭控制器取消所有在途网关请求。控制器直接通知状态变化，不再依赖 200ms 轮询。

分析默认 60 秒、连接检查 30 秒；取消等待覆盖图片读取及模型响应，结果返回后再次校验令牌。迟到成功不能返回，迟到异常有接收端；finally 释放超时定时器和注册表连接。后台抢占作为 AnalysisInterrupted 交回持久队列，超时是失败，可以按队列策略重试。分析仍只携带本次来源，不附带主会话、记忆或工具。

总结队列保留 10 秒轮询：analysis_triggers.dart 在 SQLite 写事务内排待办，失败任务还受 available_at 控制；只监听页面通知会遗漏这些入口。轮询只领取满足条件的任务，不把空轮询当作模型请求。

## 回到前台与输入区

`App.didChangeAppLifecycleState` 在 hidden/paused 通知 `AssistantController.setForeground(false)`，resumed 通知 true；切后台保留健康模型请求，语音单独取消。返回前台后，在当前运行期间每隔 `resumeGrace` 对比消息、模型尝试、正文和思考快照；有进展、待确认或工具执行时继续观察，没有进展则请求取消并提供“继续本轮”。重复前台通知不会撤销仍有效的检查，新发送、继续和关闭会取消旧检查，运行结束释放定时器。已开始的业务工具仍等待真实结果，不能通过清空忙碌状态冒充完成。

页面始终响应共享语音控制器的忙碌变化，只有当前页面发起的录音才回填文字；系统后台取消完成后重新计算发送按钮。没有已持久会话时也发布状态刷新，避免准备失败后保留旧按钮状态。消息生成状态只显示进度，停止入口集中在输入区；无输入区的语音浮窗保留自己的停止入口。

## 思考程度

输入区快捷菜单和设置页共用 `ReasoningEffort` 的 off、low、high、max，显示文字由 `assistant_reasoning_display.dart` 提供。`AssistantSettings.reasoningEfforts` 按模型配置编号保存选择，`SecureAssistantSettingsStore` 写入设备安全存储中的 `assistant_reasoning_efforts`，不改任务数据库或凭据内容。

```text
输入区选择 / 设置页保存
  → AssistantController.setReasoningEffort → 配置协作者
  → AssistantSettingsStore.saveReasoningEffort → 重读偏好
  → 当前 AgentSession.configureGeneration(thinking: effort)
  → AgentLoop → ModelRequest.reasoningEffort → 现有协议编码器

新建 / 重开 / 切换模型 → 应用该模型已保存的思考偏好
```

运行中禁用更改。没有保存偏好时保留现有模型或会话默认值；已有会话配置不被无条件重置。主会话的生成设置沿用 agent_core 日志持久化，不通过新增消息模拟参数。服务实际接受的档位及效果依供应商而定，界面不将本地保存成功当作供应商能力验收。

快捷菜单通过 MenuAnchor 和 MenuItemButton 排成两行四格，沿用共享选项外观、原保存入口及原生键盘、焦点和关闭行为；默认内容宽度 160，按字号和视口约束调整。

### 思考与工具过程

本地原项目 `/root/Working/deepseek-harness-master` 的 `packages/client/ui-chat/src/client/chat/ReasoningRow.tsx`、`ReasoningContent.tsx` 与 `ChatGroupSeat.tsx` 作为展示参考：思考使用次级文字的一行预览，完整内容按需展开；同一轮的思考与工具归入过程，最终回答独立。本项目沿用自己的颜色、字号和最小触控规范。

`assistantTurnParts` 按 AssistantMessage 的原顺序和 content 块索引产生位置引用，不将不同请求的思考拼到开头。`AssistantProcess` 汇集单次用户输入后的思考、工具与中间说明；生成期间默认展开，结束后默认收起为一行，手动展开状态保留。待确认、失败或未知操作自动展开。普通过程区域按可用高度限制并滚动，生成时跟随最新内容，用户回看后暂停跟随；待处理操作不受内部高度限制，原确认、编辑及结果核对入口保留。最终回答位于过程区域外。

浮窗的单项工具入口通过 initialOperationCallId 打开主对话，自动展开所属过程及该项结果，避免新增分组后再次逐层展开；一般打开对话仍使用默认收起规则。

`AssistantThinking` 默认收起，使用无卡片边框的一行预览和 12 号文字；完整内容通过紧凑 Markdown 展开，标题也保持次级层级。只有思考没有正文的消息也保留，签名不呈现，不为未返回的思考补写内容。

```text
用户输入 → AssistantMessage.content 原顺序
  → ThinkingBlock → 思考行
  → ToolCallBlock → 真实操作状态与回执
  → 下一条 AssistantMessage 的 ThinkingBlock → 下一段思考行
  → 最终 TextBlock → 过程外的回答正文
```

`SessionActivity.requestSerial` 在每次正文模型尝试（包括工具后的再次请求、重试）递增，`modelRequestRunning` 从请求开始持续到完整消息接收或失败，`turnUserMessageId` 将快照绑定本次用户输入，恢复时沿用原用户消息。只有当前运行且当前模型请求在途才展示流尾，完整消息接收后立即转为原消息块；不再按字符串内容相等判重，因此相同文字的后续思考不会被此前请求吞掉。这些是内存展示快照，不新增持久化状态；原消息、工具结果、签名和模型回传保持不变。

## 工具与生命周期约束

普通写操作已完成或已取消后，AssistantOperationCard 默认呈现单行展开摘要：18 状态图标、12 字号的操作/对象名称和状态，最小触控高度 48。整行展开后展示原输入摘要、历史补记明细、对象入口和返回数据，去除默认铺开的两个独立详情标题及重复底部留白。待确认、运行、失败和结果未知仍保留原操作内容及确认、编辑、取消和核对入口；查询结果与专用排期卡继续使用原组件。这里只改变展示，不修改操作状态、执行或回执。

工具的读写属性由实际注册的 `AgentTool.readOnly` 提供，准备和权限判断共用该属性；注册时拒绝重名。记忆保存由事务根据实际写入、去重或保护拦截生成回执，并将同一结果用于幂等重试及操作恢复。同主题内容冲突时保留原有事实，新条目作为未验证观察，不进入核心记忆；墓碑按条目或同范围相同内容匹配，不能因来源相同阻止无关内容。后台提取只接收带用户原文引用的陈述、偏好和约束。

`getMemory` 将本页编号、对象和版本作为固定选择保存，默认20条，可指定最多100条；`manageMemory` 当前支持批量忘记，执行时校验所属会话、持久化用户消息和全部对象快照，变动时整批零写入。回执默认展示20条，`getOperation` 支持分页读取记忆清理和历史补记回执。选择快照和回执保存在现有操作回执表，不使用正式数据做测试。自然语言授权意图目前依赖主模型遵循提示词；来源消息存在本身不能证明用户确已授权。记忆保存、合并与恢复尚未合入 `manageMemory`，其他业务工具也尚未接入统一结果和回执查询。

`completeHistory` 固定目标及日期范围内的候选与跳过任务，事务内重读整个范围，任何范围或对象变化均回滚；回执分别列出已取消、已结束、强制材料及可选材料等跳过原因。零候选仍保存统计回执；模型默认收到前20项跳过明细，可用 `getOperation` 读取余下页面。补记依据要能关联本会话用户原话，但原话匹配本身不证明语义授权。

`planMissions` 接受最多100项，新建与改期共用整份事务；固定时间的一批冲突候选由一次查询读取，计划内冲突另带对方条目编号。冲突时不改变任务或排期，保存阻塞回执及完整冲突明细；成功和阻塞回执默认只返回20项，可通过 `getOperation` 分页。批量改期准备按编号批量装配原任务。单条旧工具与重做尚未收敛到该入口，也尚未提供可用时段候选。

工具目录、确认及执行使用同一组名称，不再注册隐藏别名；目标、任务、日程统一使用 getGoal / getMission / getSchedule 与同一读取契约，扩展能力不替换查询工具。权限只使用 AssistantPermissionMode 三档配置，删除旧布尔开关和读取适配；凭据状态按模型分别保存，当前模型状态由配置派生。操作回执需匹配命令类别与目标，材料回执还核对来源记录。模型配置只接受 credentialKey；摘要会话使用当前消息引用格式，旧格式报错并保留原数据。

页面 state 统一释放文本、滚动和语音对象；控制器关闭会话订阅、事件流及模型资源。协作者共享所属对象状态，不创建重复 ChangeNotifier 或新的数据库连接。错误映射保留短中文业务原因，其他错误显示相应操作的重试提示。


## 2026-11-03 实际使用修复

会话写租约仍为 30 秒。`DriftSessionStore` 追加日志时在写事务内检查 writerToken；后台暂停定时器后，原持有者若未被接管可以继续写入并续租。续租也以 token 为条件，不因时间过期永久锁死；另一窗口接管后旧 token 仍被拒绝。`AgentSession.needsReopen` 表明存储失败，下一次发送先关闭旧句柄并重读持久日志；未知工具结果仍必须核对，不能自动重放写入。

助手新增 `manageMissions`，与页面共用 [任务维护入口](../任务与材料/总览.md#任务维护与撤销历史)。action 为 cancel/delete/reset，支持 missionIds、goalId、beforeDate、phase；没有范围时必须显式 all=true。准备时固定整个范围、完整事实及指纹；确认遵循现有三档权限，提交时事务重读范围，变化则整批拒绝。回执按 20 项返回，`getOperation` 可分页；结果未知按同一操作编号核对回执。删除是物理删除，不进入回收站。自然语言授权仍依赖模型遵循用户意图，不能把 all 字段本身当作授权证明。

`getMission` 新增 date/beforeDate/phase/summaryOnly。筛选阶段来自完整 `MissionDetail.phase`；summaryOnly 返回整个筛选范围的精确 total 和 countsByPhase，不必逐页读取全文。本页 items 与全量统计分开表达；小型统计结果在读取预算耗尽后仍可读取。预算拒绝会指出累计字符、本次 offset 和范围总量，提示模型说明未覆盖部分。`getMissionRecords(section: revoked)` 与 `getMaterial` 可以追溯已撤销的历史材料，结果标识不参与当前阶段或评价。

记忆 basis 仍须逐字引用本轮用户消息的连续原文。失败提示区分记忆保存和执行报告，说明换行、标点及不可拼接/改写的要求；content 仍可概括，未放宽原话校验。

聊天 Android 附件菜单增加拍照，复用 PhotoCapturePanel 的预览、重拍与相机生命周期；照片确认后进入原消息草稿，不直接发送。拍照和系统选图共用超限压缩确认：原图最多 20 MiB，超过发送上限 4 MiB 时用户可选压缩副本，保持原文件；CPU 压缩在独立任务运行，检查像素上限、纠正方向、按尺寸缩小并转 JPEG。多帧图压缩只取第一帧。仍保留每条 4 个附件、合计 8 MiB 以及发送前预览和取消。文件读取、压缩和总量错误不会清空草稿。

记录摘要独立于任务、节点和目标提示：原图仍由 `AnalysisInput.imageKey` → 模型网关 → ImageBlock 发送，提示优先辨认可读的文字、公式与步骤，标注模糊位置，不把无说明或无子项视为无内容。单条记录的来源指向该记录，coverage=1；界面不展示“直接子项覆盖数”。既有摘要保留，用户更新摘要后才生成新版本；不以测试中的模拟模型回答代表真实图片识别质量。

## 独立设置与工具时间输出（2026-11-03）

助手设置通过统一设置行进入 AI 模型、语音输入、联网搜索、自动总结、日记本和数据备份。模型子页只保存模型、思考和凭据，语音子页只保存语音配置与独立 Key；主设置只保存角色、称呼、风格与权限。子页等初始化完成后再建立表单，各自校验、显示保存结果并保护未保存草稿。Key 可显隐，读取状态仅显示已配置，不回填安全存储中的密钥。

语音页保留离线模型检查、下载、取消及错误重试；转写模式说明录音去向。App 装配独立试用控制器工厂，试用页新建并拥有实例，离开或切后台释放录音；识别结果不写聊天、不创建会话。测试使用注入的语音实现，不能据此声称真实人声识别通过。

软件设置与助手设置都进入 DataBackupPage，共用完整备份的范围说明、导出与导入恢复。恢复由装配层关闭旧助手和分析队列，完成后重新建立工作区；具体格式、事务及附件边界见[数据备份与恢复](../数据备份与恢复/总览.md)。

```text
业务查询 / 写回执 / 扩展工具 / 未知结果恢复
  → AssistantToolResultFormatter（仅成功 JSON）
    → 已知时刻字段：毫秒或含时区 ISO → ISO 8601 + 明确偏移
    → 条目 timeZone / timeZoneId 优先，子项继承；默认产品排期时区
    → 查询附 timeContext：本次时刻、今天、默认时区、日期和时长约定
  → AgentLoop 持久化结果 → 模型
```

日历日期、编号、版本、数量、秒/分钟时长不转换。材料/任务/目标索引、嵌套总结及撤销历史同样处理；错误和非 JSON 输出保留。数据库、原回执与业务日期过滤不修改。查询预算按格式化后的文本计算。无效条目时区使用 UTC 偏移，避免格式化令已成功操作变成失败；真实夏令时由 timezone 数据计算。
