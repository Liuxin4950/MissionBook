## 数据流

```text
新会话 / 对象入口 → 未持久化草稿（独立 draftKey）
首次有效发送 → 页面输入区 → Controller → 创建会话与关联对象 → 会话协作者 → agent_core
  → mission_book_context（时间与显式引用）
  → MemoryContextAssembler（五层记忆纯读装配）→ replaceContext（同来源只留最新一份）
  → 公开工具 schema → prepare / 校验 / 快照
  → 需要确认的写操作 → 用户确认 → 业务服务 → 仓储事务 → 保存回执
  ← 成功结果 → AssistantToolResultFormatter → 会话消息与引用
  ← 拒绝或可恢复错误 → 会话消息与引用

事实变化 → 持久总结队列 → AnalysisService.claim
  → 按 AnalysisScope 读取上下文 → 模型 → 版本匹配才发布
```

具体任务投影移到 application/missions/mission_projection.dart，domain 不输出助手展示 Map。模型及 JSON 协议字段仍在边界转换；内部用枚举消除魔法 scope 字符串。

助手 Markdown 在生成期间即按 GFM 显示，正文与思考共用渲染器。控制器仍按约 66 ms 合并活动快照；流式版本不挤占全局 AST 缓存，未变化的块复用节点及样式。完成内容使用有界 AST 缓存（最多 8 项、128 Ki 估算权重，超过 32 Ki 字符的单条不缓存）。正文和展开思考自然增加页面高度，不拥有独立的纵向滚动窗口；文字可选择并复制，回复按钮复制完整原始正文。

主聊天对已完成轮次中达到 4,000 字符的正文复用整篇 AST，并将顶层块切片直接交给外层聊天 ListView 按可见范围构建；首尾圆角、底色和整条回复复制入口保持连续。流式轮次仍在活动区域更新；单个超长段落、表格、展开过程和浮窗的整体布局成本仍需按设备样本测量，不能用限高窗口代替优化。
完成回答可包含 `missionbook-chart` 围栏块。AST 缓存只将该语言标记且不超过 4,096 字符的代码块提升为图表节点；解析器只接受 `bar` / `line`、最多 12 个数据点及受限标签、单位和数值，再由 Flutter Widget 绘制。无效 JSON 以可选择文本回退；模型输出的 HTML、脚本或任意绘图代码不会执行。流式阶段共用 Markdown 渲染器；结构块满足 JSON 校验后即可显示图表，未完成或无效内容按文本回退。

应用内助手快捷入口提供文字和语音：手机快捷模式圆按钮为 56dp，入口上方留 4dp 间距，保持至少 48dp 触控面积。输入区加号菜单只提供拍照、添加图片和添加文件；上下文面板承担手动压缩及实际用量查看。预算环点按和长按都打开同一个主题化图表面板，不以纯文本 Tooltip 显示整份统计；读屏语义仍包含预算和会话用量。预算、缓存率和异常状态使用全局颜色、字号与紧凑统计行。跨应用悬浮入口在助手设置中开启。应用内不再提供页面截图入口。

Android 系统悬浮入口由 `AssistantOverlayService` 承载，不持有 FlutterEngine 或业务数据库；用户显式启用后才显示。点“截屏提问”启动 `AssistantCaptureConsentActivity`，系统确认后由 `AssistantScreenCaptureService` 捕获一帧并停止投影；点“长截图提问”则保持投影，用户在原应用中滚动并逐次点击原生控制条采集，最多 12 屏，按相邻帧重叠区域拼接后再停止投影。两项都不默认高亮，控制条在采集帧时移除，不自动滚动且不申请无障碍权限；授权 Activity 收到截图服务的包内广播后打开 `MainActivity`，后者将缓存图片交给 `AppShell`。系统入口通过 `prepareExternalEntry` 等待正在进行的会话导航，接续当前会话或草稿；即使对象会话正在生成或等待确认也不强制切换到全局会话。`AssistantLauncher` 加入截图并通知页面刷新，已有聊天路由则回到该路由，关闭其上方的预览、设置或详情；没有聊天路由时新开一个。草稿接收后确认删除原生缓存。原生取消、失败、缓存回收及悬浮窗添加失败的状态处理见[平台资源](../平台资源/README.md#android-跨应用助手)。HyperOS 3 手机已验证单应用及整屏截图自动回到聊天；长截图、多屏拼接、冷进程与 HyperOS 4 仍待验收。

## 附件选择与截图交接

Android、Windows 和 Web 的聊天选择器支持批量选择。每条消息最多 12 个图片或文本附件，合计最多 24 MiB；单张发送副本保持最多 4 MiB，原图选择最多 20 MiB，超过发送大小时沿用用户确认压缩流程。文本大小、编码及合计字符限制保持由 `AssistantAttachment` 和输入区校验。批量处理按顺序读取，整批超限或处理失败时保留原草稿。自定义头像继续单选。图片草稿以 48dp 方形触控区显示 40dp 缩略图，不另占删除按钮和文件名宽度；点按打开预览，预览右上角提供移除操作，文件名在预览和读屏名称中保留。

截图加入草稿通过 `AssistantController.addCapturedAttachment` 通知已经打开的聊天页，页面本地附件修改同步到控制器。根 Navigator 持有实际聊天 Route，复用并恢复已被其他页面覆盖的聊天，不重复取得运行时会话。AppShell 在消费截图期间再次收到截图通知时排队再消费，确认成功交接后才向原生确认删除缓存。全局、对象、指定会话和新会话切换、删除和重命名由 `_AssistantSessions._navigate` 串行执行，并通过 `_changingConversation` 阻止切换期间发送。恢复对象引用或配置失败时关闭刚打开的运行时会话，退出时等待进行中的切换完成。

## 会话创建与提示词

点击新会话或首次进入某个对象的助手，只切换到空白草稿，不写 assistant_sessions；首条有效文字或附件发送时才创建持久会话。重复点击新会话不新增历史。全局和各对象的草稿按 draftKey 隔离；创建后页面切换到会话编号，语音气泡显式接续本轮消息的身份。删除持久会话会同时回收该会话编号下的文字与附件草稿；旧页面在删除完成后的延迟保存不得复活该编号，未删除会话的草稿继续保留。发送准备失败时如果用户已经输入新草稿，原内容进入该草稿身份下的未发送内容队列，可在输入区恢复；不覆盖新输入。附件选择固定原草稿身份，选择完成时若已切换会话，则加入原会话草稿并提示。对象已删除或不可读时显示关联失效提示，后续请求不继续使用旧对象引用。打开另一个持久会话时清除上一会话遗留的错误提示和本地日程暂态。

首条输入在预检或上下文准备阶段失败且未保存用户消息时，清理本次新建空壳。用户消息已经保存后即使模型失败，保留真实历史供重试和恢复。既有历史不批量删除。

任务详情、任务执行、目标详情和记录列表页使用应用内 `AssistantSurface` 提供快捷入口；记录页根据 mission / goal / node 来源绑定对应会话，助手输入区仍负责选择相册图片、相机拍摄或文字/语音。该入口仍是 MissionBook 窗口内的 Flutter overlay，不代表跨应用悬浮或系统截屏。

主提示词独立由 assistant_prompt.dart 组合：讨论和假设先回答，明确操作且参数齐全时走工具，关键歧义才询问；已给出的信息与授权不反复索取，实际工具权限仍由宿主执行。事实、用户声明、材料、模型评价与掌握分别处理。恢复历史时沿用当前提示词及用户角色设置，不改写历史消息。

## 偏好与失败恢复

角色名称首次使用默认“书祺”；已保存的自定义名称继续沿用，缺少名称字段的旧配置按当前默认名称读取，不改写已持久化配置。

角色头像由 [assistant_avatar.dart](../../../../lib/presentation/assistant/shared/assistant_avatar.dart) 的 `AssistantPersonaAvatar` 统一显示。默认 `spark` 选项展示 `assets/branding/shuqi-avatar.png`，设置页名称为“书祺”；书页和指南针仍显示各自图标。中央入口按可用宽高的较短边等比显示头像，手机入口为 56dp，平板侧栏受限时保持正圆。设置摘要、角色选择和语音气泡标题复用同一组件；录音、生成及打开中的状态继续由入口显示对应状态图标或进度。

“角色与风格”位于助手设置首项，折叠摘要用 48dp 头像预览当前名称与风格；“操作权限”复用设置卡片与折叠行，默认收起并显示当前模式，展开后选择，随底部保存提交。角色的名称、称呼及定位/表达字段按内容宽度和字号自适应排列。头像选择复用 `AppSelectionOption`，手机最多两列；选中使用浅绿底及勾选。输入正文沿用 `bodyLarge`（14），说明与选项沿用 12 号文字，区块标题为 14。

自定义头像复用跨平台 `pickAssistantAttachment(image: true)` 选择图片，由 [assistant_image.dart](../../../../lib/application/assistant/assistant_image.dart) 的 `prepareAssistantAvatar` 校验像素、处理方向并居中裁成 192×192 PNG。缩略图通过 `AssistantPersona.customAvatarBase64` 随角色设置原子保存到现有设备安全存储；预览、选择取消及处理失败均不写入配置。选择内置头像或恢复默认会清除该字段，保存后更新中央入口、设置摘要及气泡标题。旧配置缺少头像字段时使用内置选择；损坏头像字段单独回退，其他有效角色字段继续读取。头像组件只在图片内容改变时重建 `MemoryImage`，解码失败时回退内置图标。角色提示词组合名称、有效定位正文、有效回答风格正文及称呼字段。角色定位与回答风格各有六种预设，支持最多 2000 字符的自定义正文；选用预设时清除相应自定义覆盖。customRole 与 customReplyStyle 随现有角色 JSON 保存，旧配置缺字段沿用原预设，损坏的自定义字段分别回退。

自动总结范围为 mission、node、goal；memory 为独立的后台提取范围，可由设置开关关闭；关闭后不排新抽取，已有记忆仍检索并注入。记录没有独立 AI 摘要。偏好读取失败时保留最近成功快照或初始默认快照，显示错误和重试入口；实际自动取任务暂停，避免在不知道用户设置时发送数据。

角色与风格区以两条统一设置行打开编辑页，预填当前正文，可选择预设继续改写。顶部感叹号打开写法参考，示例和 AI 提示词分别可复制；编辑完成交回草稿，由设置页统一保存，离开时保留丢弃确认。实际模型请求使用有效正文，已有和重开会话均生效。

## 摘要来源与层级

```text
任务执行中的记录 / 照片
  → RecordsPage(missionId) 保存 Record + 任务 Evidence 内容快照
  → END 事件提交后排队 mission 总结
    → 任务事实 + 有效材料快照 → 任务评价
      → 节点总结：直接任务总结 + 子节点总结
        → 目标总结：直接任务总结 + 根节点总结
```

执行中的材料保存只写业务事实，不启动任务 AI 总结；首次自动任务总结以 END 为门槛。任务结束后的材料补交、修正和任务事实更改会使任务总结重新排队。直接关联目标或节点的原始记录仍可在记录列表浏览，但不进入节点/目标 AI 摘要；分层摘要只消费任务与子节点的摘要，避免把原始记录重复放入上下文。助手设置中只配置任务、节点和目标三层自动总结。

显式手动请求表达本次意图，可在偏好读取失败时处理。领取任务时自动范围为空仍允许 manual 任务，不能把读设置失败写成用户关闭所有开关。设置重读成功后恢复正常范围；主会话占用模型时后台队列暂停取下一项。

## 模型请求的生命周期

后台分析、主会话工具内的按需分析、连接检查分别登记取消令牌。主会话开始立即抢占后台分析，停止主会话取消其按需分析，关闭控制器取消所有在途网关请求。控制器直接通知状态变化，不再依赖 200ms 轮询。

分析默认 60 秒、连接检查 30 秒；取消等待覆盖图片读取及模型响应，结果返回后再次校验令牌。迟到成功不能返回，迟到异常有接收端；finally 释放超时定时器和注册表连接。后台抢占作为 AnalysisInterrupted 交回持久队列，超时是失败，可以按队列策略重试。分析仍只携带本次来源，不附带主会话、记忆或工具。

显式配置独立摘要模型时，切换主模型保留摘要选择；默认摘要才跟随主模型。文字分析使用独立摘要模型，图片分析使用主模型能力。按需分析输出为 `min(profile.maxOutputTokens, 2000)`，连接检查为 `min(profile.maxOutputTokens, 64)`；请求前估算文本、图片、输出预留与 headroom，超预算直接拒绝。分析和连接检查只接受 completed、无工具调用且非空正文，截断或空响应不给成功回执。模型预算与生命周期专项已通过，真实供应商对最终实现的复验未执行。

总结队列保留 10 秒轮询：analysis_triggers.dart 在 SQLite 写事务内排待办，失败任务还受 available_at 控制；只监听页面通知会遗漏这些入口。轮询只领取满足条件的任务，不把空轮询当作模型请求。

## 流式输出与重建边界

模型逐 token 推送时，`AssistantController.liveActivity` 只承载当前请求的正文、思考与请求身份；只有正在生成的轮次订阅它，输入区、会话列表和已完成消息只在消息、工具、会话或运行状态变化时重建。`_refreshSnapshot` 先比较 `AgentSession.transcriptLength` 与 `lastTranscriptMessageId`；只有消息数量或最后一条编号变化时才读取新的不可变 `transcript`，纯文本增量不复制整条历史。控制器随后直接持有该不可变快照，不再在每次公开读取时二次包装。

当前轮次使用稳定的请求序号及连续块分段身份，实时内容与正式消息共用轮次组件。思考与过程的手动展开状态通过 PageStorage 保留；展开内容暂停主聊天跟随，重新滚回底部后恢复。页面按草稿身份记录切换前的阅读位置。生成正文和思考使用相同 Markdown 渲染器，主题样式和未变化的节点可复用。

## 回到前台与输入区

`App.didChangeAppLifecycleState` 在 hidden/paused 通知 `AssistantController.setForeground(false)`，resumed 通知 true；切后台保留健康模型请求，语音单独取消。返回前台后，在当前运行期间每隔 `resumeGrace` 对比消息、模型尝试、正文和思考快照；有进展、待确认或工具执行时继续观察，没有进展则请求取消并提供“继续本轮”。重复前台通知不会撤销仍有效的检查，新发送、继续和关闭会取消旧检查，运行结束释放定时器。已开始的业务工具仍等待真实结果，不能通过清空忙碌状态冒充完成。

页面始终响应共享语音控制器的忙碌变化，只有当前页面发起的录音才回填文字；系统后台取消完成后重新计算发送按钮。没有已持久会话时也发布状态刷新，避免准备失败后保留旧按钮状态。消息生成状态只显示进度，停止入口集中在输入区；无输入区的语音浮窗保留自己的停止入口。

进入文字聊天只连接共享语音控制器，不预热离线识别模型；用户首次录音时才按配置准备后端。控制器的 `close()` 会取消录音并等待语音服务释放本地后端；同步 `dispose()` 只启动同一关闭流程，调用方可选用 `close()` 等待完成。聊天图片按 data URL 复用 `MemoryImage`，进程内缓存限制为最多 24 项和 12 MiB；超限单张图片可显示但不进入缓存。

总结读取子项时先批量查询子项事实、任务和最近总结，再按 SQLite 参数数分块；500 个直接子项的隔离审计从 1,505 次 SELECT 降至 7 次。此数字描述固定审计夹具的查询数，不代表所有目标形状或设备耗时。会话日志计数由读取所有序号改为 `MAX(sequence)+1` 聚合，避免打开时为计数额外传回整列数据。

## 思考程度

输入区快捷菜单和设置页共用 `ReasoningEffort` 的 off、low、high、max，显示文字由 `assistant_reasoning_display.dart` 提供。`AssistantSettings.reasoningEfforts` 按模型配置编号保存选择，`SecureAssistantSettingsStore` 写入设备安全存储中的 `assistant_reasoning_efforts`，不改任务数据库或凭据内容。

```text
输入区选择 / 设置页保存
  → AssistantController.setReasoningEffort → 配置协作者
  → AssistantSettingsStore.saveReasoningEffort → 重读偏好
  → 当前 AgentSession.configureGeneration(thinking: effort)
  → AgentLoop → ModelRequest.reasoningEffort → 现有协议编码器

新建 / 重开 / 切换模型 → 应用该模型已保存的思考偏好
```

运行中禁用更改。没有保存偏好时保留现有模型或会话默认值；已有会话配置不被无条件重置。主会话的生成设置沿用 agent_core 日志持久化，不通过新增消息模拟参数。服务实际接受的档位及效果依供应商而定，界面不将本地保存成功当作供应商能力验收。

快捷菜单通过 MenuAnchor 和 MenuItemButton 竖排四档，沿用共享选项外观、原保存入口及原生键盘、焦点和关闭行为；默认内容宽度 128，外层留白 4，单项最小触控高度 48，按字号和视口约束调整。

### 思考与工具过程

本地原项目 `/root/Working/deepseek-harness-master` 的 `packages/client/ui-chat/src/client/chat/ReasoningRow.tsx`、`ReasoningContent.tsx` 与 `ChatGroupSeat.tsx` 作为展示参考：思考使用次级文字的一行预览，完整内容按需展开；同一轮的思考与工具归入过程，最终回答独立。本项目沿用自己的颜色、字号和最小触控规范。

`assistantTurnParts` 按 AssistantMessage 和内容块原顺序引用位置；`assistantTurnSections` 仅合并同一请求中连续的过程块。主聊天和浮窗共用 `AssistantTurnContent`，按请求依次呈现思考、工具、中间说明和回答，不把后续请求的过程提前到已有回答之前。生成期间过程可展开，待确认、失败、未知操作自动展开；用户手动展开思考后，结束不会自动隐藏该过程。过程和思考均不设内部纵向视口。

`request_failed` 保存当前正文请求的部分正文、部分思考及重试信息；SessionState 将它投影为 `InterruptedModelAttempt`，主聊天与浮窗按所属用户消息及请求位置显示“本次输出未完成”。该列表独立于 transcript/contextMessages，重开会话可回看，但不会作为已完成消息回传模型。结果未知的工具继续按真实回执核对，不能借重试重放写入。

浮窗的单项工具入口通过 initialOperationCallId 打开主对话，自动展开所属过程及该项结果，避免新增分组后再次逐层展开；一般打开对话仍使用默认收起规则。

`AssistantThinking` 默认收起，使用无卡片边框的一行预览和 12 号文字；完整内容通过紧凑 Markdown 展开，标题也保持次级层级。只有思考没有正文的消息也保留，签名不呈现，不为未返回的思考补写内容。

```text
用户输入 → AssistantMessage.content 原顺序
  → ThinkingBlock → 思考行
  → ToolCallBlock → 真实操作状态与回执
  → 下一条 AssistantMessage 的 ThinkingBlock → 下一段思考行
  → 最终 TextBlock → 过程外的回答正文
```

`SessionActivity.requestSerial` 在每次正文模型尝试（包括工具后的再次请求、重试）递增，`modelRequestRunning` 从请求开始持续到完整消息接收或失败，`turnUserMessageId` 将快照绑定本次用户输入，恢复时沿用原用户消息。只有当前运行且当前模型请求在途才展示流尾，完整消息接收后立即转为原消息块；失败或取消后的未完成内容由独立展示投影保留；不再按字符串内容相等判重，因此相同文字的后续思考不会被此前请求吞掉。这些是内存展示快照，不新增持久化状态；原消息、工具结果、签名和模型回传保持不变。

## 工具与生命周期约束

`setRecordOwnership` 在仓储写锁内检查来源记录，不存在或已删除时，在写入前以带记录编号的参数错误拒绝；工具返回 `invalid_input`，模型可以继续处理本轮。真正执行异常仍保留 `outcome_unknown`，按已提交的操作回执核对，不能把所有 `StateError` 都当成未执行。旧会话已保存的未知结果不会因修复自动改写，无可确认回执时仍保留核对状态。

普通写操作已完成或已取消后，AssistantOperationCard 默认呈现单行展开摘要：18 状态图标、12 字号的操作/对象名称和状态，最小触控高度 48。整行展开后展示原输入摘要、历史补记明细、对象入口和返回数据，去除默认铺开的两个独立详情标题及重复底部留白。待确认、运行、失败和结果未知仍保留原操作内容及确认、编辑、取消和核对入口；查询结果与专用排期卡继续使用原组件。返回数据保留非对象 JSON 和纯文本的原文回退；长 JSON 初始展示节选，可展开完整数据。只读查询确认显示完整参数。工具详情的展开状态可按调用编号保留。这些展示不修改操作状态、执行或回执。

工具的读写属性由实际注册的 `AgentTool.readOnly` 提供，准备和权限判断共用该属性；注册时拒绝重名。记忆保存由事务做主题消解并返回 NOOP / UPDATE / ADD / BLOCK 四态与 reason，每次实际变更追加 memory_versions。同主题正文不同时：原条目未被用户编辑则保留原事实、新说法以未验证条目并存并带 keptId，原条目已由用户编辑则保持原样；用户显式更正带 id 与 14 字段快照才更新原条目。墓碑按条目或同范围相同内容匹配，不能因来源相同阻止无关内容。后台提取只接收带用户原文引用的陈述、偏好、习惯并写 stated，不写未验证观察。五层语义、主题别名、评分与预算见[长期记忆](长期记忆.md)。保存记忆时须显式登记同义别名；装配器与检索查别名，不能据单次真实 B 的上下文命中宣称通用同义消解。通用 save 派生同步、所有 certainty 的 basis 门控与 usage 召回/注入记录已有代码和定向测试。旧摘要回放、连续安全摘要，以及 getMemory、saveMemory、manageMemory、getOperation 的旧参数、结果与恢复通知失效已完成本机回归；真实模型和 Android 模拟器结果及能力边界见[收尾复验](../../../审查/2026-11-13-长期记忆本机复验.md#接续收尾)。原始聊天记录与回执仍可回看。

`getMemory` 按相关性、确认程度、目标亲和与时间衰减排序，将本页编号、对象和版本作为固定选择保存，默认20条，可指定最多100条；`manageMemory` 当前支持批量忘记，执行时校验所属会话、持久化用户消息和全部对象快照，变动时整批零写入。回执默认展示20条，`getOperation` 支持分页读取记忆清理和历史补记回执。选择快照和回执保存在现有操作回执表，不使用正式数据做测试。自然语言授权意图目前依赖主模型遵循提示词；来源消息存在本身不能证明用户确已授权。记忆保存、合并与恢复尚未合入 `manageMemory`，其他业务工具也尚未接入统一结果和回执查询。

`completeHistory` 固定目标及日期范围内的候选与跳过任务，事务内重读整个范围，任何范围或对象变化均回滚；回执分别列出已取消、已结束、强制材料及可选材料等跳过原因。零候选仍保存统计回执；模型默认收到前20项跳过明细，可用 `getOperation` 读取余下页面。补记依据要能关联本会话用户原话，但原话匹配本身不证明语义授权。

`planMissions` 接受最多100项，新建与改期共用整份事务；固定时间的一批冲突候选由一次查询读取，计划内冲突另带对方条目编号。冲突时不改变任务或排期，保存阻塞回执及完整冲突明细；成功和阻塞回执默认只返回20项，可通过 `getOperation` 分页。校验或准备失败的错误消息带具体 itemId 和 missionId，指出是哪一条。批量改期准备按编号批量装配原任务。单条旧工具与重做尚未收敛到该入口，也尚未提供可用时段候选。

工具目录、确认及执行使用同一组名称，不再注册隐藏别名；目标、任务、日程统一使用 getGoal / getMission / getSchedule 与同一读取契约，扩展能力不替换查询工具。权限只使用 AssistantPermissionMode 三档配置，删除旧布尔开关和读取适配；首装没有配置时沿用当前完整权限策略，但已保存的非空损坏值必须显式报错，不得静默落到完整权限。凭据状态按模型分别保存，当前模型状态由配置派生。操作回执需匹配命令类别与目标，材料回执还核对来源记录。模型配置只接受 credentialKey；摘要会话使用当前消息引用格式，旧格式报错并保留原数据。

页面 state 统一释放文本、滚动和语音对象；控制器关闭会话订阅、事件流及模型资源。协作者共享所属对象状态，不创建重复 ChangeNotifier 或新的数据库连接。错误映射保留短中文业务原因，其他错误显示相应操作的重试提示。


## 2026-11-03 实际使用修复

会话写租约仍为 30 秒。`DriftSessionStore` 追加日志时在写事务内检查 writerToken；后台暂停定时器后，原持有者若未被接管可以继续写入并续租。续租也以 token 为条件，不因时间过期永久锁死；另一窗口接管后旧 token 仍被拒绝。`AgentSession.needsReopen` 表明存储失败，下一次发送先关闭旧句柄并重读持久日志；未知工具结果仍必须核对，不能自动重放写入。

助手新增 `manageMissions`，与页面共用 [任务维护入口](../任务与材料/README.md#任务维护与撤销历史)。action 为 cancel/delete/reset，支持 missionIds、goalId、beforeDate、phase；没有范围时必须显式 all=true。准备时固定整个范围、完整事实及指纹；确认遵循现有三档权限，提交时事务重读范围，变化则整批拒绝。回执按 20 项返回，`getOperation` 可分页；结果未知按同一操作编号核对回执。缺失任务或 reset 遇到未结束任务时，错误列出具体 missionId（必要时带标题），不只报告批次失败；cancel 的跳过项继续由回执 skippedIds 表达。删除是物理删除，不进入回收站。自然语言授权仍依赖模型遵循用户意图，不能把 all 字段本身当作授权证明。

`getGoal` 默认只返回当前层的直接子节点和直接任务，指定 `node` 逐层深入，`mission: '*'` 才分页读取整个子树。`getMission` 的列表项返回阶段、时间安排、材料要求和摘要；指定任务只返回方案概览、材料数量与 `details` 入口，不再内联执行历史、失败原因和材料索引，需要时按 `details` 调用 `getMissionContent` / `getMissionRecords` / `getMaterial`。筛选链先按日期、目标、节点和标题取候选编号，再批量装配事实并派生完整 `MissionDetail.phase`；summaryOnly 返回整个筛选范围的精确 total 和 countsByPhase，items 固定为空。普通分页的本页 items 与全量统计分开表达，nextOffset 继续读取。读取不再累计字符预算，单次查询由页大小和分段上限约束，上下文接近预算时由自动压缩处理。`getMissionRecords(section: revoked)` 与 `getMaterial` 可以追溯已撤销的历史材料，结果标识不参与当前阶段或评价。

记忆 basis 须逐字引用本轮最后一条用户消息的连续原文，不含此前对话，保留换行和标点，不能拼接或改写；content 可概括。本轮将 AI save 的强制依据扩大到所有 certainty（stated、inferred、unverified），工作树已有校验调整，最终测试待回填；撤回旧的“仅 stated 强制”说明。observation 固定未验证，带 id 的 AI 更正必须 stated。失败提示区分记忆保存与执行报告。saveMemory 一次一条；批量清理使用 manageMemory 的 selectionId/itemId，手动编辑与后台反思另有入口。

聊天在 Android 和 Web 的附件菜单显示拍照，复用 PhotoCapturePanel 的预览、重拍与相机生命周期；拍照失败时可改选文件。照片确认后进入原消息草稿，不直接发送。拍照和系统选图共用超限压缩确认：原图最多 20 MiB，超过发送上限 4 MiB 时用户可选压缩副本，保持原文件；CPU 压缩在独立任务运行，检查像素上限、纠正方向、按尺寸缩小并转 JPEG。多帧图压缩只取第一帧。仍保留每条 12 个附件、合计 24 MiB 以及发送前预览和取消。文件读取、压缩和总量错误不会清空草稿。

记录详情只展示原始文字和附件，不单独调用模型。关联任务时提交快照；任务总结按快照分析文字与图片，不读取记录之后的修改。直接记录归属仍用于记录筛选和列表展示，不作为 AI 总结来源。

## 独立设置与工具时间输出（2026-11-03）

助手设置通过统一设置行进入 AI 模型、语音输入、联网搜索、自动总结、AI 日记本和数据备份。“自动总结”页的“自动整理对话记忆”即时独立保存，任务/节点/目标开关仍点“保存设置”；关闭新抽取不关闭已有记忆使用。日记本的“目标范围（含全局记忆）”是浏览筛选，手动新增目前为全局，更正保留原 goalId，不因筛选而改绑。聊天预算圆环打开“上下文与用量 → 压缩早期对话”，忘记与备份的完整待验收路径见[长期记忆](长期记忆.md#用户体验与待验收路径)。模型子页只保存模型、思考和凭据，语音子页只保存语音配置与独立 Key；主设置只保存角色、称呼、风格与权限。子页等初始化完成后再建立表单，各自校验、显示保存结果并保护未保存草稿。Key 可显隐，读取状态仅显示已配置，不回填安全存储中的密钥。联网搜索说明明确搜索词会发送给 Tavily、网页读取请求会发送给目标网站；该告知不改变工具权限或现有网络限制。

语音页保留离线模型检查、下载、取消及错误重试；转写模式说明录音去向。App 装配独立试用控制器工厂，试用页新建并拥有实例，离开或切后台释放录音；识别结果不写聊天、不创建会话。测试使用注入的语音实现，不能据此声称真实人声识别通过。

软件设置与助手设置都进入 DataBackupPage，共用完整备份的范围说明、导出与导入恢复。恢复由装配层关闭旧助手和分析队列，完成后重新建立工作区；具体格式、事务及附件边界见[数据备份与恢复](../数据备份与恢复/README.md)。

```text
业务查询 / 写回执 / 扩展工具 / 未知结果恢复
  → AssistantToolResultFormatter（仅成功 JSON）
    → 已知时刻字段：毫秒或含时区 ISO → ISO 8601 + 明确偏移
    → 条目 timeZone / timeZoneId 优先，子项继承；默认产品排期时区
    → 查询附 timeContext：本次时刻、今天、默认时区、日期和时长约定

```

日历日期、编号、版本、数量、秒/分钟时长不转换。材料/任务/目标索引、嵌套总结及撤销历史同样处理；错误和非 JSON 输出保留。数据库、原回执与业务日期过滤不修改。读取量由分页、分段和自动压缩约束，不累计字符预算。无效条目时区使用 UTC 偏移，避免格式化令已成功操作变成失败；真实夏令时由 timezone 数据计算。


## 上下文压缩与 token 预算

[ContextCompactor](../../../../packages/agent_core/lib/src/context/context_compactor.dart) 和 [TokenEstimator](../../../../packages/agent_core/lib/src/context/token_estimator.dart) 负责本次请求预算。输入估算按实际协议中的系统提示、消息和工具定义计算，排除输出额度等请求控制参数；历史回答和工具结果在下一次请求中属于输入。

```text
上下文总窗口 − 本次输出预留 − 安全余量 → 可用输入预算
实际请求输入估算 ≥ 可用输入预算 × triggerRatio → 压缩旧历史
摘要 + 保留消息 + 系统提示 + 工具定义 → 重新估算并校验可用输入预算
```

自动与手动压缩均使用当前会话的输出额度和请求设置，摘要分块另按摘要模型的输出额度预留空间。输入区圆环按可用输入预算计算比例，提示分别显示输入估算、可用输入、输出预留与总窗口；默认按可用输入的 80% 触发自动压缩。轻触圆环打开上下文与用量面板，除预算外还展示会话累计、缓存命中率、最近一次正文请求和手动压缩入口。

服务端实际用量通过 `TokenUsage` 保存：`inputTokens` 是包含缓存读写在内的总输入，`cachedInputTokens`、`cacheWriteTokens` 和 `reasoningTokens` 分别是输入/输出中的子集；`cacheReported`、`reasoningReported` 区分“供应商报告了 0”和“供应商没有报告”，不能把未知当成 0。Chat Completions 解析 `prompt_cache_hit_tokens`、`prompt_tokens_details.cached_tokens` 和 `completion_tokens_details.reasoning_tokens`；Messages 解析 `cache_read_input_tokens`、`cache_creation_input_tokens` 及可选的输出推理桶。

`SessionState` 回放日志中的 `usage_reported` 形成 `SessionUsage`：全部尝试（含摘要与重试）累计总用量，正文请求单独累计；只有全部正文样本都报告缓存时才标记 `cacheComplete`。命中率按 `cachedInputTokens / inputTokens` 计算；正文样本不全时仍可显示带“仅已报告请求”标注的样本值。重开、导入和分支通过同一日志回放恢复，不新增数据库表或迁移。

输入区圆环仍用本地估算决定压缩与预算；提示另外显示会话累计、正文缓存命中率以及最近一次正文请求的供应商输入和缓存命中。估算不等于精确 tokenizer 或账单；原始会话日志、工具完整组和供应商原始用量保留。DeepSeek 的前缀缓存是自动的，关键优化是系统提示、工具 schema 和历史消息保持追加式稳定，不需要新增 cache key。[真实缓存 E2E](../../../../packages/agent_core/test/deepseek_cache_e2e_test.dart) 使用环境变量门控验证每次后续请求都有缓存命中；[请求前缀测试](../../../../packages/agent_core/test/model_streaming_test.dart) 在本地锁定工具说明不重排、历史只追加。

节点菜单打开助手时临时选中该节点；取消快捷菜单会清除临时选择，随后普通入口按当前页面的任务或目标上下文打开。
