## 数据流

```text
新会话 / 对象入口 → 未持久化草稿（独立 draftKey）
首次有效发送 → 页面输入区 → Controller → 创建会话与关联对象 → 会话协作者 → agent_core
  → 公开工具 schema → prepare / 校验 / 快照
  → 需要确认的写操作 → 用户确认 → 业务服务 → 仓储事务 → 保存回执
  ← 成功结果、拒绝或可恢复错误 → 会话消息与引用

事实变化 → 持久总结队列 → AnalysisService.claim
  → 按 AnalysisScope 读取上下文 → 模型 → 版本匹配才发布
```

具体任务投影移到 application/missions/mission_projection.dart，domain 不输出助手展示 Map。模型及 JSON 协议字段仍在边界转换；内部用枚举消除魔法 scope 字符串。

## 会话创建与提示词

点击新会话或首次进入某个对象的助手，只切换到空白草稿，不写 assistant_sessions；首条有效文字或附件发送时才创建持久会话。重复点击新会话不新增历史。全局和各对象的草稿按 draftKey 隔离；创建后页面切换到会话编号，语音气泡显式接续本轮消息的身份。

首条输入在预检或上下文准备阶段失败且未保存用户消息时，清理本次新建空壳。用户消息已经保存后即使模型失败，保留真实历史供重试和恢复。既有历史不批量删除。

主提示词独立由 assistant_prompt.dart 组合：讨论和假设先回答，明确操作且参数齐全时走工具，关键歧义才询问；已给出的信息与授权不反复索取，实际工具权限仍由宿主执行。事实、用户声明、材料、模型评价与掌握分别处理。恢复历史时沿用当前提示词及用户角色设置，不改写历史消息。

## 偏好与失败恢复

自动总结范围为 record、mission、node、goal；memory 为独立的后台提取范围。偏好读取失败时保留最近成功快照或初始默认快照，显示错误和重试入口；实际自动取任务暂停，避免在不知道用户设置时发送数据。

显式手动请求表达本次意图，可在偏好读取失败时处理。领取任务时自动范围为空仍允许 manual 任务，不能把读设置失败写成用户关闭所有开关。设置重读成功后恢复正常范围；主会话占用模型时后台队列暂停取下一项。

## 模型请求的生命周期

后台分析、主会话工具内的按需分析、连接检查分别登记取消令牌。主会话开始立即抢占后台分析，停止主会话取消其按需分析，关闭控制器取消所有在途网关请求。控制器直接通知状态变化，不再依赖 200ms 轮询。

分析默认 60 秒、连接检查 30 秒；取消等待覆盖图片读取及模型响应，结果返回后再次校验令牌。迟到成功不能返回，迟到异常有接收端；finally 释放超时定时器和注册表连接。后台抢占作为 AnalysisInterrupted 交回持久队列，超时是失败，可以按队列策略重试。分析仍只携带本次来源，不附带主会话、记忆或工具。

总结队列保留 10 秒轮询：analysis_triggers.dart 在 SQLite 写事务内排待办，失败任务还受 available_at 控制；只监听页面通知会遗漏这些入口。轮询只领取满足条件的任务，不把空轮询当作模型请求。

## 工具与生命周期约束

工具的读写属性由实际注册的 `AgentTool.readOnly` 提供，准备和权限判断共用该属性；注册时拒绝重名。记忆保存由事务根据实际写入、去重或保护拦截生成回执，并将同一结果用于幂等重试及操作恢复。同主题内容冲突时保留原有事实，新条目作为未验证观察，不进入核心记忆；墓碑按条目或同范围相同内容匹配，不能因来源相同阻止无关内容。后台提取只接收带用户原文引用的陈述、偏好和约束。

`getMemory` 将本页编号、对象和版本作为固定选择保存，默认20条，可指定最多100条；`manageMemory` 当前支持批量忘记，执行时校验所属会话、持久化用户消息和全部对象快照，变动时整批零写入。回执默认展示20条，`getOperation` 支持分页读取记忆清理和历史补记回执。选择快照和回执保存在现有操作回执表，不使用正式数据做测试。自然语言授权意图目前依赖主模型遵循提示词；来源消息存在本身不能证明用户确已授权。记忆保存、合并与恢复尚未合入 `manageMemory`，其他业务工具也尚未接入统一结果和回执查询。

`completeHistory` 固定目标及日期范围内的候选与跳过任务，事务内重读整个范围，任何范围或对象变化均回滚；回执分别列出已取消、已结束、强制材料及可选材料等跳过原因。零候选仍保存统计回执；模型默认收到前20项跳过明细，可用 `getOperation` 读取余下页面。补记依据要能关联本会话用户原话，但原话匹配本身不证明语义授权。

`planMissions` 接受最多100项，新建与改期共用整份事务；固定时间的一批冲突候选由一次查询读取，计划内冲突另带对方条目编号。冲突时不改变任务或排期，保存阻塞回执及完整冲突明细；成功和阻塞回执默认只返回20项，可通过 `getOperation` 分页。批量改期准备按编号批量装配原任务。单条旧工具与重做尚未收敛到该入口，也尚未提供可用时段候选。

工具目录、确认及执行使用同一组名称，不再注册隐藏别名；目标、任务、日程统一使用 getGoal / getMission / getSchedule 与同一读取契约，扩展能力不替换查询工具。权限只使用 AssistantPermissionMode 三档配置，删除旧布尔开关和读取适配；凭据状态按模型分别保存，当前模型状态由配置派生。操作回执需匹配命令类别与目标，材料回执还核对来源记录。模型配置只接受 credentialKey；摘要会话使用当前消息引用格式，旧格式报错并保留原数据。

页面 state 统一释放文本、滚动和语音对象；控制器关闭会话订阅、事件流及模型资源。协作者共享所属对象状态，不创建重复 ChangeNotifier 或新的数据库连接。错误映射保留短中文业务原因，其他错误显示相应操作的重试提示。
