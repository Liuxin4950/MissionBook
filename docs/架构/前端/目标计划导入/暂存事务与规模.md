# 暂存事务与规模

> 目标包导入如何用独立暂存库、流式解析和一次原子事务支撑万级任务，以及回执去重、复核门槛、取消与恢复。代码依据 [goal_import_database.dart](../../../../lib/data/goal_import/goal_import_database.dart)、[goal_package_import_service.dart](../../../../lib/application/goals/goal_package_import_service.dart)、[drift_goal_package_repository.dart](../../../../lib/data/repositories/drift_goal_package_repository.dart)。协议字段见[协议与校验](协议与校验.md)。

## 独立暂存库

`GoalImportDatabase` 是与正式业务库分离的持久暂存库（`mission_book_goal_import`，schemaVersion 1），没有今天页或执行调度的读入口。原生落在应用支持目录，Web 用 sqlite3 WASM + drift worker；若浏览器只能 inMemory 暂存则直接拒绝（要求允许网站存储）。建库设 `auto_vacuum=FULL`、`foreign_keys=ON`，并按 `GoalImportLimits.stageBytes / page_size` 设 `max_page_count` 限制体积。

| 表 | 结构要点 |
| --- | --- |
| `import_job` | `singleton=1` 单作业；`id`、`goal_id`、`state`、`root_json`、`summary_json` |
| `import_entry` | `kind∈{NODE,MISSION}`、`source_index`、`parent_index`、`order_index`、`entry_key`、`id`、`schedule_id`、`plan_id`、`raw_json`、`resolved_json`；主键 `(kind,source_index)`，唯一 `(kind,entry_key)` |

索引 `import_entry_parent(kind,parent_index,order_index)` 支撑树遍历。`entries` 分页限 1–100 条，并用窗口累计 `raw_json+resolved_json` 字节，超过 `batchBytes`（1 MiB）即止（至少返回一条），避免单页装配过大。

## 作业状态机

```text
begin（READING，单作业；已有草稿报 JOB_EXISTS）
  → append（仅 READING；批量插入，UNIQUE 冲突 → DUPLICATE_KEY）
  → setRoot（READING → VALIDATING，写 root_json）
  → resolveBatch（仅 VALIDATING，写任务 resolved_json）
  → seal（VALIDATING → READY，写 summary_json）
  → assertReady（校验 jobId + READY + payloadHash，失效报 JOB_CHANGED）
  → discard（删除 entry 与 job）
```

`pending` 返回当前作业（jobId/goalId/state/root/summary）。`_require` 对缺失作业报 `JOB_CHANGED`、对状态不符报 `JOB_SEALED`（封存后不能再改暂存）。

## 流式解析

`GoalPackageParser` 按输入块处理 JSON，只保留当前一条节点/任务，不建立整包 AST：`nodes`/`children`/`missions` 是流式数组，逐条经 `onNode`/`onMission` 交暂存层，根对象只留空数组标记。节点用 `sourceIndex/parentIndex/orderIndex` 表达树与同级顺序，任务用 `sourceIndex` 保留顺序。解析期强制[协议与校验](协议与校验.md)的字段集合与规模上限（节点 500/12 层、任务 10000、JSON 64 层/1000000 值、步骤 100000、单任务 256 KiB）。

服务层 `prepare` 以 65536 字节块流读 `GoalImportSource`，每块让出执行权（`Future.delayed(Duration.zero)`），首块拒绝 BOM；`flush` 按 ≤100 条批量 `append`。随后 `validateRoot` 定大纲/目标包，分页 `validateNode`（重复键 `DUPLICATE_NODE_KEY`），用 `canonicalJson`（键排序、保留数组顺序与原始字符串）+ sha256 计算 `payloadHash` 与 `contentHash`（后者排除 `packageId`）。目标包再分页 `resolveMission` + `creation` 校验并 `resolveBatch`，最后 `seal` 成 `GoalImportPreview`。

## 回执与内容去重

| 入口 | 键 | 行为 |
| --- | --- | --- |
| `receipt` | `schemaName + packageId` | 无回执 → null；`payloadSha256` 不符 → `PACKAGE_ID_CONFLICT`；相符 → `alreadyImported` 结果 |
| `duplicateContent` | `schemaName + contentSha256` | 返回同内容已有 `goalId`，供预览提示重复 |

大纲的 `packageId` 取 `jobId`，目标包取根 `packageId`。回执持久化解决重开文件与响应丢失后的重复创建。

## 原子导入事务

`importPackage` 经 `AppDatabase.transaction` 进入 `_importOnce`，BEGIN 短暂竞争由 `AppDatabase` 统一恢复，不重放已运行导入：

```text
database.transaction
  → 写锁（UPDATE missions SET id=id WHERE 0）
  → 重查 receipt（已导入直接返回，幂等）
  → stage.assertReady + pending.goalId/root 与预览一致（否则 PREVIEW_STALE）
  → validateRoot → _review（当前时钟门槛）
  → 插入 Goal（ACTIVE）
  → 分页节点（≤100）：校验关系/身份/顺序 → batch insertAll goalNodes
  → 分页任务（≤100）：重 resolveMission 与暂存 resolved 比对（PREVIEW_STALE）
      → batch insertAll missions / executionPlans / missionScheduleRevisions
  → 节点/任务总数必须与预览一致
  → 最终 _review（checkConflicts=false，按提交时刻重查截止/自动开始）
  → 插入 ImportReceipt（schema/packageId/version=1/payloadSha256/contentSha256/goalId/计数）
```

创建时间保持同一 `_now()` 值。提交成功后服务回调 `onCommitted`（刷新目标与任务页面）并 `discard` 暂存；这两步异常被吞掉，不把已提交事实变成重新创建。

## 复核门槛（_review）

`review` 与最终提交各按当前时钟检查；选项来自 `GoalImportOptions`（默认全 false）。

| 情形 | 错误码 | 放行选项 |
| --- | --- | --- |
| 强制材料截止已过 | `INVALID_DEADLINE` | 无（须调整重新预览） |
| FIXED 落在当前计划时段内 | `DUE_AUTO_START` | `allowDueAutoStart` |
| FIXED 已错过计划时段 / 自选日期已过 | `PAST_SCHEDULE` | `keepPastSchedules` |
| 包内固定计划重叠 | `SCHEDULE_CONFLICT` | `allowOverlaps` |
| 与已有固定计划重叠 | `SCHEDULE_CONFLICT` | `allowOverlaps` |

已有冲突用批量 SQL（每批 ≤100 窗口）查 `mission_schedule_revisions` 最新排期谓词，排除已取消、已有 START/END、同目标任务，不逐任务装配材料。计划窗口 `GoalImportWindow` 只表达计划区间，不把计划结束当成实际 END。

## 取消、恢复与并发

- `GoalImportCancellation` 是读取/校验/提交共享的取消信号，`check()` 抛 `GoalImportCancelled`（未提交数据回滚）；提交结果最终以回执为准。
- `recover` 读取 `pending`，仅 `READY` 作业重建预览；`discard` 带 `expectedJobId` 守卫（不符报 `JOB_CHANGED`）。
- 服务 `_busy` 串行化 `prepare`/`commit`/`discard`，并发调用报 `StateError`。
- `page`/`nodePaths` 从暂存分页读取预览明细与节点父路径，长说明不一次性装载。

## 陷阱与约束

- 暂存库独立于业务库：正式查询不读暂存，确认前零写入；Web 无持久存储时拒绝导入。
- 单作业：同时只允许一份导入草稿，`begin` 遇已有草稿报 `JOB_EXISTS`，须先继续或丢弃。
- 预览一致性是提交前提：root、resolved、计数任一变化都 `PREVIEW_STALE`，须重新预览。
- 万级任务靠流读 + 磁盘暂存 + 分页 + 受控批量事务；协议允许 10000 任务不代表设备验收已通过，规模仍需实机验证。
- 导入只创建计划事实；FIXED 在时段内且允许自动开始时，提交后调度器可能立即 START（见[调度与执行事务](../任务与材料/调度与执行事务.md)）。
- 关闭顺序：App 退出先关闭助手、分析与导入再关业务库，见[调用与失败恢复关系](../../调用与失败恢复关系.md)。
