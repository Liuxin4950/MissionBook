# 协议与校验

> 目标计划导入的两条 JSON 协议、资源上限、字段校验与默认值展开。规则集中在 [goal_package_rules.dart](../../../../lib/domain/rules/goal_package_rules.dart) 与 [goal_package_parser.dart](../../../../lib/application/goals/goal_package_parser.dart)，上限在 [goal_package_import.dart](../../../../lib/domain/entities/goal_package_import.dart) 的 `GoalImportLimits`。本文只描述协议与校验，暂存与提交见[暂存事务与规模](暂存事务与规模.md)。

## 两条协议

`GoalPackageRules.validateRoot` 按 `schema` 分流，`version` 必须为整数 `1`，未知根字段一律拒绝（`UNKNOWN_FIELD`）。

| 协议 | schema | 必填根字段 | 创建结果 |
| --- | --- | --- | --- |
| 仅大纲 | `mission-book.goal-outline` | `schema`、`version`、`goal`、`nodes` | Goal + GoalNode 树，不建任务 |
| 完整目标包 | `mission-book.goal-package` | `schema`、`version`、`packageId`、`goal`、`defaults`、`nodes`、`missions` | Goal + 节点 + 万级 Mission |

大纲另有独立严格解析器 [goal_outline_parser.dart](../../../../lib/application/goals/goal_outline_parser.dart)（`GoalOutlineParser.parseText/parseBytes`，2 MiB、500 节点、12 层），实体在 `goal_outline_import.dart`；目标包走流式 `GoalPackageParser`。两者都“确认前不写业务数据”。

## 字段去向

| 层级 | 允许字段 | 校验与去向 |
| --- | --- | --- |
| `goal` | `title`、`description`、`why` | `title` 必填 ≤200 字；其余可选文本 → Goal |
| `defaults` | `timeZone`、`plannedDurationMinutes`、`verificationPolicy` | 任务级缺省值，按 IANA 时区 / 1–1440 分钟 / 三种材料策略校验 |
| `nodes[]` | `key`、`title`、`description`、`children` | `title` 必填 ≤200；`key` 见下；`children` 递归表达树 → GoalNode |
| `missions[]` | `key`、`nodeKey`、`title`、`description`、`why`、`verificationPolicy`、`schedule`、`executionPlan` | `nodeKey` 必须命中已校验节点（`UNKNOWN_NODE_KEY`），缺省直接归属目标 |
| `missions[].schedule` | `scheduledDate`、`timePolicy`、`timeZone`、`plannedDurationMinutes`、`fixedStartAt`、`evidenceDeadlineAt` | → MissionScheduleRevision（revisionNumber=1） |
| `missions[].executionPlan` | `objective`、`steps`、`verificationCriteria`、`notes` | `objective` 缺省取任务标题；→ ExecutionPlan |

`key` 模式 `^[a-z0-9][a-z0-9._-]*$`，节点/任务键 ≤64 字符，`packageId` ≤128。`title`/`objective` ≤200 字，普通文本 ≤20000 字（`text` 默认上限），单条字符串解析上限 20000 runes。

## 资源上限（GoalImportLimits）

文件不能覆盖这些常量；解析与暂存逐块强制。

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `fileBytes` | 32 MiB | 选取文件总字节上限 |
| `pasteBytes` | 2 MiB | 粘贴上限；大纲协议即便走文件也仍限 2 MiB |
| `nodes` | 500 | 节点总数 |
| `missions` | 10000 | 单目标任务总数（万级设计目标） |
| `depth` | 12 | 节点树层级 |
| `jsonDepth` | 64 | JSON 嵌套层级 |
| `jsonValues` | 1000000 | JSON 值总数 |
| `steps` | 100000 | 全包步骤总数 |
| `missionBytes` | 256 KiB | 单条任务序列化字节 |
| `batchBytes` | 1 MiB | 暂存分页累计字节预算 |
| `stageBytes` | 256 MiB | 暂存库 `max_page_count` 预算 |
| `pageSize` | 50 | 预览分页默认条数（暂存 `entries` 上限 100） |

解析器另拒绝：小数/指数数字（`INTEGER_TYPE`，只接受整数）、重复对象键（`DUPLICATE_FIELD`）、未配对 Unicode 代理（`INVALID_UNICODE`）、BOM（服务层 `BOM`）、根对象后多余内容。

## 时间与截止校验

- `timePolicy` 仅 `FIXED`/`FLEXIBLE`。FIXED 必须给 `fixedStartAt`；FLEXIBLE 出现 `fixedStartAt` 报 `UNEXPECTED_FIELD`。
- `instant` 要求真实日期、秒和明确时区偏移或 `Z`（拒绝 `-00:00`），最多毫秒精度；非 `Z` 时换算到排期时区必须与当地时刻一致，否则 `OFFSET_ZONE_MISMATCH`。
- `scheduledDate` 走领域 `validateScheduledDate`，必须是真实 `YYYY-MM-DD`。
- `verificationPolicy` 仅 `SELF_REPORT`/`OPTIONAL_EVIDENCE`/`REQUIRED_EVIDENCE`。强制材料必须填 `verificationCriteria`（`REQUIRED_CRITERIA`）；只有强制材料可设 `evidenceDeadlineAt`（否则 `UNEXPECTED_DEADLINE`）。
- 强制材料缺省截止由 `nextMidnight(date, zone)` 展开为排期时区次日零点；对历史偏移变化导致的歧义午夜或不存在零点报 `INVALID_DEADLINE`，要求自定带偏移截止。
- `steps` ≤100 条，每条非空 ≤2000 字；`plannedDurationMinutes` 为 1–1440 整数。

## 默认值展开与创建组装

`GoalPackageRules.resolveMission` 把任务级缺省回落到 `defaults`（时区、时长、材料策略），将 `nodeKey` 映射为应用生成的节点 id，输出规范化 `resolved` 字段集。`GoalPackageRules.creation` 据此组装 `Mission` + `MissionScheduleRevision`（revisionNumber=1）+ `ExecutionPlan` 为 `MissionCreation`，并调用领域 `validateMissionCreation` 复用普通创建的同一校验。规则层不写数据库、不判定任务当前是否可执行；时间门槛与冲突在仓储复核阶段按当前时钟检查。

## 陷阱与约束

- 协议字段是封闭集合：解析器 `_fields` 与 `validateRoot` 双重拒绝未知字段，JSON Schema 的 `format`/`default` 不等于运行逻辑。
- 大纲与目标包共用确认前零写入边界，但解析路径不同：大纲内存严格解析，目标包流式 + 暂存。
- 万级是设计与协议目标，不是设备验收结论；规模预算与取消恢复见[暂存事务与规模](暂存事务与规模.md)。
- 外部 AI 生成提示词与样例属历史设计资料，见[归档](../../../设计/目标计划导入/总览.md)；现行字段以本文与源码为准。
