# 提醒恢复与资源释放

> 本机提醒投影损坏后的恢复、稳定通知编号和资源关闭顺序。任务事实仍通过 MissionService 写入。

## 提醒配置恢复

```text
App._configureNotifications
  → ReminderStore.load
    ├ 有效文件：完整校验后替换内存快照
    └ JSON / 字段类型 / 编号损坏
       → 保留 reminders.json.corrupt-<时间> 原件
       → 写入空设置及 needsNotificationReset=true
  → 如需恢复，先 plugin.cancelAll
  → completeNotificationReset：原子保存清除标记
  → AppNotificationService.start → 按当前任务重新对账
  → _notificationsReady=true → 交付初始化期间的通知动作
```

[ReminderStore](../../../../lib/data/notifications/reminder_store.dart)只捕获格式和类型损坏；文件读写权限、磁盘等 IO 失败仍向调用者报告。恢复标记在原子文件替换中持久化；系统撤销或后续保存失败时不能假装已经恢复。坏文件保留供排查，业务数据库不被清空。

全量撤销和恢复编号表由 App 组织，不能在缺少编号的情况下直接重排新通知。Windows 直发形态仍可能无法撤销已有计划项，该平台边界保留；旧提醒被点击时仍要按任务事实检查序号与排期。

Android 后台入口使用 recoverCorruption=false 读取设置。损坏时在内存使用空提醒投影，不改写或归档前台文件；任务调度继续运行，编号和通知外观恢复由前台负责。JobService 重复下发同一作业时不覆盖正在运行的引擎，完成回调始终用最新 JobParameters 结束作业，避免旧引擎与超时泄漏。

## 编号与队列

- 当前排期的开始、等待和执行通知键在重复对账中保持稳定。改期后旧开始键、任务结束后的执行键、已移除任务的全部键，在平台撤销成功后回收。
- 提醒候选查询有条数上限（未开始固定任务取前 64 条）。落榜不等于任务消失：对账时按编号重读真实事实，只有确实已删除的任务才回收编号，其余继续同步，避免远期固定任务被误撤销提醒。
- 数字分配器只递增；删除过期键不重新使用旧数字。仍有效的当前版本键不能因一次未显示而被回收，后台唤醒继续使用这些编号。
- App 初始化动作队列和通知服务待交付 UI 队列各限制为 64 项。超过上限保留最新项；App 就绪后告知部分旧操作已丢弃，要求核对当前任务。
- 通知初始化失败后，回到前台可重试配置。重试合并为一个 Future；不会同时创建多个通知服务。
- 通知服务关闭后拒绝新动作，不重新 start 或 refresh；已经排队的业务动作在数据库关闭前等待完成。

## 关闭责任

[closeResources](../../../../lib/application/lifecycle/close_resources.dart)顺序尝试所有释放步骤，逐项报告安全的错误类型和堆栈，返回是否全部成功。它不会把服务失败变成任务写入成功。

```text
App 正常退出
  → 等待已有恢复及语音关闭
  → 等待通知初始化 / 重试
  → 截止调度 → 计划调度 → 通知动作及刷新
  → 助手 → 分析 → 目标导入
  → 任务 / 目标变化流与界面监听
  → 数据库

备份恢复前
  → 停止所有会写入的旧服务
  → 有任何暂停错误：其余服务仍继续释放，随后拒绝数据替换
  → 全部暂停成功：进入已有恢复事务与工作区重建

后台单次运行
  → scheduler.dispose → missions.dispose → database.close → 原生 finished
```

PlannedMissionScheduler.dispose 等待在途刷新，并吸收已经交由刷新调用者处理的失败；AppNotificationService.dispose 独立等待变化订阅、动作、刷新和两个事件流，通知服务重复关闭复用同一 Future。平台后台即使释放中遇错也继续尝试 finished，并报告 failed。

同步 Flutter State.dispose 只能启动异步关闭；系统直接杀进程时没有清理执行保证。对应持久事务和回执仍是恢复依据。

## 语音与诊断

助手入口的语音切换使用 try/finally 解除 transitioning，异常保留草稿并提示重试。模型下载同一实例继续共享尚未完成的任务；临时文件删除失败不覆盖原下载异常，下次下载会截断重建 .part。没有引入并行下载或新的语音引擎代次协议。

分析和导航排障只记录错误类型与堆栈，不原样输出模型供应商响应或凭据。用户可见错误仍经既有脱敏映射。
