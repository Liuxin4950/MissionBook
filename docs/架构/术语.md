# 当前术语

| 概念 | 代码 | 含义与边界 |
| --- | --- | --- |
| 目标 / 节点 | Goal / GoalNode | 长期方向及大纲结构；任务可独立存在，也可关联目标和节点 |
| 任务 | Mission | 一次具体行动；归属在开始后锁定，目标归档不自动结束其任务 |
| 行动方案 | ExecutionPlan | 任务的具体目标 objective、验证标准等；不是一批排期建议 |
| 排期版本 | MissionScheduleRevision | 日期、时区、时段、投入额度和材料截止的版本事实 |
| 安排提案 | ScheduleProposal | 助手准备的多任务创建或改期建议，先预览冲突再确认提交 |
| 调度快照 | PlannedMissionSnapshot | 自动执行候选与刷新时刻，供调度器使用 |
| 执行事件 | ExecutionEvent | 实际 START / PAUSE / RESUME / EXTEND / STOP / END 时间线 |
| 执行报告 | UserExecutionReport | 用户声明的发生日期和实际时间，可追加更正；不伪造专注事件 |
| 记录 | Record | 独立保存的原始文字或附件，可关联目标、节点、任务 |
| 材料 | Evidence | 指向记录内容的任务材料事实；EvidenceRecords 表保存关联投影，关联时不复制原始内容 |
| 失败事实 | FailureRecord | 超时、用户未完成等事实，与自由记录、材料、模型结论分开 |
| 评价 / 总结 | AnalysisScope + AnalysisService | 任务 UI 使用评价，记录、节点、目标使用总结；仅辅助理解，不改变用户结果 |
| 长期记忆 | MemoryService | 跨会话偏好、明确事实及待验证观察，有独立生命周期和仓储 |
| 记录库 | RecordsPage | 查看多条独立记录 |
| 任务执行记录工作区 | MissionRecordWorkspace | 查看单个任务的事件、用户报告和材料 |

AnalysisScope 在 Dart 内使用 record / mission / node / goal / memory 枚举，在 SQL、JSON 和偏好存储边界仍使用原来的字符串。未知值明确报错，不默认为其他范围。

旧 MissionPlan、MissionRecordPage 和 AssistantPlanService 的内部名称已迁移。数据库 operation kind、已保存工具名、JSON 字段保留兼容；旧 snake_case 工具作为隐藏的恢复入口，模型接收当前公开工具名，不能为了统一命名破坏会话重放和幂等回执。
