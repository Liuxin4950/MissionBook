# 当前术语

| 概念 | 代码 | 含义与边界 |
| --- | --- | --- |
| 目标 / 节点 | Goal / GoalNode | 长期方向及大纲结构；任务可独立存在，也可关联目标和节点 |
| 目标包导入 | GoalPackageImportService + ImportReceipt | 课标 JSON 经独立暂存、校验、预览后原子创建目标/节点/任务，持久回执保证幂等；确认前不写业务，见[目标计划导入](前端/目标计划导入/README.md) |
| 任务 | Mission | 一次具体行动；归属在开始后锁定，目标归档不自动结束其任务 |
| 行动方案 | ExecutionPlan | 任务的具体目标 objective、验证标准等；不是一批排期建议 |
| 排期版本 | MissionScheduleRevision | 日期、时区、时段、投入额度和材料截止的版本事实 |
| 安排提案 | ScheduleProposal | 助手准备的多任务创建或改期建议，先预览冲突再确认提交 |
| 调度快照 | PlannedMissionSnapshot | 自动执行候选与刷新时刻，供调度器使用 |
| 执行事件 | ExecutionEvent | 实际 START / PAUSE / RESUME / EXTEND / STOP / END 时间线 |
| 执行报告 | UserExecutionReport | 用户声明的发生日期和实际时间，可追加更正；不伪造专注事件 |
| 记录 | Record | 独立保存的文字或单个附件及说明，归属目标/节点；任务可引用内容快照 |
| 材料 | Evidence | 任务提交时固定的内容快照；保留来源记录编号，原记录可独立编辑、删除或改归属 |
| 失败事实 | FailureRecord | 超时、用户未完成等事实，与自由记录、材料、模型结论分开 |
| 评价 / 总结 | AnalysisScope + AnalysisService | 任务结束后分析任务及其材料；节点、目标汇总下层摘要；记录不单独生成 AI 摘要 |
| 长期记忆 | MemoryService + MemoryContextAssembler | 五层条目、主题与别名、追加式版本、派生情节/流程与 usage；写入、检索、抽取开关、预算和待验收边界见[长期记忆](前端/助手与总结/长期记忆.md) |
| 记录库 | RecordsPage | 查看多条独立记录 |
| 任务执行记录工作区 | MissionRecordWorkspace | 查看单个任务的事件、用户报告和材料 |

AnalysisScope 在 Dart 内使用 mission / node / goal / memory 枚举，在 SQL、JSON 和偏好存储边界仍使用稳定字符串。未知值明确报错，不默认为其他范围。

记忆的 `layer`（identity / semantic / episodic / procedural / observation）与 `certainty`（stated / inferred / unverified）是两个维度；“confirmed”装配条件指 stated 且非 observation，不是额外 certainty 值。`goalId` 表示全局或具体目标作用域：日记本选择某目标同时显示全局记忆，“全部记忆”用于浏览，不等于全部目标都可注入助手。AI save 的所有 certainty 均须本轮 basis 是本轮收口要求，最终测试待回填。

“自动整理对话记忆”是“助手设置 → 自动总结”中的独立即时保存开关，关闭只停新自动抽取，已有记忆仍可使用；它不同于任务/节点/目标三层自动总结。“忘记”写墓碑并保留版本，不表示物理删除对话、日志或备份；旧摘要与工具结果的传播清理仍待最终验收。

助手工具采用统一的语义化名称，归属设置与材料提交分别执行；命令回执用于确认当前操作结果。
