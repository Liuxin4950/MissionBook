### 主页面按需装载与刷新

AppShell 仍保留四个 IndexedStack 位置以维持导航状态，但未访问过的标签先用轻量占位；首次选中时才创建对应页面。已经访问的页面继续保留，切换离开后通过 `active` 标记停止无关刷新；期间收到 changes 或应用恢复时只记下待刷新状态，重新选中后再读取。该策略保留各页滚动、筛选和展开状态，不把后台通知当作新事实。

历史列表将日期分组改为一次遍历并由 SliverList 按可见范围构建卡片；今天页的待补材料查询先用持久事实筛选候选，再装配完整详情并通过唯一 `deriveMissionPhase` 确认阶段。分析输入批量读取子项事实与总结，分块受控。详细调用见[任务与材料](前端/任务与材料/README.md)及[助手与总结](前端/助手与总结/总览.md)。

### 事实与事务

任务阶段由事件、材料、失败和排期共同推导，不保存可写 phase。事件为 START、PAUSE、RESUME、EXTEND、STOP、END；STOP 冻结到点计时，END 保存用户确认结果。七种阶段以[当前枚举](../../lib/domain/entities/mission_phase.dart)及完整派生规则为准。

固定任务以计划开始为计时起点，原计划终点仅因明确 EXTEND 延后，调度唤醒和应用恢复不改变窗口。事务校验当前时间与快照后保存固定 START/STOP 的生效时刻；统一计时规则也按原排期修正旧的迟到 START 投影。详见[固定任务计时](前端/任务与材料/README.md#固定任务计时)。

材料可在执行前或执行后保存。材料、用户报告完成、模型评价和用户掌握是不同事实，互不冒充。材料修正追加历史，不覆盖旧内容；关联已有记录经过任务材料命令保存提交快照；来源内容和归属独立维护。

执行报告及必要 END 在任务命令事务内保存。到期 STOP 由应用服务在独立维护步骤先提交；旧快照导致报告冲突时，STOP 不会一起回滚。命令身份和已保存回执用于幂等重试。

自动调度也先独立提交到期 STOP，再在另一事务尝试 START；已补记 END 不进入开始候选。BEGIN 竞争只在正文尚未执行时按 SQLite 结果码有限重试，正文和提交失败不自动重放。见[调度与执行事务](前端/任务与材料/调度与执行事务.md)。

不带 AndReconcile 的 MissionService 查询保持纯读取；带该后缀的方法明确执行材料截止维护后再查。定时调度的开始/停止仍从专门维护入口进入，不在阶段 getter 内写库。

开发阶段只维护当前数据库结构，不保留历史版本转换代码与结构快照副本。旧结构数据库不会迁移，也不会被应用自动删除；打开旧版本库时显式拒绝，并提示用户导出仍可读的数据或清除应用数据。记录归属与材料提交使用独立入口和操作回执。详见[记录边界](前端/任务与材料/记录独立维护与材料快照.md)。

完整备份恢复先使用当前结构的隔离库校验，再以新附件键和数据库事务替换业务快照；App 暂停服务后执行恢复并重建工作区。版本要求和失败边界见[数据备份与恢复](前端/数据备份与恢复/README.md)。

## 跨模块数据流

```text
页面 / 助手工具 / 系统提醒
  → application 服务：校验意图、准备命令身份、组织附件
    → domain 仓储契约
      → data 仓储：共享 AppDatabase → 写锁 → 重读事实 → 校验 → 原子提交
    ← 提交成功后发送 changes
  ← 重新查询 MissionDetail → 唯一时间线 / 阶段推导 → 页面呈现

独立记录 → RecordService → DriftRecordRepository（内容）
                         → MissionService（关联任务材料）
记录和任务 → AttachmentCoordinator（共享附件与提交互斥）
长期记忆 → MemoryService / MemoryContextAssembler → DriftMemoryRepository（条目、主题别名、版本）
总结队列 → AnalysisService → DriftAnalysisStore → 已配置模型
```

## 全局约束

跨模块装配、备份文件互斥、提醒恢复、工具核对和可靠关闭见[调用与失败恢复关系](调用与失败恢复关系.md)。

仓储拆分使用同一 Dart library 的具体协作者，事务和数据库连接仍由同一个仓储外观持有；part 文件不是独立连接或新的持久化层。各页面局部区域保持在所属页面 library 内，避免拆出无职责的公共组件。

模型调用失败不能更改任务事实。通知、前台和助手共用应用服务，不能绕过事件与材料命令直接写事实。应用退出先等待通知动作、截止与计划调度关闭，再关闭共享数据库；Web 不初始化本机通知存储。自动化与目标设备验收的范围见[整改记录](../审查/2026-10-31-全局样式与架构整改.md)。
