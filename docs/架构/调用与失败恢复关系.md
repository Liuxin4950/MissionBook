# 跨模块调用与失败恢复关系

> 本文定位当前已经接通的对象关系、写入入口及失败后的责任归属。具体规则分别以模块文档和源码为准；图中所有入口均已实现。

## 装配与资源拥有者

```text
App / _AppWorkspace（一个工作区）
  ├ AppDatabase（共享业务数据库）
  │   ├ DriftMissionRepository → MissionService
  │   │   ├ 页面：今天 / 全部任务 / 执行 / 报告 / 材料
  │   │   ├ AssistantTools：执行、补记、维护及排期
  │   │   └ 计划调度 / 材料截止 / 通知动作
  │   ├ DriftGoalRepository → GoalService → 目标及路径页面
  │   ├ DriftGoalPackageRepository → 目标包原子导入（写锁内重查回执）
  │   ├ DriftRecordRepository → RecordService → 独立记录及材料关联
  │   └ 会话、记忆、分析和搜索额度仓储
  ├ GoalPackageImportService → GoalImportDatabase（独立暂存库，确认前不写业务）
  ├ AttachmentCoordinator（记录、任务和备份共用）
  │   └ 文件读取 / 提交 / 清理之间的进程内互斥
  ├ AssistantController → AgentRuntime → AgentSession → AgentLoop
  ├ AnalysisService（持久分析待办的领取与发布）
  ├ PlannedMissionScheduler / EvidenceDeadlineScheduler
  ├ AppNotificationService → ReminderStore + 平台 NotificationDispatcher
  └ ManagedBackupService → 导出 / 隔离校验 / 恢复后重建工作区
```

源码入口为 [App 装配](../../lib/app.dart)、[任务服务](../../lib/application/missions/mission_service.dart)及[助手工具](../../lib/application/assistant/assistant_tools.dart)。仓储协作者是同一 library 的具体职责，不是新的数据库连接。

Android 计划任务后台入口会建立自己的连接和调度实例；跨连接写入由 SQLite 事务约束。AttachmentCoordinator 只负责当前进程的文件协调，不作为跨进程数据库锁。见[任务事务](前端/任务与材料/调度与执行事务.md)及[平台资源](前端/平台资源/提醒恢复与资源释放.md)。

## 事实、快照和界面

```text
用户 / 助手 / 通知表达意图
  → MissionService 准备固定命令身份
  → 仓储取得写权限 → 重读序号、排期和事实 → 校验 → 原子提交
  → changes 通知订阅者重新读取
  → MissionDetail 构造不可变快照
  → deriveMissionPhase 唯一完整推导（包含 STOP、END 与材料事实）
  → 页面显示快照；计时随注入时钟投影，不追加执行事件
```

MissionDetail 的事件、材料、失败和报告列表会防御性复制；阶段在构造时计算一次，不能由调用方提供或修改。新事实通过新查询生成新快照；没有第二份可写阶段。发生日期的设备回看、用户声明日期和日程业务周界仍分别沿用既有口径。

## 事务与错误归属

| 操作 | 提交边界 | 失败时的处理入口 |
| --- | --- | --- |
| 到期 STOP 与自动 START | STOP 事务先提交，START 使用后续事务 | START 失败保留 STOP，MissionService 通知重读并继续抛错，由调度器安排重试 |
| 用户执行与执行报告 | 到期维护在前；当前命令及必要事实原子保存 | 序号或排期变化时拒绝，固定身份重试用于核对既有事件 |
| 助手执行工具 | 批准快照 → MissionService → 任务事务 | 可证明无提交的业务拒绝返回 ToolRejected；提交后异常按事件编号核对；不能确认的结果由运行时保留未知状态 |
| 已有记录关联材料 | 命令回执与材料快照同事务 | 回执确认后若任务被并发删除，返回明确 EvidenceConflict，不能用空断言或重新提交替代 |
| 完整备份导出 | 同一数据库快照，事务外编码与附件读取 | 共享附件互斥保护原件存活，缺文件则整个导出失败，不交付缺件 ZIP |
| 恢复备份 | 先暂停旧资源，再按既有指纹与事务替换 | 任一暂停失败仍尝试停止其余服务，最后拒绝替换；成功后重建工作区 |
| 目标包导入 | 写锁内重查回执，目标/节点/任务/方案/排期/回执一次事务 | 已导入按回执幂等返回；预览不一致报 PREVIEW_STALE；BEGIN 竞争由 AppDatabase 恢复，不重放已运行导入 |

## 本机提醒与业务执行

提醒 JSON 保存本机送达状态和编号，不保存任务执行事实。损坏文件恢复、系统通知撤销和重新对账由 App 装配入口组织；计划任务是否停止或开始仍只由任务仓储决定。通知初始化失败不会把任务调度解释成执行成功，也不会无限积累 UI 动作。

详细恢复关系见[提醒恢复与资源释放](前端/平台资源/提醒恢复与资源释放.md)。

## 关闭关系

```text
正常退出
  → 等待已有恢复过程、语音关闭、提醒初始化 / 重试完成
  → 停止截止调度、计划调度及通知动作
  → 关闭助手、分析与导入
  → 关闭任务 / 目标变化流及界面监听
  → 关闭共享数据库

后台一次运行退出
  → 停止调度 → 释放任务服务 → 关闭后台数据库 → 向原生报告 finished
```

[closeResources](../../lib/application/lifecycle/close_resources.dart)会逐项等待并隔离异常。某项失败不会跳过后面的数据库或后台完成信号。同步 State.dispose 发起关闭 Future，不能等待它；实际顺序由 App._closeWorkspace 负责。进程被系统直接杀死不等同于正常退出，不保证有机会执行 Dart 清理。
