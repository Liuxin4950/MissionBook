## 图的四条带

1. **业务流程与页面路由**：入口 → 详情 → 执行 → 报告 → 记录 → 再次尝试 → 新任务。标明 START / END 成功使用路由替换，临时查看详情使用压栈，返回复用原页面实例。
2. **写入链路**：页面动作 → `MissionActionController` → `MissionService` → `ExecutionCommand` → `DriftMissionRepository.execute` 同一事务 → 事实表 → 提交后 `_notify()`。
3. **状态同步**：图中 `changes` 广播 + `changeRevision` → 今天页、当前任务栏、历史页、详情页、执行页各自重读；当时记录页未订阅。现行记录页已订阅事实变化并检查材料截止，只有执行时长仍按 END 冻结。
4. **读取与派生**：五个仓储查询 → 同一读事务的 `MissionDetail` / `ScheduledMission` → `deriveSelfReportMissionPhase` 与 `calculateExecutionTimes` → 页面显示；右侧五张表及关系。（图为 2026-10-24 快照：阶段派生现由完整入口 `deriveMissionPhase` 承担，`deriveSelfReportMissionPhase` 已删除，见 2026-10-25 变更记录。）

- 第一轮：发现 ① 的箭头标签压住任务框、② 的 `ExecutionCommand` 长字段越过右边框、行内短箭头标签遮住框线。修正为标签移到框下方、缩短字段、移除短箭头标签。
- 第二轮：发现 ③ 执行页的 `_refresh(acceptReportSequence:false)` 超宽、④ `missions` 表与关系总线之间的说明拥挤。改为 `_refresh(false)`，并补充“阶段不落库”。
- 第三轮：把“提交成功 → 广播”的虚线箭头从 `提交与返回` 连到 `changes`，并确认四块文字、箭头方向和表关系没有交叉。
