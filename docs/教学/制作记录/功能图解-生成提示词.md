```text
画清晰完整的状态流程图，六个阶段必须恰好有六个独特状态大节点，中文大字、英文小字：
“待开始 NOT_STARTED”“执行中 RUNNING”“已暂停 PAUSED”“待补材料 EVIDENCE_PENDING”“已结束 CLOSED”“已取消 CANCELLED”。

待补材料→已结束有三条平行清晰路径：“提交首批正式材料”“可选材料：明确放弃”“强制材料：达到截止记录超时”。已结束和已取消在右下共同连向独立操作框“再次尝试 RETRY”，再一条长箭头回到新建入口，标“产生新任务；不复活旧任务”。
底部两条重要图形注释：“开始后：归属、方案、排期锁定”“结束后：保留报告与历史，正式材料只能追加修正”。不要引入第七种阶段，不要将END事件画成状态。
```

```text
“已完成”向下进入“选择的验证策略”，下方三列完整分流，列宽均匀：
左列“自报型 SELF_REPORT”：直接→“已结束”。
中列“可选材料 OPTIONAL_EVIDENCE”：菱形“本次是否稍后提交？”；“否”→“已结束”；“是”→“待补材料”；待补材料有两个出口“提交至少一条有效材料”→“整批原子提交”→“已结束”；“明确放弃可选材料”→“记录放弃时刻”→“已结束”。小注“没有强制截止”。
右列“强制材料 REQUIRED_EVIDENCE”：菱形“事务内 now < 截止？”；“是”→“待补材料”；“否，含等于截止”→“保存完成报告＋唯一材料超时记录”→“已结束”。右列待补材料下再画菱形“首次提交时仍未到期？”：“是”→“整批原子提交正式材料”→“已结束”；“否”→同一“唯一材料超时记录”终点。待补材料另有虚线触发“启动／回到前台／前台到期补算”→截止判断。小注“未开始、执行中、暂停不被材料截止强制结束”。
为避免连线混乱，各列用自己的已结束终点，允许重复终点但不能错误合并条件。所有分支都有标签，不交叉。
底部独立一条“材料的生命周期”图形带：“草稿：可增删改”→“提交成功：正式记录”→“后续修正：追加新记录→旧记录保留”；草稿下图标“失败保留当前草稿／退出进程不保证恢复”；正式记录下标签“文字／代码／手动记录／图片／文件”；右侧强调“报告完成 ≠ 材料通过验证；本版没有AI评分”。不要把材料存在画成通过验收。
```
