# 目标计划导入：实现与验证记录

## 实际数据路径

外部 AI 根据[字段协议](协议与字段.md)、[排期配置](排期与导入配置.md)和[生成指引](外部AI生成指引.md)输出 JSON；可从目标页面选择文件或粘贴。解析器分块读取并写入独立暂存库，完整校验后分页预览；确认后业务库事务写入 Goal、GoalNode、Mission、ExecutionPlan、首条 MissionScheduleRevision 和 ImportReceipt。用户取消或异常不会留下半个业务目标；回执用协议、packageId 与内容摘要识别重试。旧 goal-outline v1 仍可导入。

上限：文件 32 MiB，粘贴和旧大纲 2 MiB，500 节点、12 层、10000 任务、总计 100000 步骤；超限拒绝。暂存库设置 256 MiB SQLite 页面上限，设备可用空间或浏览器配额不足仍可能更早失败。恢复时可继续已预览作业或丢弃未完成暂存。Android 选择器先复制到应用缓存，仍需要额外本地空间。

导入前检查时区、日期、字段、引用、材料和计划冲突。已过去的计划、正在开始时段的任务及重叠排期需要用户明确选择；最终提交时再次检查。固定排期使用现有真实 START 事务，已有运行中任务不会被抢占，计划到时不自动生成 END。执行步骤和备注可在开始前查看及编辑。

为控制大量任务的资源占用，计划通知最多同时安排最近 64 个固定任务；后续候选会随计划推进更新。大量任务同时到点时，部分任务的提前提醒可能未能安排。单次业务导入保持原子提交，导入时间内业务库写入可能短暂等待。目标和任务列表分页，任务详情批量读取。

业务数据库由 v9 升级 v10，新增导入回执和查询索引；v9 的材料修正关系保留。完整 App 备份恢复与目标包导出仍需另行设计和实现，目前已有备份不支持恢复。

## 验证与边界

- 实际代码在隔离文件 SQLite 上测试 500 节点和 10000 任务：暂存约 3.1 秒、事务写入约 2.1 秒、读取目标任务约 0.4 秒；重开、外键和真实 START 通过。这是单次宿主测量，不代表手机、平板或 Windows 性能。
- 10001 任务输入在正式业务写入前被拒绝；v1–v9 迁移专项 19 项通过，包含 v9 修正链。
- 全量回归 455 项通过；后续新增目标包页面操作专项 1 项通过。静态分析、Web 编译和 Android ARM64 调试包构建通过。真实设备的峰值内存、长时间后台、系统通知送达、浏览器持久化和多窗口竞争仍需实测。
