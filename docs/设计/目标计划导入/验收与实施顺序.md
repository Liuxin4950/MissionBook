## 2. 实施应按完整功能单元推进

| 单元 | 要交付的完整结果 | 必须一起验证 |
| --- | --- | --- |
| A：统一完整任务输入 | 手工/导入准备共用规则，能保存和开始前编辑 steps / notes | 未编辑字段保留、材料条件、开始后锁定 |
| B：新协议到完整预览 | 流式解析、磁盘暂存、默认展开、引用映射、时间和冲突检查 | 错误路径、课标样例、资源预算、分页及所有条件字段 |
| C：整包提交与回执 | 一次提交树和全部任务，重开文件不重复 | 迁移、失败回滚、两连接竞争、提交响应丢失 |
| D：导入页面与调度联通 | 在原导入区完整预览及一次确认，提交后刷新所有入口 | 三步路径、取消零写入、保留草稿、调度失败反馈 |
| E：规模与真实使用 | 精简候选查询、批量装配、必要索引，运行课标试验 | 查询次数、设备耗时/内存、实际执行到历史 |

可以先完成小规模闭环，再扩到学期；不能把只有解析器、只有表结构或只有插入成功称为“完整导入功能”。

同日已发现的结束报告 R01 / R02 会影响真实执行链，应在正式可行性试验前修复并补回归；查询放大 R06 应在开放大批量前整改。详见[现有功能审查](../../开发/审查记录/2026-10-27-lib功能审查.md)。本轮研究未代为修复它们。

## 3. 新协议必须覆盖的自动验收

| 分类 | 场景 | 预期 |
| --- | --- | --- |
| 结构 | 未知键、错误版本、null、重复对象键、超字节/深度 | 带路径拒绝，零写入 |
| 节点 | 同名不同 key、重复 key、总数、树深度 | 同名可用；其余按规则判断 |
| 引用 | 未知 nodeKey、仅目标归属、同节点多任务 | 未知拒绝；合法映射准确 |
| 默认值 | 覆盖时区/时长/策略、方案省略 | 预览和落库内容逐字段一致 |
| 完整方案 | 多步骤、notes、objective、材料方向 | 保存、读取、编辑、重试都不丢失 |
| 日期 | 2 月 30 日、跨年、无偏移、无效 IANA | 拒绝非法，合法按 UTC 保存 |
| 时区 | 夏令时重叠/跳时、偏移不符、午夜不存在 | 歧义或不存在时明确拒绝，不顺延 |
| 排期 | FIXED 缺开始、FLEXIBLE 带开始、0/小数时长 | 拒绝 |
| 材料 | 继承强制策略但无标准、非强制带截止 | 拒绝 |
| 截止 | 默认次日零点、显式截止、等于 now、预览后过期 | 合法确定展开；不合法整包拒绝 |
| 冲突 | 包内/已有计划、跨午夜、端点相接 | 按统一半开区间及本地确认选项处理 |
| 原子性 | 第 K 条失败、回执失败、外键失败 | 全部回滚 |
| 去重 | 同包同内容、空白/对象键序变化、同包异内容 | 返回原结果或明确冲突 |
| 重开后重试 | 成功后目标改名/暂停、任务开始、截止过去 | 返回原回执，保留后续修改 |
| 并发 | 两独立连接同时导入相同包或不同包 | 相同包仅一次，不出现半链 |
| 调度 | 提交前不触发、提交后固定任务可被发现 | 先提交，后重读并沿用统一执行入口 |
| 导入期间退出 | 提交前/后分别退出并重开 | 全部未保存或全部存在，回执可确认 |
| 兼容 | 旧大纲文件及各旧版数据库 | 旧入口仍能使用，保数据升级 |

## 4. 性能验收

用户目标为单 Goal 约 1 万个任务。准备 10 / 100 / 1000 / 10000 个新任务，以及累计 10 个此规模 Goal、已有大量事件和材料的组合库，分别测：

- 文件读取、解析、默认值展开、冲突检测、预览首次可操作时间。
- 整包提交、提交后页面刷新、通知对账、寻找下一次唤醒的时间与 SQL 数。
- 主线程长任务、列表滚动、内存峰值、进程重开时间和数据库大小。
- 与取消/改期/手动 START/后台唤醒并发时，写锁等待及错误恢复。

SQL 次数应由固定批量读取和有限分块决定，不能随任务数恢复为“每项四五个查询”。性能数值以目标 Android / Windows 实测建立基线，本轮不凭宿主探针承诺毫秒级目标。

性能不合格应减少重复查询、缩小候选集和控制预览构建；不分段提交导致半包，也不隐藏丢失的任务来让数字通过。

## 5. 用户的第一轮可行性试验

1. 用真实课标中的一小段，生成 5–20 个近期任务，核对知识点、次数、可用时段和材料要求。
2. 预览确认前退出一次，确认没有新增目标或任务；再次导入并正式确认。
3. 在目标树、今天和全部任务查看相同的真实记录，检查节点归属、固定/自选及方案。
4. 先修改一条尚未开始的任务，确认新排期追加版本、steps / notes 被正确保留。
5. 到固定时刻观察 START；有其他 RUNNING 时观察保留当前任务和冲突反馈。
6. 实际暂停/继续/结束至少一条，分别走自报、可选材料和强制材料；重开后核对报告及附件。
7. 再选择同一目标包，确认指向原目标且任务数不变，已经发生的执行事实不被覆盖。
8. 最后再试错过时段、跨午夜、锁屏、进程回收与设备重启，记录平台能力。

核验的是“能否忠实生成、导入、启动、执行并保存可回看的课程记录”。不能把有完成记录或交了材料等同于知识掌握。用户掌握仍需独立解释或操作证据。
