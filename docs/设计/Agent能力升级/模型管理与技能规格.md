# 模型管理与技能规格

对应 M01 与 S01，依赖和交付顺序见[工作包与验收](工作包与验收.md)。

M01 的目录、凭据、分页和选择已有实现，当前架构见[助手总览](../../架构/前端/助手与总结/总览.md)。本文同时保留接续目标，未落地项集中登记于[实施状态](工作包与验收.md#实施状态)。S01 仍为规划。

## M01 多服务、多模型

### 用户可完成的操作

1. 新增自定义服务，填写名称、地址、协议和可选 Key。
2. 获取服务模型列表，搜索选择后加入模型，允许重复添加及手动补充编号。批量多选作为接续扩展。
3. 修改每个模型的窗口、输出硬上限、日常输出预算、图片能力和思考选项。
4. 选择新会话默认模型和摘要模型，在当前会话中明确切换模型。
5. 编辑、停用与恢复服务或模型，查看配置缺失的历史会话并重新选择可用模型。
6. 清除或替换指定服务 Key，其他服务使用自己的凭据引用。

服务管理使用“服务列表 → 服务编辑与模型列表 → 保存”的完整路径。常用模型切换在聊天现有模型入口完成，搜索与选择合并在同一弹层。实际点击路径含必要系统返回，按三步交互原则核对。

### 数据关系

| 对象 | 字段与职责 |
| --- | --- |
| ProviderConfig | providerId、modelProvider、displayName、baseAddress、protocol、credentialRef、requiresCredential、archived |
| ProviderModel | profileId、providerId、modelId、displayName、contextWindowTokens、outputTokenLimit、maxOutputTokens、supportsImages、reasoningEffort、archived |
| ModelSelection | defaultProfileId、可空 summaryProfileId，当前会话主模型保存在核心会话日志 |

profileId 是本地稳定身份，modelId 是供应商请求编号。不同服务可以具有相同 modelId，切换和历史引用通过 profileId 定位。

modelProvider 对应核心供应商适配身份，独立于 providerId。新 profileId 使用本地受控编号，长 modelId 保持原文。能力来源、供应商元数据刷新和额外请求头属于接续扩展。

`ModelProfile` 继续承接实际请求所需的完整地址、协议、凭据引用与预算。ProviderConfig/ProviderModel 在应用层编译成现有配置，核心执行入口读取本次不可变 ModelProfile。

窗口、输出硬上限与日常输出预算分别保存。未知能力使用明确的默认值和“手动设置”来源，不能仅凭模型名字猜测视觉、上下文或思考参数。选择列表中的模型以后仍需校验实际请求。

### 存储和编号

- 首期将服务目录及选择保存为安全存储中的一个带版本 JSON 文档，复用现有设置存储职责，避免把整套目录拆成多键半写状态。
- Key 使用独立 credentialRef，允许无 Key 的本机或兼容服务。凭据解析从固定白名单调整为受控的本应用服务凭据引用集合，拒绝任意存储键读取。
- 当前内置 `deepseek-chat`、`deepseek` 和已经存在的 `custom` profileId 在本次数据归并中保持可解析。已有 custom 配置和 Key 首次归入服务目录，成功提交目录后以新结构为运行来源。
- 该归并针对当前已经存在的数据路径。实施完成后清理旧固定配置写入口与重复状态，具体一次性读取/完成标识及失败重试必须有测试。
- 角色、语音、搜索 Key、权限设置分别保存，模型目录保存不会覆盖其他设置。

### 凭据与配置提交

新增服务时先产生稳定 providerId 和受控凭据引用。输入 Key 不作为配置 DTO、日志或模型消息的字段。

设置 JSON 与安全存储 Key 属于不同写入操作，当前使用以下提交顺序。

1. 配置草稿校验通过，生成本次新凭据版本引用，写入新 Key。
2. 一次提交指向新引用的目录 JSON，提交成功后发布新目录状态。
3. 当前实现等待运行结束再允许配置，目录提交及运行时重建后回收其他服务未引用的旧 Key。
4. 目录写入失败时保留旧生效目录，回收本次新引用或记录为可清理残留。不得删除仍被旧目录引用的 Key。

清除 Key 提交一个没有凭据的新引用，成功后显示缺少凭据。无 Key 模式跳过读取和发送凭据。目录失败保留原状态，旧 Key 清理失败通过保存结果告知。安全存储写失败后的残留清理限制见修复记录。

Key 输入框可显隐，安全存储值只在请求边界读取。额外 headers 中的敏感鉴权值按秘密处理，普通 headers 与秘密引用分开。受保护的 Authorization、x-api-key 和协议版本头由适配器生成，避免互相覆盖。

### 模型列表获取

复用并完善已落地的 `AssistantModelCatalog`。

- 使用当前草稿地址、协议和 Key，留空 Key 时可以选用该服务已有凭据。获取操作不需要先保存模型编号。
- 接受根地址、API 前缀和完整请求地址。通过协议明确转换调用地址及列表地址，保留用户自定义路径与端口。
- 现有实现会把裸根地址补为 `/v1`。完善后测试同时覆盖根级 `/models` 和 `/v1/models` 服务，自动尝试仅限相同来源的已知路径，并在采用补全结果时回填明确的生效地址。
- 支持供应商标准分页，依据实际分页字段推进并检测游标重复。保持有界总等待和取消，获取期间可退出，关闭拥有的网络资源。
- 401/403、404/405、超时、无效 JSON、空列表与分页中断给出具体可恢复状态，手动输入入口可用。
- 列表去重以 modelId 为准，选中模型与手动覆盖能力保留。刷新目录只刷新发现结果，不自动删除已添加配置。
- 若服务返回能力元数据，保存其来源与时间。用户覆盖值有更高优先级，刷新后提供恢复供应商值的明确操作。
- 服务地址、协议或草稿 Key 修改后，旧请求结果不能覆盖新草稿。使用请求身份/修订校验，按生命周期丢弃过时结果。

### 请求、切换和停用

编辑草稿与运行请求分别拥有快照。配置更新只影响后续明确的请求边界，正在流式执行的客户端和注册表在其结束前有存活所有者。

会话切换模型经过已有图片能力、预算和历史文件引用校验。主模型与摘要模型分别可用，摘要模型无法处理图片时沿用现有明确占位和预算机制。

服务和模型使用 archived 停用，保留稳定身份。历史会话回放与索引读取保持可用，发送前检查模型和凭据。恢复目录缺少原主模型时，打开会话使用日志快照供回看，并由用户选择可用模型。仅缺历史摘要时按全局选择重新绑定，主模型保持原值。

停用默认主模型或当前会话主模型前要求先切换到可用模型。服务页的停用操作先修改草稿，保存时统一校验并提交，放弃修改撤销本次编辑。

### 备份、恢复和实际调用

当前本机资源备份可以按用户勾选包含设置与 Key。新增目录、动态凭据引用和手动能力覆盖必须接入现有收集/恢复契约。用户未选择相关资源时使用已有范围行为，不能把新增 Key 混入业务数据库导出。

恢复后校验目录、凭据引用与模型选择。安全存储恢复失败时沿用当前部分恢复结果语义，显示真实生效状态。会话级导出只记录配置引用及必要历史元数据，避免携带密钥明文。

首期协议验收覆盖 Messages 与 Chat Completions 的完整流式工具循环、取消、图片、思考和错误。Responses 是后续可选协议扩展，须实现独立适配器、SSE 事件、工具参数拼装、使用量和错误测试后再加入服务选择。

### M01 验收清单

- 两个服务具有相同 modelId，选择后请求分别到正确来源并使用对应 Key。
- 当前已有 custom 数据归并后可以打开原会话，重复启动和归并中断不会复制服务。
- 新增、编辑、Key 轮换、清除、停用、删除分别检查保存失败与重启结果。
- 删除主模型/摘要模型后可浏览历史、导入历史并重新绑定模型。
- 获取列表时使用草稿 Key、已有 Key、无 Key、分页、过时请求和手动覆盖，真实路径均能完成选择保存。
- 流式生成期间编辑设置，原请求、后续请求及其关闭顺序分别正确。
- 带设置/Key 与仅业务数据的两类备份分别恢复，实际来源、权限和凭据状态可核对。

## S01 技能目录与按需加载

### 首期用户能力

用户可以查看内置技能、从输入框显式选择、通过 `/技能名` 调用、添加和编辑本地技能、导入导出技能文本。选择技能后展示用途及所需输入，再由用户发送自己的任务。

四个内置技能采用以下完整流程。

| 技能 | 输入与工具 | 成功输出 |
| --- | --- | --- |
| 周计划整理 | 目标、已有安排、可用时间，必要时 askUser，调用 planMissions | 实际安排提案、保存回执、冲突与跳过项 |
| 任务复盘 | 任务事实、报告、材料与总结，必要时补问 | 有依据的复盘与下一步建议，引用真实任务 |
| 材料归纳 | 用户选择的记录/材料、允许的图片与片段读取 | 分层摘要和来源编号，说明未读取/无法识别的部分 |
| 目标进度检查 | 目标、节点、任务与相关总结的分页查询 | 实际进度、阻塞项与可执行建议 |

具体工具名以现有工具目录为准。实现者为每个内置技能核对输入、调用、失败与结果，不以几段静态提示词和空回调交付。

### 技能结构与格式

SkillDefinition 建议包含 skillId、name、description、whenToUse、instructions、requiredInputs、allowedTools、modelInvocable、revision、source。内置技能在版本化资源中维护，自定义技能保存于应用自己的本机资料目录或现有设置存储适合的位置，实际使用时再建立必要存储。

导入格式使用 `SKILL.md` 的元数据与正文。明确支持的元数据字段，校验未知字段及错误位置。首期支持纯文本说明和允许范围内的相对资料引用。执行 shell、Python、外部下载和任意文件读取属于独立工具能力，导入技能时按声明识别。

本地资料引用相对技能根目录解析，读取前核对真实路径归属、大小与文件类型。归档导入沿用已有安全解压思想，验证路径、重复条目与链接，错误时保留原技能。

### 加载与上下文

```text
选择技能 / 解析显式 slash
  → 读取 SkillDefinition → 校验本次可用工具与模型能力
  → 展示用途并把必要参数交给输入草稿
  → 用户发送 → 持久化技能 id、revision 与实际指令快照
  → 有来源的上下文块 → 预算检查/压缩 → AgentLoop
```

同一运行的技能使用快照，编辑后影响下次调用。只加载本次选中的指令与实际需要的资料片段，技能目录摘要可供选择，全部技能正文不常驻每次请求。

技能上下文使用通用来源身份和显式固定策略。实例化的技能说明及执行约定在所属运行需要时固定，结束后按生命周期退出当前活动投影，原日志可回看。会话级角色、长期记忆与本轮技能各有来源，压缩后仍能识别执行依据。

### 工具范围与权限

allowedTools 是技能请求范围，由宿主与实际工具目录求交集。未知工具在发送前展示缺失原因或拒绝本次调用。技能内容不能修改用户权限、写入完成事实或成为记忆的用户原话依据。

首期默认 `modelInvocable: false`，显式调用先完成端到端验收。后续启用模型发现时，只向模型提供技能名称、适用条件和加载工具，由宿主执行同一校验与日志路径。显式禁用自动调用的技能只接受用户选择。

### S01 验收清单

- 四个内置技能通过正式聊天入口使用真实业务数据，输出可定位来源和结果。
- 缺少输入时使用 Q01，执行进度使用 P01，补充信息通过 I01，长输入遵守已有预算。
- 编辑、导入、导出、重开及重复名称的处理有明确结果。skillId 稳定，重命名不改变历史关联。
- 相对资料读取的路径边界、格式错误、缺资料、不可用工具、模型不支持图片各有可恢复提示。
- 技能改版后，历史运行仍能回放原快照，未来运行使用新 revision。
- 备份范围中纳入用户自定义技能及资料，缺失本机资料时显示可补齐状态。密钥不写入技能包。
