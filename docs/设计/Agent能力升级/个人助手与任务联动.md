# 个人助手与任务联动

> 本轮产品范围。2026-11-21 对照起始提交 `6b8cac8` 与实施前基线 `2b6a809`；表中的缺口均指该基线。当前状态见实施与验收记录。

本文定义产品范围；开工顺序、权限、状态和验收以[个人助手实施任务书](个人助手实施任务书.md)为准。

## 最初目标与当前缺口

2026-09-13 的起始版把 MissionBook 定义为「以人的长期成长为核心的 AI 辅助规划、执行、验证与反思系统」。最早的本地闭环从目标大纲、今日任务到执行和正式材料；长期方向是在此基础上评价、反思、调整下一项任务。AI 可以替用户观察、整理、拟方案；用户的真实行动和掌握程度不能用模型输出代替。历史产品依据见[产品纲领](../../需求文档v1.0/产品纲领.md)，现状以下表和生产代码为准。

| 环节 | 当前工作树 | 本轮要接通的断点 |
| --- | --- | --- |
| 目标 → 日程 | 目标/节点大纲、手动排期、今天/周视图和 Agent 批量安排提案已接通。见[任务与材料](../../架构/前端/任务与材料/README.md)、[排期确认卡](../../../lib/presentation/assistant/operations/assistant_schedule_card.dart)。 | 截到活动通知后，要能在原地核对时间、确认加入，再定位到同一条真实日程。 |
| 日程 → 行动 | 固定/自选任务与执行、到点停止和待确认已接通。见[今天页](../../../lib/presentation/today/today_page.dart)、[任务详情](../../../lib/presentation/missions/detail/mission_detail_page.dart)。 | 系统提醒能告知时间，缺少结合当前用机情况的主动对话和直接返回任务的入口。 |
| 行动 → 材料 → 反思 | 独立记录、材料快照、执行报告和分层总结已有链路。见[记录服务](../../../lib/application/records/record_service.dart)、[执行记录](../../../lib/presentation/missions/record/mission_record_workspace.dart)、[分析服务](../../../lib/application/analysis/analysis_service.dart)。 | 聊天截图与正式材料仍分开；复盘后的下一步要能通过既有提案回到排期或再次尝试。 |
| 对话与观察 | 已有共享 Agent、应用内对象会话与近期接续；Android 截图仍经授权页打开主 Activity。见[授权页](../../../android/app/src/main/kotlin/chat/liuxin/mission_book/AssistantCaptureConsentActivity.kt)、[会话上下文](../../架构/前端/助手与总结/上下文与工具预算.md)。 | Android 跨应用原地会话、前台 App 与时长感知、经独立授权的主动看图仍未接通；近期摘要目前仅进程内复用。 |

判断：目标/任务/材料的事实链已建立，Agent 能做单段问答、规划和总结；还未形成日常可反复使用的「知道现在要做什么 → 帮用户行动 → 依据结果安排下一步」。已有 Android 构建和安装记录不能代替本轮[真机交互验收](../../教学/验收记录/2026-11-17-Android构建交付-0.2.26.md)。

## 同一轮交付的 UI

| 位置 | 交互与状态 | 复用和约束 |
| --- | --- | --- |
| Android 悬浮球 | 点击展开截图、语音、文字。多张图按顺序显示在球上方，可预览/移除；语音回填可编辑。不跳主应用就能发、看流式回复、追问和确认操作。收起、取消截图或可重试的发送失败保留同进程草稿；只有用户显式选择打开会话、日程、任务或记录草稿等导航动作才唤起主应用。 | 共用正常会话、模型和历史，不另建悬浮聊天。主动提醒不抢正在输入的草稿；气泡提供回应、稍后、本次不再提醒及有任务时的「回到任务」。 |
| 助手设置与气泡状态 | 一个「应用使用情况」开关，按需跳转 Android 授权；暂停与恢复可从设置或悬浮菜单操作。悬浮球开启后在主界面和其他 App 均保留。 | 发送悬浮消息时直接读取当前 App 名称与估算时长，交给当前会话模型，不单选模型。后台排期提醒在本机判断，不传历史清单。允许画面搁置，手动截图保留。 |
| 今天与周视图 | 在既有今日安排区域突出「现在」和「接下来」，必要时显示监督状态；点当前项去执行、完成确认或记录，遵从实际阶段。读其他日期时不把现在的手机使用状态贴到那天。活动问答在气泡中显示明确日期、时间段和冲突对象；确认成功后提供「查看日程」，落到对应日期和任务。 | 不加第五个主导航，不另做一套时间轴数据。沿用既有排期冲突和写入确认；只依据已知安排，缺关键时间先追问。无冲突不等于对外部日历或用户空闲作保证。 |
| 任务与目标节点 | 把「我卡住了」「帮我看下一步」做进现有对象助手入口。任务问答带目标、步骤和验收要求；节点有待推进任务时提供真实对象入口，尚未安排则可请助手提出下一步安排。 | 传已保存的稳定 ID 和有界任务上下文，不把步骤默认标成做过，也不让跳转抢占已有会话。安排建议必须走既有提案。 |
| 材料与复盘 | 手动截图可由用户选择「保存为记录」或按现有入口关联任务；发送图片本身不算交材料。执行记录的总结区域加入「跟书祺复盘 / 安排下一步」，可据实际结果提出改期、后续任务或再次尝试，确认后才写。 | 先选归属和预览，再由记录/材料服务提交。主动监督画面不进入草稿、执行材料、聊天附件或长期记忆；观察提醒和用户回复可进入正常对话。评价、用户报告、材料和能力掌握各自独立。 |
| 聊天和历史 | 悬浮回复和 App 内同一会话可见，支持从聊天历史继续；区分主动提醒和用户提问。来源会话有最终可用回合后，下一新会话首次发送才按已有接续设置取最近三个同范围摘要，缺失或更新才生成，跨重启复用。 | 不把收球、退到后台或一段时间没说话当作结束；同会话继续读原消息。源删除、修改或接续关闭须撤下旧摘要；失败不挡聊天，不带图和工具回包。 |

图像化用于表达真实信息：功能图标、图片缩略图、App 图标和时长、时间冲突条、状态标识。移动窄屏、大字和键盘下仍能操作；复用现行暖白/森林绿、间距与减少动效规范。相关联动放现有页面，避免新增一套「个人助手首页」或独立监控统计页。

## 调用边界

```text
已有：任务/目标与执行事实 → 今日/周视图、执行记录、总结
Android 前台信号 → 排期本地判断 → 提醒气泡
悬浮发送 → 现读当前 App 名与时长 → 当前会话模型
规划：悬浮输入/回复 → 共用普通会话 → 已有 Agent 查询与操作提案
已有：提案确认 → 业务服务 → 仓储事务/回执 → 真实页面重读
```

- 原生负责系统权限、窗口、前台信号和采集资源；App 应用层负责判断、会话、用户授权、生命周期及书祺与任务的联动；`agent_core` 不理解 Android、任务阶段或监督策略。不能让后台原生代码直接读写业务库或另起一套任务状态机。
- 监督可自己观察、查询和打断，但不据截图写任务、签到、提交材料或标记完成。悬浮日程操作沿用同一套确认、重读、冲突校验和回执，不能用模型说「已加入」代替成功回执。返回任务读取唯一阶段，`STOP` 后仍由用户报告，不从手机使用情况推导任务结果。
- App 名与时长是系统估计，不声称看到了具体内容。暂停、锁屏、没权限或系统取不到时，不提供这一上下文。主动取样搁置，不建持续录屏档案。
- 此轮不扩大到 App 例外名单/白名单、绕过系统限制、接管其他 App、完整设备使用报表、云同步、新 Plan 数据模型或自动判定掌握。不为这些后续功能预建数据库表和接口。

## 一次验收的三条流程

1. MissionBook 停在设置页后切到别的 App，连续截两张活动图 → 原地问能否参加 → 看到依据和冲突时间 → 确认加日程 → 在主动点「查看日程」之前一直留在原 App；取消不写入，重复确认不重建。未发图能删，取消第二次截图后第一张保留。
2. 开启并授权应用使用情况，在两款不同 App 中用悬浮球问「我现在在哪个 App？」；切换、暂停与恢复后都核对回答不使用过期前台信息。进入并离开 MissionBook，头像持续可见。课堂/专注安排内的本地提醒可稍后或返回真实任务，不要求额外模型。
3. 从任务页问「我看不懂」能根据已保存的步骤解释；结束后只把主动选中的手动截图保存到记录/材料，打开既有总结并提出下一项安排。回放同一会话能找到原消息，开启接续后新会话用近期摘要，重启未变来源不重复生成。覆盖摘要失败和监督不可用时正常任务流程仍可用。
