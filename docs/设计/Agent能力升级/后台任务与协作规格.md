# 后台任务与协作规格

对应 J01、R01、A01，后续扩展为 E01–E04。核心身份、交互和队列契约见[交互与会话规格](交互与会话规格.md)。

## J01 可查看、停止和恢复的长任务

### 用户结果

用户可以启动较长的资料整理或分析，离开聊天查看其他页面，随后回到任务查看状态和输出。任务有完成、失败、停止、等待问题及等待结果核对等真实状态，并能定位到关联会话。

首期长任务采用已有受支持的读取、搜索和分析工具完成，逐步接入业务工具。后台与前台均有明确的运行拥有者，业务写入沿现有权限和事务处理。

### 作业模型

| 字段 | 说明 |
| --- | --- |
| jobId | 宿主生成的稳定作业身份 |
| sessionId / runId | 实际执行会话与运行关联 |
| kind | analysis、research、summary、childAgent 等已实现作业类型 |
| title / input | 用户可读任务名与持久化输入 |
| source | 用户启动、技能、父会话或后续定时触发 |
| status | queued、running、waitingForUser、needsReconciliation、completed、failed、cancelled、interrupted |
| createdAt / startedAt / finishedAt | 实际生命周期时间 |
| progress / resultRef / error | 有来源的进度、结果定位与可读错误 |
| requestedStop / checkpoint | 用户停止事实和可恢复位置 |

当前会话日志承接执行事实。需要跨会话快速列举作业时可以新增可重建的索引，执行原始事实仍有唯一拥有者。新增表、版本和备份结构在实现该用户路径时一起提交。

### 事件契约

J01 实现时建立 job_created、job_status_changed、job_checkpoint_saved 和 job_result_published。事件携带 jobId、sessionId、runId、revision，状态变化还携带预期前态与原因，结果携带 resultRef 与实际用量。可重建索引只接受已提交日志派生，索引写回失败可由原日志修复。

作业创建与会话建立使用同一稳定 jobId 协调。若跨存储步骤执行，先保存创建意图，重试按该身份找回已有会话，再发布可执行状态。

### 调度与生命周期

```text
页面/技能创建作业 → 持久化输入与排队状态
  → 应用级调度选择可运行作业 → 取得对应 SessionHandle
  → 运行时执行 → 日志提交 → 作业投影/索引刷新
  → 状态通知 → 页面回看真实结果
```

- 将“当前正在显示的会话”与“正在执行的会话”分别管理。打开历史不会直接关闭另一作业仍在使用的运行时和模型客户端。
- 同一 sessionId 仍只有一个写拥有者，统一通过现有租约与 SessionHandle。多个页面和作业观察相同的只读投影。
- 作业调度与已有总结队列协调。前台用户请求、后台资料任务和总结请求有明确优先级，取消后台分析的现有语义须逐一核对。
- 建立可等待的 close，先停止派发、等待在途操作结算或标记未知、持久化最终状态，再关闭模型客户端、句柄和数据库。
- 阻塞于问答的作业展示问题入口，答复由 Q01 路径回到其实际会话。业务操作需要确认时通知相应确认卡入口。

### 故障与恢复

1. 创建失败保留输入，重复 jobId 返回同一作业。
2. 用户停止记录 requestedStop，并取消当前协作请求。已提交写入检查回执，结果未知进入 needsReconciliation。
3. 进程终止后，running 恢复为 interrupted。已完成 checkpoint 和操作回执是继续依据。
4. 用户显式停止的作业不会因重新进入 App 自动启动。interrupted 提供恢复、查看已完成结果和取消入口。
5. 无副作用的分析可以从最后完整边界重试，重复模型调用的用量保留。写入不得以新身份重做。
6. 已生成结果先持久化再发送完成通知。通知点击通过 jobId/sessionId 定位，重复点击打开同一任务。
7. 导入备份或切换工作区时关闭旧调度，恢复旧 running 为可恢复状态，避免从恢复数据直接重放执行。

### 平台范围

App 内跨页面运行由应用级拥有者实现。Android 切后台、进程被系统终止、设备重启、Windows 退出与 Web 标签页关闭分别验证。需要持续运行时，接入实际平台允许的前台服务/通知和生命周期，界面说明经验证可支持的状态。

单纯在 Dart 中保留 Future 只能作为进程存活期间的行为证据。设备测试记录中分别写明前台、切后台、锁屏、杀进程和重启结果。

J01 验收覆盖两会话导航、同一会话写租约、模型资源释放、创建重复、停止竞态、进程中断、备份恢复、等待追问、未知业务结果、通知路由和用量汇总。

## R01 独立只读工具受控并发

### 并发条件

将已注册工具的副作用与依赖整理为宿主可检查的元数据。只有真实无副作用、输入完整且结果互不依赖的读取才进入并发组。业务写入、交互等待、进度写入以及先后依赖的读取按确定顺序执行。

当前工具的 `readOnly` 声明先逐项审查。某些“读取”可能包含维护、下载、缓存或状态改变，必须按真实实现分类。与 Mission 时间线有关的维护调用通过已有显式入口进入。

### 执行规则

- 单个模型响应中的工具调用保留原 callId 和顺序。并发执行结束后，工具结果按原调用顺序持久化或按可验证的等效完整组发布。
- 每个调用在实际开始前记录开始事实，并有独立取消与失败结果。整组结束前不发送下一次模型请求。
- 一项读取失败不会让已成功结果丢失。是否继续其他读取由其副作用和取消状态决定。
- 开始记录提交失败时不执行对应调用。组内结果持久化失败后停止后续模型请求，恢复时按日志区分已完成与尚未结算。
- 网络连接、图片解码、数据库查询和结果文本分别计入已有上限与资源拥有关系。并发不会放宽 16 KiB 工具结果上限。
- 主会话、子智能体和后台作业共同受运行时资源预算约束，避免各自按独立最大值叠加失控。

### 验收

使用可控制完成时刻的工具验证并发确实发生、最大在途数、结果顺序、部分失败、取消、日志失败及写工具串行。再使用正式业务查询链验证快照和阶段派生结果。性能报告给出同一工作负载的串行/并发耗时与峰值资源，依据实测调整默认值。

## A01 子智能体分工

### 首期用户场景

主助手整理复杂计划时，可以建立“查询已有安排”“归纳材料”“检查方案冲突”等子工作，显示每项状态。主助手收到真实完成结果后合并分析，并按现有业务工具处理最终操作。

初版采用最大深度 1、同时运行 2 个子会话、只读分析权限。这是本计划建议的可交付范围，后续允许用户明确扩展写入能力时再接通相应授权与事务路径。

### 父子关系

| 对象 | 必需信息 |
| --- | --- |
| ChildDescriptor | childSessionId、parentSessionId、parentRunId、taskId、label、mode、toolScope、modelProfileId |
| ChildTask | 输入任务、引用数据范围、输出约定、预算、状态、jobId |
| ChildResult | taskId、childSessionId、status、summary、sourceRefs、resultRef、usage、error |
| Delivery | deliveryId、parentSessionId、parentRunId、childTaskId、resultRevision、deliveredAt |

父子身份由运行时创建和校验，模型只提出任务与所需范围。子会话有自己的日志、模型请求和预算，记录父任务来源。子会话页面通过真实父子关系读取和操作。

A01 建立 child_task_created、child_task_status_changed、child_result_published、child_result_delivered 事件。父记录保存子任务身份及投递事实，子日志保存实际执行和结果。所有事件关联 taskId，结果投递再关联稳定 deliveryId，跨日志恢复依据这些身份协调。

### 创建、执行、汇总

1. 主模型调用创建子任务工具，宿主校验工具范围、深度、并发和总预算。
2. 持久化父任务描述，建立子会话并注册 J01 作业，创建中断可按同一 taskId 重试并找回子会话。
3. 子会话只收到任务必要上下文、明确的数据引用和允许工具。父会话的整段聊天与 Key 不直接复制到子任务输入。
4. 子任务执行结果持久化后形成结构化完成记录，父会话通过稳定 deliveryId 接收一次投递。
5. 父会话正在运行时，结果以系统来源的补充输入进入其下一安全边界。父会话空闲时显示待汇总结果，按原任务授权继续该工作。
6. 主助手汇总时保留来源与失败项，不能把子任务的草稿结论直接写成用户陈述或业务完成事实。

### 权限、预算与停止

- 子任务允许工具为父会话能力、任务范围与初版只读集合的交集。子任务的模型输出不能提升该范围。
- 每个子任务的输入窗口和输出预算独立计算，费用/用量回归父任务汇总，摘要和重试也计入。
- 父任务停止向仍运行子任务传递取消。已经完成结果保留，尚在退出的任务显示实际状态。
- 用户已经停止父任务时，迟到结果可供回看，不能自动重启父任务或消费用户队列。
- 子任务失败、超限、缺模型和工具不可用产生明确结果，父任务可以缩小范围或自己接续。
- 超大结果沿已有有界文本返回，完整产物通过 resultRef 分段读取，避免占满父会话窗口。
- 后续支持可继续子会话时，通过父子地址路由追加输入，不能绕过拥有者再打开一个写句柄。

### 原始事实与恢复

父任务与子会话建立可能跨多个存储步骤。使用稳定 taskId 以及创建状态重查，完成父子关系发布后才允许子任务执行。异常残留会话在索引中可识别，不能重复建立同一子任务。

结果投递的领取与确认有可恢复记录。父会话接受结果后、作业索引更新前退出时，重开依靠 deliveryId 去重。备份包括父子关系、输入与结果引用，恢复后子任务按 J01 的 interrupted 规则处理。

A01 验收覆盖并发上限、嵌套拒绝、只读工具范围、两个子任务相反的完成顺序、部分失败、父停止、迟到结果、创建中断、重复投递、重开和备份恢复。至少一条正式业务链展示父任务汇总真实来源。

## 后续 E01 定时 AI 作业

参考 `features_api.dart` 的 schedule 模型和目标会话选择，结合 J01 提供每日复盘、每周计划整理等用户主动设置的 AI 工作。

实施时明确区分本地提醒触发、AI 模型实际执行、用户确认和业务结果。事件触发使用稳定 scheduleId 与 occurrenceId，对重复系统通知和重启补发去重。时间表达包含用户时区，夏令时、错过触发、断网、设备关机及重复唤醒分别定义行为。

执行时选择既有会话、新建单次会话或按周期分组，结果进入可查看的作业页。停止和删除定时工作有真实持久结果。任务 STOP、END 和材料截止处理使用现有服务与派生规则。

先实现用户设置一次性与每日/每周工作并通过真实设备验证，再按需求引入复杂 cron。设备无法保证的唤醒场景需要展示最后触发和错过原因，不能显示伪造的准时执行记录。

## 后续 E02 第三方工具与插件界面

参考插件的能力声明、工具注册、原生结果卡片、配置和失败诊断。实施顺序为一个真实扩展工具 → 类型化结果呈现 → 生命周期与配置 → 按需求增加分发。

扩展须声明运行位置、所需资源、输入输出和副作用类型，宿主提供实际授权。第三方内容不能修改三档权限或直接持有 AppDatabase 写连接。若采用 MCP 接入，先核对目标服务器、传输和工具协议并实现实际连接，MCP 支持作为独立适配器验收。

任意外部 Dart/JS 代码执行与插件市场涉及运行时、分发、升级和隔离。本轮源码调查未完成这一整条服务端调用链，E02 实施前补齐相应调查，按选定真实工具建立最小路径。

## 后续 E04 Android 手机操控

参考原生无障碍、截图、动作结果、显式停止和技能录放。先选择一个授权清晰的具体用户流程，核对代码来源与许可、Android 服务生命周期和权限入口。

执行过程有可见状态和可用停止入口，工具结果基于真实屏幕/动作响应。模型规划、动作完成与目标应用最终结果分别核对。无障碍服务断开、屏幕锁定、后台限制与用户手动操作发生时给出实际可恢复状态。

此项涉及 Android 专用运行和实际设备验证。Windows/Web 页面应呈现实际平台可用能力，不能调用空实现报告成功。
