### 特别影响实施的源码事实

1. `AssistantSettingsStore` 和安全存储实现只接受固定配置与凭据名。多服务功能须修改解析、保存、选择、清除和备份恢复全部入口。
2. `AgentRuntime._attach()` 和导入路径会立即检查主模型与摘要模型是否存在。服务删除后历史查看需要有明确的配置缺失状态及只读打开能力。
3. `AgentTool`、`ToolOutput` 当前为 `final class`，`ToolHandler` 返回 `FutureOr<ToolOutput>`。结构化等待要统一调整结果契约及调用方，不能假定已有可继承的交互工具。
4. `SessionState` 对业务日志执行严格解码。新事件必须覆盖复制、回放、恢复、导入导出与压缩，不能用 `ignorable` 跳过影响执行的事实。
5. 当前运行中发送会被 `AssistantSessions.sendMessage` 拒绝。队列功能需要修改核心消费时机及应用层状态。
6. 工具的当前派发顺序为串行。是否并行须依据真实依赖和副作用，不由 `Future.wait` 替换整段循环。
7. 当前本机资源备份可按勾选包含助手设置与 API Key。凭据相关改动同时检查 `local_resources_io.dart`、Web 实现与资源应用路径，不能沿用旧注释推断 Key 永不进入备份。

## dsh-Go 能力的实际拥有者

```text
Flutter 页面与状态
  → packages/dsh_client 的类型化 API
    → HTTP / SSE / mux 连接
      → JS 桥接及 DSH 插件、引擎服务
        → 模型、工具、任务和会话运行
```

`dsh_client` 提供客户端协议，服务端会话、问题等待、队列、技能执行和子智能体运行由对应引擎服务承担。MissionBook 采用进程内 Dart 核心，迁移工作同时需要应用页面与核心执行语义。

## 复用与直接迁移的边界

- 优先复用 MissionBook 已有的会话、工具、压缩、权限和业务存储逻辑，围绕真实缺口增加能力。
- 页面交互、不可变数据结构、事件投影和测试场景适合参考。Riverpod provider、dsh RPC、mux 会话地址与桥接调用需要映射到本项目控制器和进程内运行时。
- 引擎侧能力须找到真实服务实现或协议后再实现。Flutter 客户端某个方法存在，只能证明其具有该调用入口。
- dsh-Go 根 `LICENSE` 标注 AGPL-3.0，`THIRD_PARTY_NOTICES.md` 记录不同来源代码与素材，其中手机操控包含经作者许可使用的来源。直接引入时逐文件记录实际授权、来源与声明，不能仅凭 Dart 包目录或某个文件的 MIT 片段注释认定整个功能可按相同许可复制。
- 对插件市场、手机操控、DSH 服务端内部调度和全部协议扩展，本轮为入口级评估。后续工作包在相应范围补齐端到端源码调查与设备验证。
