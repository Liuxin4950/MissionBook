## “我的”应该展示什么

“我的”承担个人资料与行动回顾，回答“我是谁、最近做了什么、接下来从哪里继续”。完整排期属于今天，完整目标树属于目标，逐项执行与材料属于历史，系统选项属于设置。

1. **本机资料**：称呼、可选简介和编辑入口。背景插画只做轻量装饰，不占整页主视觉；未实现账户与同步，不展示虚构的会员、同步状态或云端头像。
2. **真实行动概览**：进行中目标数、已结束任务数、实际专注时长。结束任务不等于完成目标，历史补报没有 START，不计入实际 Focus。读取失败显示重试，不冒充零值。
3. **最近的行动**：少量最近结束记录，直接打开正式执行报告；详细筛选和全量浏览仍由历史页承担。现有实现有记录才展示，不用示例填满。
4. **继续推进的目标**：少量进行中目标的真实入口，帮助回到已有工作；此处不重复完整大纲，不发明完成率或掌握度。
5. **管理入口**：右上设置统一管理模型与语音、权限、提醒和导出。数据保存在哪里、导出了什么，必须准确表达。

空数据时不为了填满屏幕制造统计曲线、连续打卡或 AI 评价。后续若增加周/月回顾，应先明确统计口径、时间范围及历史补报如何展示，再决定布局。本轮先完成标题移除与已有事实的展示整理，没有新建评分、账号、习惯或总结系统。

## 布局与交互约定

- 是否分栏依据内容区实际宽度，并考虑文字缩放；不能只判断设备名称或窗口总宽。
- 320/390 宽采用单列；768 宽优先保留正文；桌面助手工作区使用会话侧栏。缩放保留输入、附件与当前会话，不重新创建控制器。
- 三个主页面不再重复显示导航标题。历史标题本轮保留；二级页面保留返回按钮和明确标题。
- 常规内容卡沿用统一圆角、森林绿小面积强调、暖白背景及字号令牌。列表内动作使用 labelMedium，整页主操作才使用 labelLarge。
- 导入保留先检查预览、再确认保存的流程；不自动改写字段大小写、忽略未知字段或把任意 JSON 猜成目标。异步检查只接纳最后一次结果，避免旧错误控制新预览。
- 助手设置保存期间禁止修改凭据，离开未保存设置时可继续编辑或放弃；保存与实际网络连通性分开表达。

## 导出内容与边界

`database.sql` 保留全库、索引、触发器与 schema 版本；`assistant-conversations.json` 提供同一快照下的会话索引与按序原始日志；`attachments/` 保留正式材料；`manifest.json` 和 `README.txt` 说明格式与范围。不导出安全存储中的 API Key、未发送草稿、本机资料、缓存与提醒偏好。缺少正式附件则整次导出失败，源数据保留。

新增 JSON 是可阅读的数据副本，不是目标计划模板，也不代表 App 已有完整恢复入口。浏览器只报告已交接下载，不声称操作系统已经保存成功。

## 同日追加：侧栏对齐、日期过渡和会话入口

用户复查指出侧栏没有对齐，日期滑动仍看不到动画，助手侧栏底部搜索突兀且设置入口重复。

- **缺失动效的实际原因**：浏览器实测 `prefers-reduced-motion: reduce` 为真，Flutter 的减少动效状态使 `AppMotion.resolve` 返回零时长；此前只验证了测试环境里的默认动效，不能证明当前浏览器播放了动画。此外，旧实现清空旧卡片后只让新内容位移 40 像素，日期栏没有参与。
- **日期过渡（按用户后续澄清修订）**：用户需要选中背景块移动，不接受正文整体平移。最终日期栏共用一个绿色背景块，点击或滑动换日时由原位置连续移动到新日期；快速反向选择从当前动画位置继续。正文保持原位，按成功加载的日期交叉淡化；等待期间保留旧画面但禁用交互和读屏，同日刷新保留组件状态。取消整体平移、跟手位移和分段退场/入场。
- **本机动效选择**：设置新增“界面 → 页面动效”，提供跟随系统、开启动效、减少动效。默认跟随系统；显式开启只覆盖本应用，不修改操作系统设置。原生使用独立偏好文件，Web 使用本地浏览器存储；不进入业务表和备份。保存失败不冒充已生效，慢读取不能覆盖用户的新选择。
- **主导航对齐**：桌面品牌左边缘与导航图标左边缘对齐，底部助手图标中心与导航图标中心对齐；平板紧凑栏保持居中。
- **助手入口**：宽屏搜索收进“会话”标题旁，移除底部两枚文字按钮；桌面顶部不再重复显示新会话与历史动作，设置仅保留右上角。窄屏无侧栏时，顶部恢复新会话、历史和设置。

追加验证以文末最终复查为准。此前“有动效”的结论不能替代当前浏览器的动效偏好与共享背景块中间帧验证。


## 同日追加：目标分类与表单助手能力

- 各分类共用 `AppJourneyHero` 的图文结构、纸艺路标、图片比例、标题和边距；已搁置/已达成/已放弃不再套入 792 宽的阅读限制，空态与分类栏等宽。创建与导入只在进行中显示，其他分类提供“查看进行中”。390、768、1366 宽的测试直接核对空态左右边界和宽度。
- 路标采用内置 image_gen 生成，透明 PNG 已存入 `assets/illustrations/goal-waymarker.png` 并登记资源；[最终提示词与生成方式](../ui设计手册/assets/ui-feedback-20261030/goal-waymarker-generation.md)。图片只装饰，不替代状态文字。
- **当前表单不能让助手自动补全**：任务名称等未保存输入只在 `MissionFormPage` 的控制器内；助手入口只传递已保存任务、目标或全局上下文。`mission_create` 可创建自报任务，`mission_update` 可修改有稳定编号的未开始任务，没有读取当前表单草稿或应用字段补丁的工具。
- 若后续实现表单协作，应采用“读取当前草稿 → 提议字段差异 → 用户确认 → 回填同一表单 → 用户创建”的流程；必须保留用户已有字段，检测提议后继续编辑的冲突，并在关闭表单后失效。此项属于已识别缺口，本轮没有声称落地，也没有用另建任务冒充回填。
