## 全量回归中补充发现

来源删除与材料引用的双后台连接测试暴露 BEGIN IMMEDIATE 的 BUSY 竞争。异常由 DriftRemoteException 包装，单查 SqliteException 会漏掉真实结果码。

AppDatabase.transaction 现在只在事务正文尚未进入时，对 BUSY / LOCKED 最多额外重试三次，并以 25、50、100ms 退避；底层原有 busy_timeout 仍保留。正文或 COMMIT 已经执行过则不重试。目标包导入不再按错误文案重放整份导入，统一使用这一入口。

[database_lock_recovery_test](../../test/data/database_lock_recovery_test.dart)验证短暂锁竞争结束后正文只执行一次，以及正文抛 BUSY 时原样失败并回滚；[record_snapshot_concurrency_test](../../test/data/record_snapshot_concurrency_test.dart)继续验证真实双连接同时删除来源与提交材料的两种合法结果。

## 已证实的误报与保留取舍

| 原意见 | 处置依据 |
| --- | --- |
| validateUrl 放过内网，生产 fetch 可直接访问 | 生产注入 publicHttpClient，解析结果会被校验并固定 IP 连接；Web 无法校验时拒绝抓取。既有 IPv4/IPv6、DNS 和重定向回归保留，本轮未放宽限制 |
| 必须把历史日期全改为排期时区 | 设备历史日、用户报告日和日程业务日为不同事实；保留现有产品口径和跨时区测试 |
| 当前开发期缺数据库迁移是缺陷 | schema 16 仅当前结构是明确要求；继续显式拒绝旧库，不自动删除数据 |
| AppShell 截图去重是死码 | await 原生确认失败时标记保留，重试可以只补确认，保留现有恢复逻辑 |
| 同一实例下载重试会被旧 finally 删除新文件 | 未完成下载由同一个 Future 共享，清理后才可重启；保留该串行边界，只修清理错误遮蔽 |
| scheduled_end 只覆盖单任务 | 已有相邻双任务成功路径；本轮新增后续 START 失败的组合 |
| 没有指定文件名就说明计时没有直接测试 | 旧仓储测试已直接断言 calculateExecutionTimes；本轮新增独立文件完善定位和边界 |
| 查询无排序就必然选错有效报告 | 合法替代链尾项唯一时不依赖顺序；本轮统一排序增强确定性，没有改写有效报告语义 |
| 多处写锁 SQL 习语不同就不具备跨连接互斥 | 事务由同一连接持有；驱动实际使用 BEGIN IMMEDIATE，保留现有显式取写权限步骤，不建立新的锁框架 |
| blocked 字符串必须改为领域状态 | 它是 planMissions 回执协议的状态值，保留在解析边界；不新增可写任务阶段 |

性能优化明确针对已找到的重复工作，没有证明或承诺设备帧率、长会话峰值内存或任意规模下的延迟。新增消息首次写大集合、会话打开重放、数据库快照读取仍有随数据规模增加的成本。
