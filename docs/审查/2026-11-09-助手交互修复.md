# 2026-11-09 助手交互与截图会话修复

依据本轮实际源码、可控模型与内存数据库回归。用户报告的思考/正文内部滚动、流式 Markdown 原文显示及系统截图会话冲突作为直接修复目标。

## 已落地行为

| 路径 | 修复 |
| --- | --- |
| 思考和正文 | 移除普通处理过程、长正文及展开文本附件的内部纵向限高；随聊天主页面自然展开。 |
| 长正式回复 | 达到 4,000 字符后复用整篇 AST，将顶层块交给外层聊天列表按可见范围构建，保持连续背景和首尾圆角；复制按钮仍复制整条原文。外层 SelectionArea 承载切片间选择。 |
| 实时 Markdown | 正文、思考、浮窗共用 Markdown 渲染，沿用约 66 ms 快照合并；流式版本不进入全局 AST 缓存，未变节点和样式复用。 |
| 顺序与展开 | 连续过程块按原始顺序分段；主聊天和浮窗共用 AssistantTurnContent。手动展开思考后保留过程，展开暂停跟随；切换前按草稿身份记录阅读位置。 |
| 失败/取消/重试 | request_failed 保存正文与思考片段；InterruptedModelAttempt 单独回放，标明未完成和重试，不进入 transcript/contextMessages。 |
| 工具结果 | 查询确认显示完整参数；非对象 JSON/纯文本原文回退；长 JSON 可展开完整数据；工具结果展开按调用身份保留。 |
| 系统打开/截图 | prepareExternalEntry 等待导航后接续当前会话，不强制从运行中的对象会话切到全局；恢复已存在的聊天 Route，不重复持有会话。 |
| 被覆盖的聊天 | 普通预览、详情返回原聊天；上层存在不允许返回的未保存编辑时保留编辑，截图仍进入聊天草稿并提示。 |
| 重复截图通知 | AppShell 消费期间再次收到请求时排队；交付成功后才确认删除原生缓存。 |
| 草稿 | 用户输入即时同步草稿；发送准备失败保留原输入和期间新草稿。已建立空壳后失败清理时，把期间草稿带回原身份。原输入与新草稿冲突时提供独立恢复入口。 |
| 附件选择 | 固定选择发起时的草稿身份；返回后若已切换会话，文件加入原草稿并提示，不误加到新会话。 |
| 会话维护 | 打开、新建、删除、重命名共用导航串行入口；维护期间拒绝发送。原关联对象已失效时显示提示，不沿用旧对象引用。 |
| Android 主入口 | MainActivity 使用 singleTask 和应用默认任务归属；悬浮入口及截图返回共用 assistantIntent。授权 Activity 单独使用 applicationId.capture 归属且不进最近任务，避免授权阶段把主应用带到被截画面前。 |

```text
系统打开/截图
  → Android：复用 MainActivity → onNewIntent → AppShell
  → Flutter：等待会话导航 → 接续当前会话/草稿
  → 图片校验并交接 → 恢复原聊天 Route / 创建聊天 Route
  → 成功后删除原生截图缓存

模型增量 → 合并活动快照 → 共用时间线 → Markdown
模型完成 → 原消息和块；长正文进入外层列表
模型失败 → 未完成尝试投影（可回看，不回传模型）
```

Android 任务复用依据 [Android 官方任务栈说明](https://developer.android.com/guide/components/activities/tasks-and-back-stack)。当前仍只有一个运行时会话；修复截图入口与任务栈冲突不需要引入多会话并发。工具权限、事务和未知结果回执核对继续由原服务处理。
