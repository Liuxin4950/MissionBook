# 2026-11-06 长期使用体验与质量审查

本审查依据 2026-11-06 当前工作区源码。目标是区分单次请求保护、长期数据增长、交互入口和系统集成边界；不把设计计划视为已实现功能。

## 当前结论

| 领域 | 当前已有 | 仍存在的问题 | 判断 |
| --- | --- | --- | --- |
| AI 上下文 | 每次请求按输入预算估算并可自动压缩；默认在可用输入预算约 80% 触发，目标约 50%，保留最近消息并保护完整工具组；每次压缩摘要请求上限已从 8 降为 3；累计供应商用量和本地估算可查看。 | 摘要仍会产生额外用量；本地估算不是账单；压缩不释放完整原始会话日志；历史清单仍无分页或保留策略。 | 单次请求和单次压缩都有上限；长期存储仍需分页与用户主动清理，不能静默裁切原始日志。 |
| AI 表达 | 回答支持 Markdown、链接、图片、表格及受校验的柱状图/折线图；流式回答在完成前使用纯文本布局。长回复按块惰性构建，AST 使用有界内存缓存。 | 暂无流程图内容类型；单个大型 Markdown 块仍整体布局；Android 200 轮强制跳回仍测到约 435 ms UI 峰值。 | 图表协议和原生绘制已接通；继续拆清外层长列表定位与块渲染成本，并验证模型生成、多图混排、窄屏和设备表现。不能执行模型输出的脚本/HTML。 |
| AI 入口 | 任务详情、执行页、目标详情和记录列表有上下文入口；应用内截图和 Android 跨应用气泡可打开助手，系统单帧截屏经授权后预填助手草稿。 | Android 与 Flutter 实现尚未在 HyperOS 3/4 真机验收；Windows 托盘/热键入口仍没有；撤权、取消和生命周期需设备验证。 | Android 首版代码链路已接通；先做目标设备验收，再独立实现 Windows 托盘/热键入口。 |
| Android 桌面组件 | 有常驻提醒和澎湃 OS 3 超级岛的通知适配。 | 没有 Android AppWidget provider/receiver/metadata；超级岛不是桌面组件。 | 适合先做只读今日/下一个安排及显式快捷入口的原生小组件。 |
| Windows / 跨应用截屏 | 有设备能力通道与主应用窗口。 | 没有系统级悬浮窗、全局热键或外部窗口截图接入。 | 与 Android 悬浮层分开设计和验收，不能共用一个 Flutter overlay 假装完成。 |

## 代码证据

- 上下文压缩：`packages/agent_core/lib/src/context/context_compactor.dart`；默认策略见 `packages/agent_core/lib/src/models/configuration.dart`。压缩结果用于后续模型上下文，摘要调用用量被记录；原始日志仍通过会话存储保留。
- 会话历史：`lib/data/assistant/drift_session_store.dart` 和 `lib/presentation/assistant/assistant_history_page.dart`。当前事件日志按会话追加，历史会话清单没有分页/保留上限。
- 文本渲染：`lib/presentation/assistant/assistant_markdown.dart`、`assistant_markdown_cache.dart`、`assistant_markdown_chart.dart`；长回复逐 GFM 顶层块惰性构建并复用有界 AST，图表仅接受受限 JSON 并由 Flutter 原生组件绘制，尚无流程图渲染器。
- 应用内入口：`lib/presentation/assistant/assistant_launcher.dart`、`assistant_screen_capture.dart`、`lib/app_shell.dart`、`lib/presentation/records/records_page.dart`。页面截图通过 Flutter `RepaintBoundary` 获取；Android 原生悬浮和投屏桥接在 `android/app/src/main`。
- Android 平台能力：`AndroidManifest.xml`、`MainActivity.kt`、`AssistantOverlayService.kt`、`AssistantCaptureConsentActivity.kt`、`AssistantScreenCaptureService.kt`。悬浮窗与单帧 MediaProjection 代码已接入，尚无 AppWidget provider/receiver/metadata。
- Windows 平台能力：`windows/runner`。当前是主窗口与设备能力通道，没有托盘 AI、全局热键或截图工作流。

## 建议实施顺序与验收

1. **助手回答体验**：长回复已采用按块惰性构建和有界 AST 缓存；相同隔离 Android profile 的滚出跳回 UI 峰值从 20 轮约 115 ms 降至 41 ms、200 轮约 587 ms 降至 435 ms，仍超过单帧预算，且该强制跳转包含外层消息列表定位。主机回看挂载元素从约 18,132 降至 1,883。柱状图与折线图结构块现已接通，输入限制图表类型、点数、字符串长度和数值范围；无效数据保留为可选择文本。专项用例 3 项通过。下一步分离真实拖动与跳转成本，验证模型生成、多图/表格混排、主题/字号变化和设备 profile。
2. **跨页面提问**：应用内截屏与 Android 原生气泡、显式投屏授权、单帧捕获和助手草稿交接已接通；图片仍经现有预览和用户主动发送。下一步在 HyperOS 3 手机及 HyperOS 4 平板检查授权返回、系统取消、投影停止、方向变化、冷/热启动和图片可读性。Windows 入口独立处理。
3. **成本与数据寿命**：把请求用量、摘要请求成本和本地估算误差分开说明；会话历史分页；增加由用户主动触发的数据清理并说明备份/删除边界。禁止上下文压缩暗中删除可回看的原始会话。
4. **Android 桌面组件**：原生 AppWidget 显示当天重点和下一个安排，以明确的 deep link 打开任务或助手；小组件更新读取有界本地快照，不调用 AI、不持有任务写入逻辑。澎湃 OS 3 手机与澎湃 OS 4 平板分别做 Launcher、触控、尺寸和刷新验证。
5. **系统级入口**：Android 代码已实现显式悬浮 opt-in、一次性 MediaProjection 截屏和取消清理，HyperOS 真机验收尚缺。Windows 仍需单独实现托盘/热键/截图。两端均需覆盖撤权、后台停止、锁屏、应用升级和取消发送。

## 验证边界

本文件是源码审查和实施顺序，不代表上述新能力已交付。Android 系统级截屏与桌面组件、Windows 桌面入口必须分别由目标设备验收。成本显示中的本地 token 估算不能替代供应商账单。
