# UI 统一与首次体验研究（2026-11-16）

> 本文记录 11 月 16 日首轮。新手引导、封面及响应式布局已于 11 月 17 日重做，现行实现见[后续验收](2026-11-17-新手引导与封面.md)及[全局样式](../架构/设计/全局样式/README.md#首次体验与媒体上下文)。

## 目标与范围

本轮不是重新设计整个产品，而是把三类容易割裂的入口拉回现有 MissionBook 视觉系统：

1. Android 跨应用助手的长截图控制条；
2. 应用内拍照取景和拍照后失败恢复；
3. 冷启动品牌页、第一次打开的新手引导及原有品牌封面。

任务、目标、记录、助手正文仍沿用当前浅色主题、暖白表面、森林绿主操作和纸张/路径插画，不建立另一套颜色或圆角体系。

## 研究依据

### 现有产品约束

- 全局令牌位于 `lib/core/theme/`：背景 `#F7F8F5`、卡片白、森林绿 `#244D3D`、主操作最小高度 52、普通触控最小 48、圆角按 4/8/12/16/20/24 分层。
- 当前已有 `AppMotion`、`AppSectionCard`、`AppJourneyHero` 和透明背景插画，首次体验应复用它们的节奏、表面和品牌资源。
- 相机业务状态不能因视觉改造改变：点按对焦、双指/滑杆变焦、后台释放控制器、照片保留后重试和全屏自动确认仍由 `PhotoCapturePanel` 负责。
- 长截图业务状态不能因视觉改造改变：系统授权、自动轮询采集、控制条移除后取帧、最多 12 屏、拼接失败和投影释放仍由原生服务负责。

### 外部设计规范

- Material 3 将主色用于最重要的操作，将次级角色用于不需要抢占注意力的选择；因此拍照只保留一个中央主快门，长截图只突出“继续/完成”中的当前可用动作。
- Android 大屏建议按窗口尺寸在底部导航和导航栏/侧栏之间切换，而不是把紧凑尺寸的控件原样放大；本项目已有 `AppLayout` 断点和侧栏实现。
- Android 无障碍建议交互目标至少为 48 × 48dp；原生控制条和 Flutter 相机操作均保留这一底线。
- 相机类产品的基础操作模型是：取景、点按对焦、缩放、明显的中央快门、拍后预览/重试。已有相机能力保留，视觉上改为更接近这个模型。

## 统一设计决策

### 1. 普通内容与媒体内容分层

普通页面继续使用暖白背景、白色内容卡、森林绿主操作；相机/屏幕捕获的图像区域继续使用黑色媒体画布，以保证照片和屏幕内容对比度。媒体画布上的操作不再直接使用普通页面按钮，而是使用：

- 顶部 48dp 圆形返回/重拍按钮；
- 底部圆角操作面板；
- 面板内仍使用全局品牌绿和文字层级；
- 图像上的提示放进半透明表面，不把长句直接压在画面上。

这不是第二套主题，而是同一套颜色令牌在高对比媒体上下文中的反转使用。

### 2. 长截图控制条

原控制条使用原生默认 `Button`，颜色、内边距和层级与 Flutter 页面不一致。本轮改为原生实现的 Material-like 控制面：

- 浅色圆角面板，与 MissionBook 的暖白/纸面保持一致；
- 顶部说明和“已采集 N/12”状态胶囊；
- 至少 48dp 的完成、取消动作；下一帧由服务自动轮询，不要求用户逐屏操作；
- 当前不可用动作降低透明度，而不是删除，避免用户不知道流程还有下一步；
- 采集帧前仍先移除面板，控制条不会写进截图；
- 不引入自动滚动或无障碍权限，用户自由滚动、服务自动检测变化。

### 3. 软件拍照

全屏拍照改为更接近主流相机的操作布局：

- 顶部为圆形返回和失败后重拍；
- 底部统一面板承载倍率滑杆和三个动作位置；
- 中间为白色外圈 + 品牌绿内圈的中央快门；
- 左侧选择图片，右侧在取景时为“不记录图片”，失败预览时为“重拍”；
- 原有全屏自动确认语义不改变：成功仍交给调用方，失败保留同一张照片并显示“重试保存照片”。

### 4. 开屏与第一次打开

开屏不伪造业务进度。它只承担品牌识别、资源装配等待和减少动效适配：

- 使用现有 `journey-garden-v2.png` 作为底部品牌场景；
- logo、品牌名和短标语形成稳定锁定；
- 使用不承诺百分比的线性指示器；
- `MediaQuery.disableAnimationsOf` 时直接到最终状态。

首次引导为三页，可跳过且不在引导中申请权限：

1. 今天：先开始一次真实行动；
2. 目标：把目标拆成路径和任务；
3. 助手：文字、语音、拍照和截屏进入同一条会话。

是否完成引导只存本机 UI 偏好 `onboarding_v1.txt` / `mission_book.onboarding_v1`，不进入任务数据库，也不影响备份恢复和业务事实。

## 用户反馈后的二次收整

首轮实现虽然已经统一了颜色和控件语义，但用户实际查看后指出：相机页的长条变焦控件和新手引导仍然“像拼出来的”，没有达到优秀相机/引导产品的完成度。本次反馈视为视觉验收不通过，而不是继续用测试通过解释外观。

二次设计按“主操作少而明确、次级能力按需展开”的方式收整：

- 相机默认不再显示横跨底部的长 Slider；取景页改为小米相机风格的透明线条轮盘，倍率刻度沿弧线排列，左右拖动连续变焦，轻触切换预设，长按打开精细调整弹层。
- 相机底部不再使用一块厚重的黑色卡片包住所有按钮，改为画面底部渐变遮罩 + 图标操作区，中央白色快门保留视觉重心；顶部只保留返回，失败预览的“重拍”不再重复出现。
- 新手引导不再使用“上图、下文”的白色大卡片；改为编辑式画面：品牌栏、单一主插画、短标题、短说明、页码指示和一个主 CTA。平板宽屏图文并置，手机保持插画先行。
- 第一页使用品牌路径封面图而不是空白日程物件，文案从解释功能改为“从今天的一步开始”，减少首次进入的信息负担。

取景区继续支持点按对焦，焦点位置显示为透明线条对焦环，并通过读屏提示“点按预览对焦”；双指变焦和精细调整仍走同一设备倍率能力。

这次修改不改变拍照保存、相机生命周期、长截图拼接或引导完成标记的业务契约；它只收整默认视觉层级和次级交互入口。


## 长截图交互纠正（用户反馈）

用户明确要求长截图流程为：点击长截图 → 系统授权 → 回到原应用自由滚动 → MissionBook 自动记录滚动后的变化画面 → 点击完成 → 自动跳回 MissionBook AI 聊天页。首轮实现错误地把每一屏采集设计成用户逐次点击“继续”，这不符合主流长截图的操作预期。

本次纠正：

- 长截图首帧自动采集；
- 控制条只保留“完成 / 取消”，不再要求用户逐屏点击；
- 服务保持投影监听并按间隔请求帧，画面没有变化时静默重试，检测到滚动变化后自动拼接；
- 完成后隐藏控制条、释放投影、写入缓存并通过包内广播交给 `AssistantCaptureConsentActivity`；
- 成功跳转到 `MainActivity.assistantIntent(capturePath)` 后不再立刻恢复悬浮球，避免悬浮服务抢回前台；
- 主 Activity 增加 `REORDER_TO_FRONT`，并保留冷进程/已有任务的 pending capture 交接。

这次修改的核心不是按钮样式，而是把“谁驱动下一帧”和“谁负责跳回 AI”两个状态机边界纠正过来。
