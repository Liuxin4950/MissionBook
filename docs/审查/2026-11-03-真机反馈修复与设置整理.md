# 2026-11-03 真机反馈修复与设置整理

## 已落地范围

| 反馈 | 本轮实现 |
| --- | --- |
| 切后台后会话丢失 | 同一 writer token 可以续租；不健康运行时重开既有持久会话，保留待发送输入 |
| 批量能力缺失 | 页面与助手共用 cancel/delete/reset，预览固定范围，事务重读并检查，回执可分页 |
| 删除与误标完成 | 按用户最新要求物理删除；撤销原执行和材料进入归档，当前任务回到未开始，可编辑重排 |
| 读取预算与事实判断 | 完整范围统计与分页正文分离；预算拒绝明确未返回的结果与未覆盖范围 |
| 记忆保存失败难理解 | 原话校验保留，说明连续引用、换行标点和不可拼接的具体要求 |
| 拍照及超限图片 | Android 聊天拍照；拍摄与选图共用可选压缩副本，原文件保留 |
| 图片记录摘要 | 单记录专用提示，图片仍由真实网关 ImageBlock 传入；自身来源与 coverage=1 |
| 当日记录、材料与个人页 | 记录标题与内容同卡；窄屏材料单列；个人页按列表、统计与阅读角色统一字号 |
| 工具时间 | 已知时刻字段统一为含时区偏移的 ISO；查询附时间上下文，日期、时长和编号保持原义 |
| 助手设置 | AI 与语音独立页面、独立保存和校验、Key 显隐、模型连接测试、独立语音试用 |
| 重复导出 | 两处入口进入同一备份页；完整备份包含仅由撤销历史引用的原件 |

现行职责与调用链见[助手与总结](../架构/前端/助手与总结/总览.md)、[任务维护](../架构/前端/任务与材料/README.md#任务维护与撤销历史)及[全局样式](../架构/设计/全局样式/README.md)。数据库仍为 schema 16。

## 实际证据与验证

- 手机仅执行截图和应用内导出备份；唯一会话 276 条日志中发现一次读取预算拒绝、四次原话校验拒绝及两次 invalid_response。备份与原图属于用户数据，保存在仓库外，未提交。
- 相关自动化最终 244 项全部通过，覆盖助手应用/存储、任务维护、记录上下文、完整备份还原、助手/个人页/设置/材料/今天与详情导航。命令以 `flutter test --no-pub` 指定这些目录和测试文件运行。
- agent_core 独立专项先前 113 项通过。当前共享核心仅增加运行时可重开状态的公开读取，不修改业务阶段派生。
- 本轮 lib 与相关测试静态分析通过。未改用户的临时探针文件；它不属于本轮检查范围。
- 390、768、1578 宽使用真实字体隔离渲染，检查个人页、助手设置、AI、语音及备份页；320/768 双倍字号有 Widget 操作回归。隔离截图不代表目标手机验收。
- 首轮全量运行 727 通过、35 失败、2 跳过。拉取时 `7b414b9` 的独立副本全量为 705 通过、37 失败、2 跳过。对照发现本轮新增的回执当前时间不稳定已修复，并通过记录上下文回归；用户未跟踪的真实文件探针不在基线。其余计时、目标界面等既有失败未全部处置，不能宣称全量回归通过。
- 更新旧界面断言时按现行入口验证：目标编辑已在操作菜单内；今天任务计时及助手过程折叠按当前布局；材料按新单列布局。没有修改对应业务事实来迎合旧断言。

## 尚需目标设备与模型验收

Android `flutter build apk --release --target-platform android-arm64` 构建成功，版本 0.2.20+2022，沿用项目当前 debug 签名配置。首次使用 `--no-pub` 时，Flutter 3.47.7 保留了调试测试插件注册而导致 Java 编译失败；去掉该选项后由工具按 Release 模式重新生成注册文件，构建通过，未手改生成代码。此安装包尚未安装到目标手机。

1. 长时间后台、锁屏、系统回收及网络中断后的发送与继续。
2. 相机权限、拍照/重拍、超过 4 MiB 压缩、原图方向及清晰度。
3. 对原图片点“更新总结”，检查真实模型提取公式和文字的质量；旧摘要未自动覆盖。
4. 麦克风、离线模型下载与人声识别、转写服务及离开页面后的录音释放。
5. 新页面视觉、手势、大字号和读屏；真实个人任务未被用于删除/撤销验收。

两次 invalid_response 没有供应商原始响应，根因仍未定位。已落地的会话恢复和错误提示不等于这两次协议失败的根因已修复。未标记用户掌握。
