## 二、已删除的不成立结论

### 数据层

- **数据库迁移、空快照、备份版本门槛不是缺陷。** 当前开发阶段明确不保留旧结构升级路径，备份只接受当前 `schemaVersion`，版本不一致已有中文提示。本次只把旧库启动异常改为可读拒绝，不补迁移，也不自动删除本机数据。
- **“30+ 事务未取写锁”误报。** 任务写入口先取写锁，维护 `prepare` 是纯读取；drift 的 SQLite 事务实际使用 `BEGIN IMMEDIATE`，并非报告假定的 deferred 读事务。仓库已有独立双连接材料竞争测试。
- **未启用 WAL 不足以认定缺陷。** 没有真实负载证明前台/后台连接因 journal 模式产生可感知阻塞；仅启用 WAL 也不能消除写写竞争，本轮不做投机性数据库模式变更。
- **`command(null)` 多表半提交误报。** 实际空调用要么单语句，要么回调自带事务/锁；`commandResult` 始终有事务。
- **恢复 remap 静默丢附件误报。** `prepareRestore` 在 remap 前校验正式与撤销归档附件引用和文件集合一致，已有缺图拒绝测试。
- **索引与触发器结论证据不足。** 查询计划显示现有索引可过滤，未证明性能越界；触发器已有真实写入、失效和恢复回归，不能仅因结构测试不比较 DDL 判为缺陷。

### 业务链路

- **固定 START 忽略 EXTEND 不是现行错误。** START 前不能追加 EXTEND；建议直接改用 `scheduledExecutionEnd` 还会在空事件时返回 null，属于错误修法。
- **发生日期按设备时区是现行设计。** 历史页明确按设备日回看，现有测试刻意使用不同排期时区验证；排期日、用户报告日和设备历史日不是同一事实。
- **`evidenceDeadlineAt!` 当前不可达。** 领域配置和详情装配先校验强制材料与截止，非只靠 SQL 预筛。
- **计划调度器 0ms Timer 是误读。** 该分支仍会继续本轮同步重试，不是必然取消的死代码。
- **`deriveMissionPhase` 无直接符号引用不等于无覆盖。** 仓储和详情 getter 均经唯一核心，STOP、reportPending、材料合格/超时/放弃已有真实写入闭环测试。

### 表现层

- **通知失败并非完全静默。** 设置页在通知服务不可用时已有“尚未就绪”提示；真实不足是 Web 会访问本机路径，已修复。
- **流式输出不会每次重解析全部历史 Markdown。** 控制器已有 66ms 活动节流，Markdown AST/样式/块 Widget 有缓存；浮窗仍会随活动更新重建，但没有性能采样证明卡顿，本轮不做无证据重构。
- **`AppShell` 四页全量重建误报。** 页面列表和主体在 `ListenableBuilder` 外创建并复用，相同 Widget 身份可跳过更新。
- **`catch` 总数不是缺陷。** 只有记忆页确实丢失业务原因或不清空错误，已修复；不引入全局 grep 门禁。
- **重复注册 postFrameCallback 误报。** UI 动作取出即清空，重复检查不会重复交付。
- **`IntrinsicHeight` 未证实性能问题。** 无掉帧采样，保留现有布局。

### 助手子系统

- **控制器规模、`part`、facade、工具串行不是已证缺陷。** 这些是现有设计取舍；串行避免并发写越权，facade 仍承担装配和读写属性，不能仅按行数或转发数量判高危。
- **“无单工具超时”证据不足。** 联网搜索/网页已有独立超时，后台分析有队列重试；通用 per-tool 超时若引入，也必须保留写工具结果未知语义，不能简单返回可重试失败。
- **`_call` 静默回退模型原始参数误报。** AgentLoop 校验、持久化并传入批准参数，prepared 调用丢失路径与所述不一致。
- **默认 `full` 权限是明确产品选择。** 首装策略和测试均已存在；本轮只加固损坏配置，不擅自改成 `standard`。
- **联网工具不会自动外发整段历史。** 工具发送模型提供的 query/URL；已补充第三方外发说明。
- **`prepare()` 的 `as` 强转抛 TypeError 误报。** 相关字段已被 schema 必填/类型约束覆盖；准备异常不会变成写工具的 `outcome_unknown`。
- **会话日志无限增长不是可直接裁剪的缺陷。** 原始日志是审计、引用和恢复依据，压缩只改模型可见投影；已有删除整会话入口，不能默认静默 prune。
- **打开会话全量重放和 copy-before-persist 是剩余成本，不是已证高危 bug。** 复制发生在持久化前以保证失败不污染已接受状态，不能直接删除；未来优化需先提供规模证据并保持未知操作恢复。
- **后台 `analyze` 无重试误报。** 失败任务进入持久队列，按 `available_at` 和尝试次数指数退避重试。
- **语音释放未闭环误报。** `App.dispose` 调用语音 dispose，最终关闭本地后端；同步 `State.dispose` 不能 await 不等于无人释放。
- **`ACTION_STOP` 后 `START_STICKY` 复活气泡误报。** `stopSelf()` 结束 started 状态，系统不会仅因返回值重建该服务；无权限分支已返回 `START_NOT_STICKY`。
- **`sendOverlayAction` 崩溃和 exported Activity 信任 extras 均未证实。** 现有路径校验、大小限制和草稿预览阻止任意文件读取；`callingActivity == null` 不能作为鉴权。本轮不做泛化安全改造。

### 测试与静态质量

- **`flutter analyze --no-pub --fatal-infos` 当前约 2 秒完成且无问题。** 原“11 分钟无输出”不能作为现行结论。
- **覆盖缺口是事实，但不是已证 bug。** App/main/后台入口、部分 Windows/平台分支仍无直接测试；未擅自新增未请求的 CI 配置。
- **`Future.delayed` 数量统计错误，且全量测试本次确定性通过。** 未证实当前存在 flaky 失败。
- **根目录日志与生成物已忽略，不是代码缺陷。** CI 仍属流程建议。
