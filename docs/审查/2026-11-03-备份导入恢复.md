# 2026-11-03 备份导入恢复（0.2.21）

## 范围与设计

按用户“先把导入修复做了，再处理安装”的要求，统一备份页接通 ZIP 选择、隔离校验、数量预览及确认后的完整恢复。保留当前导出格式，只接受与应用相同的数据库版本和表列；没有历史迁移、合并策略或兼容分支。架构和失败边界见[模块总览](../架构/前端/数据备份与恢复/README.md)。

附件先写新键，数据库在同一事务内替换并核查外键。数据插入失败回滚删除及触发器变动，附件失败保留当前数据。预览后业务事实变化则拒绝替换。恢复前暂停语音、会话、分析和提醒，随后整体重建工作区。旧状态销毁不会再次清除新工作区的计划通知通道监听。

沿用已有 SQLite、附件协调器、系统文件选择通道及全局样式。新增 sqlite3 的直接依赖用于 Web 隔离内存库（版本与原有传递依赖一致）；未增加数据库表或更改任务规则。

## 实际验证

- 恢复持久化专项覆盖：实际导出 ZIP、只读预览、任务/文字记录/记忆/会话/撤销历史原图、当前 SHA256 回执列、清空旧会话写租约、外键与可信触发器、重复恢复拒绝。
- 失败路径覆盖：预览后当前数据变化、附件写入失败、目标库唯一索引引发插入失败、缺失附件、错误版本、截断 SQL、额外执行语句、损坏文件及备份携带触发器。均验证当前数据保留。
- 页面专项使用真实恢复器及内存 SQLite，覆盖选择取消、损坏反馈、确认取消与实际提交、320 宽双倍字号滚动、重复选择和进行中的返回保护。
- 用户原手机导出包在隔离数据库完成恢复后重新导出对照：18 张表行数一致，207 项任务、1 个会话的 276 条日志、11 条记忆、1 个 86391 字节附件；附件字节一致、外键无错误。全部数据行除有意映射的附件键和清空的助手写租约外一致。私有备份及测试产物保存在仓库外，未提交。
- 最终相关回归 94 项全部通过，包含备份、恢复页面、个人页、助手入口/生命周期、提醒服务、材料截止调度及当前数据库。精简隔离库创建接口后，恢复单元/页面与真实手机备份专项再跑 10 项全部通过。`dart analyze lib test/application/backup_restore_test.dart test/presentation/backup_restore_page_test.dart` 无问题，修改范围格式检查、差异空白检查及 110 个文档链接检查通过。已有全量测试基线失败见[前一轮验收](2026-11-03-真机反馈修复与设置整理.md)，本轮不宣称全量测试通过。
- `flutter build web --release` 与 `flutter build apk --release --target-platform android-arm64` 均通过；Web 为默认 JavaScript 发布构建，尚未验收浏览器恢复交互。APK 经 aapt 核对为 0.2.21、versionCode 2023，并复制至下载目录的 `MissionBook-0.2.21.apk`，副本 SHA256 与构建产物一致。
- Android 沿用现有 debug 签名。构建中的既有 Kotlin 插件迁移和 Web wasm dry-run 提示未在本轮扩展处理，不影响本次已通过的发布构建。

## 安装与设备边界

原手机安装的 0.2.19 与当前 Windows 构建签名不同，覆盖安装曾被 Android 拒绝。没有卸载或清空旧应用数据。本轮恢复验证期间 ADB 已断开，尚未完成目标手机的安装、系统 ZIP 选择、恢复后提醒与会话发送验收。

备份排除 API Key、模型/语音配置、本机资料与提醒偏好。应用内恢复保留目标设备现有设置；卸载再安装需要重新配置这些设置。恢复路径已实现不代表已授权卸载，保留旧应用等待后续处理。
