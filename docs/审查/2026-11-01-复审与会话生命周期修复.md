## 用户补充：新会话应在首次发送时建立

原 startNewSession、首次对象入口及返回全局入口会直接创建数据库会话，导致重复点击产生空历史。现在先呈现未持久化草稿，只有首次有效文字或附件发送才创建和关联。空文字不会创建；并发重复发送不会创建两份；已有用户消息的失败会话保留，预检拒绝的本次空壳清理。

全局、任务、目标和节点草稿按 draftKey 区分，已有历史仍可恢复。语音气泡在首条消息创建会话时接续同一轮身份，不因编号由空变为正式编号而消失。旧的历史改名/恢复测试改为先发送真实消息后准备历史，保留原有断言。

主提示词提取到 assistant_prompt.dart，按意图、事实与工具、规划与历史、记忆与外部内容组织。讨论不自动写入、明确操作不只给建议、必要歧义才澄清，继续复用用户已经说明的信息；工具回执、STOP/END、材料与掌握的边界明确。角色风格只影响表达，宿主仍控制权限。新旧会话实际模型请求均使用升级后的提示词；未把脚本测试当作真实模型的回答质量验收。

## 架构影响

```text
新会话/对象入口 → 内存草稿 → 首次发送 → 持久会话及对象关联 → agent_core
主会话状态 → 网关请求令牌 → 中断后台 / 停止按需分析 / 关闭全部请求
App 生命周期 → EvidenceDeadlineScheduler → MissionService → 现有仓储事务
```

没有数据库迁移、领域阶段变化或工具协议重命名。材料仍可在任意阶段保存，历史事实、旧会话及用户数据不批量删除。架构细节见[助手与总结](../架构/前端/助手与总结/总览.md)和[任务与材料](../架构/前端/任务与材料/总览.md)。
