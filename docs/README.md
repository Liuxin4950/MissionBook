## 统一约定

- 产品原则约束行为，不自动扩大本地应用规格中的当前范围。未来能力只有明确提升并同步相关规格后才进入工程。
- 术语与转换以领域模型为准，字段以数据模型为准，页面和存储引用规则，不各自建立业务状态。
- 图片决定视觉基调和布局；业务能力、状态、样例数值和最终中文文案以当前文字规格及设计稿说明为准。图中的旧版本页脚不决定工程版本。
- Mission 只有六个派生阶段；完成报告、材料、超时和取消分别来自真实记录，不重复维护多套可写状态。
- 可在验收与交互中举同一规则的不同场景，不复制维护第二份定义。跨文档引用使用可点击路径，章节引用带有效锚点。
- 不为未来 AI、同步或 Provider 创建空表、未使用字段和占位接口；临时阶段限制不能冒充最终完成。
- 业务数据、代码和验收结果才是实现证据；文档统一不意味着功能已经完成。
- 旧设计通过 Git 回溯，正文不并列维护过时方案；文档目录版本与 JSON/Schema 协议版本分开理解。

## 文档检查

在仓库根目录运行：

```powershell
python tool/check_docs.py
```

检查覆盖本目录全部 Markdown 及根 README 的本地链接/锚点、代码围栏、JSON 示例、旧状态残留、六阶段动作表、策略分流矩阵和核心表映射。它用于发现结构与已知口径回退，不能代替业务场景审阅或实现后的运行验收。
