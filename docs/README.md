## 统一约定

- 早期规格用于追溯，不能以旧“不包含”拒绝用户的新需求。新场景先对照当前实现具体分析，再记录调整、影响与验收；提出方案不等于已经实现。
- 术语、转换和字段保持统一，专题设计与相关规格相互链接；页面和存储不各自建立业务状态，未决产品选择不得写成已获确认。
- 图片决定视觉基调和布局；业务能力、状态、样例数值和最终中文文案以当前文字规格及设计稿说明为准。
- Mission 阶段由真实记录派生，不保存可写 phase；现行七阶段及完整派生见[术语](架构/术语.md)与[架构入口](架构/README.md)。完成报告、材料、超时和取消分别来自真实记录，不重复维护多套可写状态。
- 不为未来 AI、同步或 Provider 创建空表、未使用字段和占位接口；开发阶段不保留旧结构迁移（现行 schemaVersion 18，旧库显式拒绝）。自动检查、真实模型、浏览器与目标原生设备验收分别记录，临时限制不能冒充最终完成。
- 业务数据、代码和验收结果才是实现证据；文档统一不意味着功能已经完成。旧设计通过 Git 回溯，正文不并列维护过时方案；目录版本与 JSON/Schema 协议版本分开理解。
